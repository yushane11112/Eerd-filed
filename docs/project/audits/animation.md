# 《小耳岛》动画系统审计

## 结论

当前游戏还没有可交付的“动态城市引擎”。

- `IslandCanvas` 仍以整岛阶段图为主体。水波、云影、居民和材料只按时间做循环位移，与城市生产、道路、天气和人物目的无关，属于假动效。
- `src/rendering` 已建立分层、对象池、裁剪、等距坐标和快照同步骨架。人物路径插值及建筑运行状态可以读取 `SimulationSnapshot`，但现有画面仍是程序化几何占位。
- `SimulationSnapshot` 能直接支持基础人物移动、生产状态、物流角色、材料及建筑等级；不能完整表达天气、昼暮、施工工序、船舶航道、植被受风、建筑专属工序和动画事件。
- 现有 28×9 张建筑 PNG 是静态等级图，不是可动画图集。整岛图、环境 PNG 和建筑 PNG 均不能直接满足真实城市动画要求。
- 最终实现应以 `DynamicScene` 为唯一游戏世界渲染入口，`IslandCanvas` 只能在迁移期作为旧版对照，不可继续承载正式动画。

## 逐项审计

| 类别 | `IslandCanvas` 现状 | `src/rendering` 现状 | 快照驱动能力 | 判定与缺口 |
| --- | --- | --- | --- | --- |

| 施工 | 整岛阶段图交叉淡入；无施工过程 | `constructing/upgrading` 仅更换颜色和尺寸 | 可判断施工/升级状态，但无施工进度和工序 | 淡入换图不算施工动画。需围挡、搭架、运料、施工、落瓦、拆架和启用事件 |

## 动画状态机

### 通用规则

- 模拟层是唯一事实来源；动画不得修改库存、订单、人口、位置或生产进度。
- 渲染按上一快照与当前快照插值。固定 Tick 决定逻辑，渲染帧率只影响平滑度。
- 所有持续动作由快照状态推导；一次性动作由带 Tick 的模拟事件触发并支持读档恢复。
- 暂停时人物、生产、物流和施工动画冻结；水面、树叶等纯环境动画可降速至 15%，UI 动画不受影响。
- 被裁剪后重新进入视口的实体根据当前 Tick 计算相位，不从第一帧重播。
- 同一快照、随机种子和 Tick 必须产生一致动画阶段；仅粒子初始微扰允许使用实体 ID 派生随机数。

### 人物 `CitizenAnimationState`

状态：

`spawn → idle → walk → enter → work/shop/serve/watch/study → exit → walk → despawn`

- `home/idle`：站立、交谈、看景、整理衣物；只能在住宅或公共节点发生。
- `commuting/returning`：按路径及方向播放八方向行走。
- `working`：进入雇主建筑的专属工作点，不在道路中央原地工作。
- `shopping/serving`：在摊位、柜台或服务点排队和交互。
- 路径中断：停下并显示短暂疑惑动作，不继续穿越地形。
- 必需数据：方向、路径段进度、目标实体、动作开始 Tick、外观变体。现有契约缺少后四项，应由主契约任务补充或建立确定性派生层。

### 建筑 `BuildingAnimationState`

顶层状态：

`constructing | upgrading | idle | working | delivering | serving | blocked`

每个建筑注册：

- `idleLoop`：烟、旗、灯笼、门窗、动物等低频动作。
- `workCycle`：以 `productionProgress / durationTicks` 映射工序，不允许自由循环。
- `deliveryIn/deliveryOut`：必须存在对应订单和承运者。
- `serviceCycle`：必须存在服务人员或访客。
- `blockedPose`：按 `statusReason` 区分缺工、缺料、仓满、断路和财政不足。
- `levelTransition`：只在升级事件发生时播放；读档位于升级中时恢复相应施工阶段。

施工阶段：

`site-clear 0–10% → foundation 10–25% → scaffold 25–45% → structure 45–70% → roof/detail 70–90% → scaffold-remove 90–98% → commissioning 98–100%`

快照至少需要 `constructionProgress`、`constructionStartedTick` 和目标等级；仅有 `status` 无法可靠恢复施工动画。

### 物流 `TransportAnimationState`

`waiting → walk-to-source → loading → in-transit → waiting-at-destination → unloading → returning`

- `waiting/assigned/in_transit/delivered/cancelled` 与订单严格对应。
- `loading/unloading` 必须绑定建筑装卸点，并显示货物类型。
- 目的地满仓时承运者停在等待点，不能循环穿门或凭空卸货。
- 车辆朝向由当前路径段决定；载货和空载使用不同外观。

### 船运 `BoatAnimationState`

`moored → loading → departing → sailing → approaching → unloading → moored`

- 仅水域路径可进入 `sailing`；码头必须提供泊位和进出航道。
- 航速决定船头波和尾流长度；停泊后尾流在 0.8–1.5 秒内消散。
- 小船可用逐帧图集；大型船用分层骨骼控制船体、帆、桨、货物和灯。
- 当前快照缺航线、泊位、航速和装载信息，必须扩展后才能称为真实船运。

### 环境状态

- 水面：基础流动、岸边浪、桥墩扰流、船尾水迹四层；由场景时钟连续运行。
- 植被：`calm/breeze/windy/rain` 四档；树冠、枝条、叶簇分层摆动，根部固定。
- 天气：`clear/drizzle/rain/mist/windy`；天气切换至少 8 秒渐变，禁止瞬切。
- 昼暮：`morning/day/dusk` 连续插值；太阳色温、全局明度、阴影方向、窗灯和灯笼分别控制。
- 建筑灯火由场景时间及建筑营业状态共同决定，停工建筑不得保持满负荷烟火。

## 资产生产要求

### 人物

- 采用 8 方向逐帧图集；基础行走每方向 8 帧，待机 4–6 帧，专属动作 6–12 帧。
- 首批至少覆盖居民、工人、搬运工、服务人员、车夫、船工六类；每类不少于 4 套服饰/色彩变体。
- 图集统一基准点在双脚中点，方向、帧尺寸、碰撞盒和动作时长写入 manifest。
- 近景缩放不低于 1.5× 时仍应保持清晰轮廓，禁止用当前圆形几何占位作为最终资产。

### 建筑

- 每个等级拆为主体、前景遮挡、阴影、灯火、烟口、机械部件、院落活动点，不再使用一张扁平 PNG 承担全部表现。
- 规则机械适合序列帧或分层骨骼：水轮、织机、磨盘、灯塔光束、船坊龙骨。
- 非规则烟火、水汽、落叶、施工尘土使用粒子；粒子不得烘焙进主体图。
- 每类建筑提供 `level-0…8`、状态挂点、入口、装卸点、服务点、烟口、灯位和遮挡多边形。
- 0、1、3、5、7 级主体轮廓必须变化；2、4、6、8 级增加院落、道路衔接、摊位、灯火、居民活动和机械细节。

### 船车与环境

- 车、船按 8 方向提供空载/载货图；货物层根据资源类型替换。
- 水面采用小型无缝法线/扰动纹理、岸线泡沫图集和尾流粒子，不使用整幅水面视频。
- 树木用 2–4 段骨骼或分层枢轴；草、稻、竹用批量实例化顶点摆动。
- 雨、雾、落叶、烟、尘使用对象池；天气层需要前景和世界空间两档深度。
- 所有资源提供 1×/2× 或分辨率桶、压缩纹理和加载分组；不再一次加载现有约 211 MB 全资产。

## 快照与渲染接口缺口

现有字段可立即使用：

- `tick/speed`：确定动画相位及暂停。
- `BuildingEntity.type/level/status/statusReason/productionProgress`：选择建筑、等级、顶层状态及生产阶段。
- `AgentEntity.role/position/path/pathIndex/activity`：选择人物类型、路径移动和基础行为。
- `LogisticsOrder.state/carrierId/resource`：绑定运输者、阶段和货物外观。
- `WorldCell.terrain/road/elevation`：生成地形、水域和道路层。
- `WorldDrop.position/source/amount`：材料落点与表现。

必须由公共契约补充：

- 场景：`sceneTimeOfDay`、`weather`、`weatherIntensity`、`windVector`。
- 建筑：`productionDurationTicks` 或可查询的定义注册表、`constructionProgress`、`constructionStartedTick`、动画挂点数据。
- 人物：`pathProgress` 或移动开始/结束 Tick、`facing`、`targetEntityId`、`actionStartedTick`、外观种子。
- 物流：装载量、当前订单 ID、装卸开始 Tick、等待原因。
- 船运：水路路径、泊位 ID、航速、装载状态。
- 一次性事件：施工阶段完成、装卸开始/完成、生产完成、服务开始/完成，均需事件 Tick。

这些字段未补齐前，可做视觉原型，但不能声称动画与完整模拟严格一致。

## 性能预算

目标设备为中端横屏浏览器，目标 60 FPS，允许复杂场景稳定不低于 50 FPS。

| 项目 | 预算 |
| --- | --- |
| 每帧总 CPU | 16.7 ms；渲染同步与动画更新合计 ≤ 5 ms |
| GPU 渲染 | ≤ 9 ms，常态 draw calls ≤ 180，压力场景 ≤ 260 |
| 可见实体 | 300 建筑、150 人物/运输、30 材料节点 |
| 可见人物骨骼/逐帧动画 | 近景全帧 ≤ 80；其余降为半帧率或简化循环 |
| 粒子 | 常态 ≤ 1,200，压力峰值 ≤ 2,500 |
| 动态灯光/投影 | 近景主要灯 ≤ 32；其余烘焙或合批 |
| 纹理显存 | 桌面 ≤ 256 MB；移动端 ≤ 160 MB |
| 单图集 | 建议 ≤ 2048×2048；按岛屿、建筑族和时段分包 |
| 首屏动画资源 | 压缩后 ≤ 20 MB；其余按视口和建造内容延迟加载 |
| 对象创建 | 游戏循环内零临时 Graphics 重建；实体和粒子必须池化 |
| 离屏更新 | 完全离屏停止渲染；模拟仍运行，环境动画降至 0–5 Hz |

现有 `BuildingVisual/AgentVisual/DropVisual` 每次更新都 `clear()` 后重绘 Graphics，不适合正式压力场景，应在资产实现任务中替换为 Sprite/AnimatedSprite/骨骼实例及属性更新。

## 验收录像清单

每条录像使用无 UI 遮挡的 1920×1080 横屏画面，同时录制性能面板；不得通过剪辑跳过状态变化。

1. **人物闭环（90 秒）**：家庭成员出门、沿道路上工、进入建筑、工作后返家；断路后人物停止并重新寻路。
2. **真实生产（120 秒）**：稻田、布坊、瓷窑和水磨各完整运行一周期；暂停后全部工序冻结，恢复后从同一进度继续。
3. **停工对照（60 秒）**：依次触发缺工、缺料、仓满和断路，专属动作停止且视觉原因不同。
4. **物流闭环（90 秒）**：订单生成、空车到源建筑、装货、载货行驶、目的地等待、卸货入库；库存只在卸货完成后改变。
5. **船运闭环（120 秒）**：渔船离港、航行、回港、卸鱼；包含转向、靠泊、尾流和停泊消散。
6. **水面与植被（60 秒）**：固定镜头展示水流、岸浪、桥墩扰流、树冠、竹林、稻田；根部和岸线不得漂移。
7. **天气过渡（90 秒）**：晴转细雨再转雾，连续渐变；人物、晒谷场、药铺晒架和盐场动作产生合理变化。
8. **昼暮过渡（90 秒）**：晨至昼至暮，展示连续色温、阴影和灯火，灯塔只在暮色开启。
9. **施工升级（120 秒）**：同一建筑从 0→1 和 7→8，完整显示清场、基础、脚手架、主体、落瓦、拆架、启用；不能只淡入换图。
10. **28 类建筑专属动作（每类 15 秒）**：逐一展示本文件表格中的核心动作，隐藏建筑名称后仍可辨认其功能。
11. **城市压力场景（180 秒）**：500 户、300 建筑、150 可见移动实体，持续拖拽和缩放，平均 ≥ 50 FPS，无明显 GC 卡顿、闪烁或层级穿帮。
12. **确定性复现（并排 60 秒）**：相同快照、种子和操作序列双实例并行，人物路径、生产阶段和一次性事件一致。

## 动画交付门槛

- `IslandCanvas` 的整岛淡入、随机漂移人物、漂移曲线水波不能出现在最终游戏路径。
- 任一生产、运输、服务或施工动画都必须能追溯到快照状态或带 Tick 的模拟事件。
- 28 类建筑不得共享同一套“光点＋烟雾”作为核心动作。
- 暂停、倍速、读档、离屏再进入和断路重算后，动画不得与模拟结果脱节。
- 上述 12 组录像、压力数据和资产清单全部通过后，动画模块才可标记为完成。
