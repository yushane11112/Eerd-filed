# 《小耳岛》建模基础审计与 3D→2.5D 生产规范

## 1. 审计结论

当前项目不存在可进入高精良游戏生产的建模基础。

- `public/assets/buildings` 只有 28 类建筑各 9 张、共 252 张 512×512 扁平 PNG；没有 Blender/Maya 源文件、网格、骨骼、UV、材质、碰撞体、入口、动画轴心或 LOD。
- 四岛地形仍是整图或阶段图，不能支持自由道路、建筑占地、岸线拼接、遮挡、局部升级、天气响应和真实船运。
- 人物、货车和环境对象也是静态 PNG 或程序化占位图形，无法提供八方向动作、载货变化、轮轴、帆桨、船舵和装卸挂点。
- 现有建筑等级图只能保留为概念气氛参考，不能反向认定为已经完成的模型设计。多数等级缺少统一尺度、占地约束、结构逻辑和可验证的 0–8 级体块成长。
- 当前渲染使用 96×48 px 等距格。正式生产应采用统一三维正交相机渲染为 2.5D 分层资产；不应继续用生成式整图直接替代模型、结构设计和动画拆件。
- 28 类建筑必须分别建立身份明确的模型族。最高级不是“基础房屋加亭子、船和装饰”，而是主体规模、院落组织、生产空间、街区连接及运行能力共同升级。

**判定：现有建筑、四岛环境、人物、车辆和船只全部需要重建。** 可复用内容仅限名称、功能定位、占地意图、色彩气氛和少量构图参考。

## 2. 统一世界尺度、相机与建筑模数

### 2.1 世界单位

- 引擎逻辑 1 格对应 4×4 m；三维源文件统一使用米，`1 Blender Unit = 1 m`。
- 等距地砖在运行时为 96×48 px；正式资产提供 2× 高分源渲染，逻辑显示仍以 96×48 px 为一格。
- 世界竖直方向使用真实 Z 轴；地形每级海拔为 1 m，渲染映射到现有 `elevationHeight = 24 px`。
- 普通道路宽 1 格，主街宽 2 格；人行巷道可为 0.5 格，但寻路和建筑入口必须落在完整格或已声明的子节点上。
- 建筑 footprint 以 `BUILDING_CATALOG` 为最低占地，不得让屋基、台阶、固定生产设施越出占地；屋檐、树冠和旗幡可视觉外扩，但必须写入包围盒。

### 2.2 人物和建筑尺度

| 对象 | 统一尺度 |
| --- | --- |
| 成年居民 | 1.62–1.78 m；标准眼高 1.58 m |
| 儿童 | 1.05–1.35 m |
| 单层檐口 | 2.8–3.2 m |
| 两层檐口 | 5.8–6.4 m |
| 普通屋脊 | 檐口以上 1.2–1.8 m |
| 公共建筑首层 | 3.6–4.2 m，避免与民居同体量 |
| 门洞 | 净高 2.1–2.4 m；主门 2.8–3.6 m |
| 栏杆 | 0.9–1.1 m |
| 货车 | 长 2.6–3.4 m、宽 1.2–1.5 m |
| 小型渡船/渔船 | 长 5–9 m |
| 中型货船 | 长 10–16 m |

人物站在门、桥、船和生产设备旁时必须比例可信。禁止通过单独缩放人物或建筑来掩盖尺度冲突。

### 2.3 相机与透视

- 使用正交相机，不使用透视相机模拟等距视图。
- 相机方位固定为 Z 轴旋转 45°，俯角以三维轴约 35.264° 为基准；所有资产使用同一相机预设。
- 光源默认来自屏幕左上偏后方，主体阴影落向右下；四岛、建筑、人物、车船不得各用不同光向。
- 建筑允许 0°/90°/180°/270° 四向放置。不能安全镜像的牌匾、文字、楼梯、装卸口和机械必须分别渲染方向资源。
- 白模、材质、动画和最终渲染均禁止手工拉斜或二次透视变形。

## 3. 建筑结构语言和 0–8 级成长

### 3.1 原创东方水乡结构规范

- 主镇采用木构穿斗/抬梁混合语言、白灰墙、深灰瓦、石台基和临水街巷；结构必须能解释柱、梁、檩、椽、屋面和开间关系。
- 屋顶至少区分硬山、悬山、歇山、攒尖、棚顶和生产性大跨屋面；按建筑功能选型，不能所有建筑统一歇山或亭顶。
- 瓦片近景可用重复几何或法线细节，中远景用烘焙；檐口、屋脊、滴水和山墙必须保持清晰轮廓。
- 建筑正面必须由真实入口、窗口、柜台、装卸口或院门决定，不得只靠招牌声明功能。
- 农业、盐业、港口、桥梁和园林必须以地貌、生产设施和空间组织为主体，不能包装成一栋通用房屋。
- 每类建筑建立独有的三项身份特征：主体轮廓、功能设备、场地组织。隐藏名称后仍须可识别。

### 3.2 九等级体块规则

等级不是九套互不相关的图片，必须基于同一模型族演进：

| 等级 | 体块和场地要求 |
| --- | --- |
| 0 | 可读的废弃前身：残基、断柱、荒田或停用设施；不得用同一瓦砾堆替代全部建筑 |
| 1 | 核心功能最小闭环恢复，形成完整入口和一个可运行工位 |
| 2 | 增加必要附属设施、储物区、道路/岸线衔接和第一组活动挂点 |
| 3 | 主体扩建或增加第二体块，轮廓必须明显变化 |
| 4 | 院落、装卸区、遮棚、摊位或生产场形成，环境利用率提高 |
| 5 | 形成成熟建筑组团，主体高度、跨度或开间升级 |
| 6 | 增加第二运行线、服务空间、景观边界和人流组织 |
| 7 | 地标级主体或完整产业院落形成，与低级轮廓显著不同 |
| 8 | 满负荷繁荣状态：主体、附属建筑、道路、庭院、生产设施和活动点完整，无废墟观感和无功能空地 |

强制规则：

- 0、1、3、5、7 级至少改变主体体块、层数、跨度或屋顶组合之一。
- 2、4、6、8 级至少增加一个真实可用的附属结构和一组运行挂点。
- 8 级 footprint 内有效空间利用率：城镇建筑不少于 85%，农业/园林类不少于 90%；空白必须是明确的庭院、田块、水面、晒场、装卸区或通道。
- 等级提升必须保留建筑身份，不得在高等级统一变成亭阁、楼船或相似大院。
- 模块复用只允许柱梁、门窗、瓦件、围墙、台阶、货架等构件级复用；每类建筑的主剪影和核心设备不得直接复用。

## 4. 模型拆件、轴心和引擎语义

每个建筑等级至少拆分为：

- `foundation`：地基、岸基、田埂或桥台。
- `structure`：不可动画的主体结构。
- `roof`：屋面和屋脊，便于施工阶段揭示。
- `foreground_occluder`：会遮挡人物的前景檐、墙、树或桥栏。
- `doors_windows`：需要开合或昼暮切换的门窗。
- `machine_*`：水轮、织机、磨盘、绞盘、窑门等独立刚体。
- `production_props`：原料、半成品、成品和库存可视化。
- `night_lights`：窗灯、灯笼、炉火和灯塔光源遮罩。
- `weather_parts`：雨棚、晒架、帆、旗、可收纳覆盖物。
- `construction_parts`：基础、柱梁、墙、屋面和装饰阶段件。

每个资产必须提交以下语义节点：

| 节点 | 用途 |
| --- | --- |
| `origin` | footprint 原点，固定在地面左/后角约定位置 |
| `entrance_*` | 居民和服务人员入口，可多入口 |
| `service_*` | 排队、柜台、授课、演出、游览等交互点 |
| `work_*` | 工人职业动作点，含朝向和动作类型 |
| `input_*` / `output_*` | 原料卸入和成品装出点 |
| `queue_*` | 等待点序列，不能堵塞道路 |
| `smoke_*` / `fire_*` | 粒子发射口 |
| `light_*` | 暮色灯位和光束轴心 |
| `berth_*` / `water_route_*` | 港口泊位、对位方向和水路连接 |
| `wheel_*` / `hinge_*` / `pivot_*` | 机械旋转和开合轴心 |
| `occlusion_polygon` | 人物进入建筑后的遮挡边界 |
| `collision` | 建筑实体碰撞，不等同于视觉包围盒 |
| `selection_bounds` | 点击和框选区域 |

碰撞必须按可通行空间拆分。桥面、码头、院落和戏台观众区不能用覆盖整个 footprint 的实心盒阻挡人物。

## 6. 四岛环境建模审计

### 6.1 主镇岛

- 需要重建连续岸线、河汊、码头基座、桥位、街巷、里弄、广场和可建地块，取代静态整岛底图。
- 地形模块至少包含直岸、凹岸、凸岸、河口、石驳岸、泥岸、台阶岸、码头接口和桥台接口。
- 最高繁荣阶段不能依赖铺满独立建筑图；道路、院墙、后巷、临水界面和背景民居必须通过模块化街区自然拼接。
- 主镇地表需提供泥土、石板、青苔、庭院和施工地五类材质变化。

### 6.2 风禾岛

- 建立梯田/平畴混合地形、灌渠、水位、田埂、果园坡地和水磨落差。
- 稻田与果园必须支持生产阶段替换，不可把植被烘焙进不可变地形。
- 水渠交汇、水闸、田间小桥和运粮道路需要独立模块，确保人物与车可达。

### 6.3 青岚岛

- 建立山坡、岩壁、雾谷、竹林、茶垄、药圃和山亭台基的海拔层级。
- 树、竹、茶垄不得全部烘焙成整块背景；需按 LOD 实例化，并提供根部固定的风动拆件。
- 山路必须与真实坡度和台阶模型对应，避免人物悬空或穿坡。

### 6.4 潮汐岛

- 建立潮间带、防波堤、盐池、卤渠、船台、港池和灯塔崖岸。
- 水位变化需暴露湿滩、盐渍和岸线湿润材质，不通过整图切换。
- 船坊下水滑道和港口航道必须具备实际宽度、转弯半径、泊位及碰撞水域。

### 6.5 环境模块验收

- 任意两块岸线、道路、田埂和水渠拼接不得出现裂缝、法线断层或比例突变。
- 四岛共享统一世界尺度和光照，但通过地貌、植被和生产结构形成差异，不仅靠调色。
- 近景不出现明显重复地块；连续 12×12 格区域内，同类细节变体至少 4 套。
- 地形遮挡、建筑占地、人物通行和水路均由独立数据定义，不能从渲染图片猜测。

## 7. 人物、车辆与船只建模

### 7.1 人物

- 建立统一人体基模：成年男、成年女、老人、儿童四种比例；工笔风格可适度头身夸张，但同一年龄层比例一致。
- 首批职业外观至少覆盖居民、农夫、工匠、搬运工、商贩、服务人员、车夫和船工。
- 服装拆为身体、发型/帽、上装、下装、工具和货物附件；相邻角色通过色板和附件变化，不能重复完整模型。
- 若采用三维渲染八方向序列帧，角色仍需完整绑定骨骼：根骨、骨盆、脊柱、头、四肢、手掌及附件点。
- 面部不追求写实毛孔，重点是剪影、姿态、衣褶和职业工具；手持物必须与动画关键帧接触。
- 白模验收：八方向站立、行走、坐、搬运和工作姿态无穿插，脚底锚点不漂移。

### 7.2 车辆

- 建立手推车、独轮车、双轮货车和客运车四个基础族，不用同一矩形色块替代。
- 车轮、车轴、车把、车厢、篷布和货物层独立；轮轴位置和轮径符合位移速度。
- 木、石、砖、布、粮、鱼、盐、药材至少提供差异清晰的载货模块。
- 碰撞体区分车身和牵引/推行空间；路径宽度不足时不得穿墙或穿过对向车辆。

### 7.3 船只

- 建立渡船、渔船、小型货船和施工船四个基础船型；船型由任务决定。
- 船体、舵、桨、帆、篷、缆绳、货物、航灯和尾流挂点独立。
- 船体水线、吃水和载货状态一致；空载/满载的水线差异需要可见但不过度夸张。
- 提供 8 方向渲染或连续旋转资产；左右非对称帆、舵、文字不得简单镜像。
- 泊位验收必须覆盖减速、对位、系缆、装卸、解缆和离港，船体不能穿岸或瞬间旋转。

## 8. 面数、LOD、UV 与材质预算

### 8.1 三角面预算

预算针对三维源资产和离线渲染场景；即使最终输出 2.5D，也必须控制源场景复杂度以支持批量九等级和动画渲染。

| 资产 | LOD0 | LOD1 | LOD2 | LOD3/替代 |
| --- | ---: | ---: | ---: | --- |
| 2×2 小建筑 | 35k | 18k | 7k | 2.5D 静态主体 |
| 3×2 / 3×3 建筑 | 60k | 30k | 12k | 2.5D 静态主体 |
| 4×3 / 4×4 大建筑 | 100k | 50k | 20k | 2.5D 静态主体 |
| 5×4 盐场/大型场地 | 130k | 65k | 25k | 分区地表＋远景合批 |
| 居民单体 | 12k | 6k | 2.5k | 方向序列帧/代表实体 |
| 货车 | 18k | 9k | 3.5k | 方向序列帧 |
| 小船 | 25k | 12k | 5k | 方向序列帧 |
| 中型船 | 45k | 22k | 8k | 方向序列帧 |
| 单棵近景树 | 8k | 3k | 800 | billboard/图集 |

- 隐藏面、重复瓦片和植被必须实例化，不允许为每级复制不可见高模。
- 轮廓件、动画机械和近景屋檐优先保留几何；细碎雕花、瓦纹和木纹烘焙进法线/颜色。
- 任何超预算资产需提交近景收益截图和性能理由，不能以“离线渲染无所谓”为由无限增长。

### 8.2 UV 和材质通道

- 建筑使用统一 texel density：主体 512 px/m，高频英雄地标可到 768 px/m；人物 1024 px/m。
- 建筑族允许共享瓦、木、灰墙、石、土、布基础材质，但必须通过顶点色、遮罩和局部贴花打破机械重复。
- UV0 用于主材质；UV1 用于烘焙 AO/光照或遮罩，禁止重叠；重复构件可在 UV0 合理重叠。
- 交付通道：`BaseColor`、`Normal`、`ORM`（AO/Roughness/Metallic）、`Emissive`、`Opacity/Mask`；必要时增加 `ID Mask` 和 `Wind Weight`。
- 金属度仅用于真实金属件；瓦、木、石、布不得通过高金属度获得“高级感”。
- 水面、湿岸、盐池和雨后地表使用独立湿润/反射遮罩，不重做整套贴图。
- 2.5D 渲染必须额外输出主体 RGBA、前景遮挡、地面接触阴影、灯火/自发光、深度或遮挡掩码；烟雾和天气粒子不烘焙进主体。

### 8.3 纹理预算

- 小建筑单等级最多 2 套 2K 材质；大型地标最多 4 套 2K。九等级共享材质库，不按等级复制全部贴图。
- 人物单职业族采用 2K 图集，服装色变通过色板遮罩。
- 车船单族采用 2K 图集；货物附件单独合图。
- 运行时 2.5D 图集按岛屿、建筑族和等级分包，单图集推荐 2048×2048，首屏不得加载全部 252 套最终资源。

## 9. 3D 渲染为 2.5D 的可行方案

采用三维建模、绑定和动画，最终为 PixiJS 输出分层 2.5D 资产，是当前浏览器项目兼顾品质与性能的可行路线。

### 9.1 建议流水线

1. 概念设计锁定四视图、俯视等距构图和九等级成长图。
2. 统一相机下完成占地白模，导入测试场景验证道路、人物、遮挡和四向旋转。
3. 中模确定结构和动画拆件，高模仅用于必要的屋脊、石雕和英雄地标烘焙。
4. 完成 UV、材质、灯光和统一色板。
5. 对机械、门窗、人物、车船完成绑定与动作。
6. 使用固定正交相机批量渲染 8 方向/4 方向、等级、状态和施工阶段。
7. 输出主体、前景、阴影、灯火、遮挡和特效挂点，生成 TexturePacker 图集及 manifest。
8. 在真实 PixiJS 场景检查锚点、深度排序、缩放清晰度、LOD 和性能。

### 9.2 不可接受的捷径

- 直接把 AI 整图切成建筑精灵。
- 每级独立生成，导致尺度、光向、屋顶结构和入口位置漂移。
- 用统一“古建筑模型”换色冒充 28 类建筑。
- 把居民、货车、船、烟、灯和生产活动全部烘焙进建筑主体。
- 只交最终 PNG，不交源模型、语义节点、材质、LOD 和 manifest。
- 以粒子、发光或上下漂浮替代机械、人物和真实生产动作。

## 10. 白模验收

任何资产在进入细化前必须通过白模关卡。

### 10.1 建筑白模

- 以统一人物、货车和地砖作比例参照，展示正交等距四方向。
- footprint、入口、道路衔接、装卸点、队列和可通行区域全部可视化。
- 展示 0–8 级同角度九宫格及 0/4/8 级叠影，确认体块连续成长而非随机换型。
- 隐藏名称后由三名评审识别建筑：功能类别识别率 100%，具体建筑识别率不低于 85%。
- 0 与 8 级投影面积、有效空间和活动点数量显著增长；8 级没有无功能大空地。
- 机械轴心、门窗开合、船舶泊位和施工分件使用简单测试动画验证。
- 四向旋转后占地、入口和阴影方向正确，无结构穿插。

### 10.2 环境白模

- 四岛分别提交 32×32 格拼装测试区，包含岸线、道路、桥、水渠、坡地和至少三类建筑。
- 人、车、船能够沿真实通道完整通过；无悬空、穿坡、穿岸和不可达入口。
- 主镇街区密度、风禾生产地貌、青岚高差、潮汐港盐空间在无材质时仍可区分。

### 10.3 人物与交通白模

- 人物完成八方向行走、转向、坐、搬、推、工作姿态测试。
- 车辆轮轴与位移一致，满载附件不穿车体和人物。
- 船只完成八方向、水线、转弯半径及完整靠离泊测试。

白模未通过不得进入高模、材质和批量九等级制作，避免在错误体块上继续投入。

## 11. 最终模型验收

- 源文件单位、命名、层级、轴心、冻结变换和法线全部正确，无孤立点、非流形面和不可解释的重叠面。
- 28 类建筑全部提供 0–8 级；逐级对比能说明主体、附属结构和运行能力的变化。
- 每类建筑至少有一项不可替代的轮廓、一套专属生产/服务设备和一组专属活动点。
- 四岛资产在统一相机、比例和光照下没有拼贴感；颜色差异不掩盖结构问题。
- 所有动画拆件轴心正确，运动中不穿主体；停工、暂停、断料时可冻结在合理姿态。
- LOD0–LOD3 切换轮廓稳定，近景到远景不出现建筑跳高、屋顶消失或角色脚底漂移。
- 2.5D 输出透明边缘干净，无白边、黑边、噪点和裁切；主体、前景、阴影、灯火可独立控制。
- 运行时隐藏名称蒙测达到既定识别率；农业、桥梁、盐场、灯塔、港口和船坊不得被误认成通用亭阁。
- 500 户、300 建筑、150 可见移动实体压力场景中，资产内存和 draw call 满足动画系统性能预算。

## 12. 美术、动画与引擎交接格式

每个资产包必须包含：

```text
asset/{domain}/{asset-id}/
  source/
    asset-id.blend
    textures/
  export/
    asset-id-lod0.glb
    asset-id-lod1.glb
    asset-id-lod2.glb
  renders/
    level-0..8/
      direction-*/
        base.png
        foreground.png
        shadow.png
        emissive.png
        occlusion.png
  previews/
    whitebox-turntable.mp4
    final-turntable.mp4
    ingame.mp4
  asset-manifest.json
  review-checklist.md
```

`asset-manifest.json` 至少声明：

- `assetId`、`buildingType`、版本、源软件和单位。
- footprint、层高、四向旋转、视觉包围盒、碰撞多边形和选择区域。
- `origin`、入口、工作点、服务点、队列、输入/输出、泊位、烟口、灯位和机械轴心。
- 0–8 级部件清单、共享模块和不可复用身份件。
- LOD 距离、三角面、材质槽、纹理尺寸、UV 密度和运行时图集分组。
- 动画部件、骨骼、片段、帧率、循环、关键帧事件及附件点。
- 2.5D 渲染相机、分辨率、方向、pivot、trim 前尺寸、遮挡和阴影层。
- 与模拟状态的映射：`idle/working/delivering/serving/blocked/constructing/upgrading/night/weather`。

交接责任：

- **概念美术**：交付九等级结构设计、功能辨识点、材质色板和四岛差异，不以气氛图替代结构图。
- **建模**：交付可编辑源模型、拆件、UV、材质、LOD、语义节点和白模/最终验收记录。
- **动画**：只使用已确认轴心、骨骼和挂点；任何新增拆件需求必须回到模型版本，不在渲染端临时切图。
- **引擎**：从 manifest 读取 footprint、pivot、遮挡、挂点和状态映射，不硬编码每张图片的偏移。
- **技术美术**：维护统一相机、灯光、批量渲染、图集、压缩、LOD 和性能检测脚本。
- **QA**：按 0–8 级九宫格、四向旋转、蒙测、通行、动画、LOD 和压力场景逐资产签字。

## 13. 建模生产放行门槛

下列条件全部满足后，MODEL-AUDIT-01 才允许转入正式模型批量生产：

1. 统一尺度、等距相机、光照和文件模板锁定。
2. 28 类建筑九等级概念结构图完成，且不再用通用亭阁替代功能建筑。
3. 每类先通过 0/4/8 三级白模，再扩展到完整 0–8 级。
4. 四岛地形模块、人物基模、基础货车和四类船型通过比例与通行测试。
5. `asset-manifest` 格式由美术、动画、引擎共同签字。
6. 选择码头、布坊、稻田、盐场、书院、灯塔六类差异最大的资产完成完整试生产，验证 3D→2.5D 管线。
7. 六类试制资产在真实 PixiJS 场景通过四向放置、遮挡、动画、昼暮、天气、LOD 和性能验收。

在上述门槛前继续批量绘制 252 张最终 PNG，只会扩大返工，不计为有效建模产出。
