# 升级经济回本与联动审计

更新时间：2026-07-16

## 目的

检查每个运行时建筑的 0→8 级升级节点，是否同时影响容量、岗位、生产价值、服务吞吐和维护费，并用统一材料价值假设估算财政回本周期。

## 可重复入口

```bash
npm run qa:upgrade-economy-audit
```

审计实现位于 `src/qa/upgradeEconomyAudit.ts`，运行时建筑目录和升级曲线是唯一输入来源；报告不是手工录入的平衡表。

## 本轮结果

- 覆盖 8 类运行时建筑、64 个升级节点。
- 健康回本 15 个，慢回本 9 个，无回报 16 个。
- 市场服务吞吐已接入等级联动：1 级保持基础吞吐，之后每 2 个等级增加 1 单/刻。
- 生产建筑已在 3/5/7 级里程碑获得产出增长与周期缩短，当前报告识别出 6 个有生产产值联动的升级节点，并把这部分真实运行时产值纳入回本估算。
- 民居和部分仓储升级在当前假设下主要增加容量/岗位，无法仅靠直接税收回本；后续需要把居住价值、物流吞吐价值和城市阶段收益纳入正式经济模型，而不是简单压低成本。

## 审计口径

- 一个财政周期为 300 tick。
- 材料按木料 10、石料 12、砖瓦 18、布匹 24 等规划价值折算。
- 新岗位按 80% 入职率和每周期 8 银两税收估算。
- 容量按每单位每周期 0.05 银两的保守影子价值估算。
- 维护费按现有财政系统的等级增量计入；服务价值按服务规则的销售价值和新增吞吐计算。

这些是假设层，不是最终商业数值。任何平衡调整必须重新运行命令并更新审计结果。
