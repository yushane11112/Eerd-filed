# 《小耳岛》商业级文明系统目标

## 目标声明

《小耳岛》的最终目标不是轻量网页玩具，也不是只展示美术概念的互动页面，而是一款可长期运营、可持续扩展、具备完整文明模拟深度的商业级横屏城市建设游戏。

项目后续所有代码、美术、动效、系统和工具任务，都必须服务于这个目标：

`活着的城市文明 × 东方水乡美术 × 可观察的真实运行机制 × 尊重音乐偏好的轻奖励入口`

## 不再接受的低标准

以下产物只能作为临时灰盒，不能作为最终目标验收：

- 单张大图或静态插画冒充游戏世界。
- 几何图形、AI 感贴图或程序化占位冒充最终建筑资产。
- 建筑升级只改变局部装饰，整体街区仍然空旷、荒凉或同质化。
- 角色、物流、生产、服务动画与模拟状态无关。
- 任务、奖励和音乐入口强行打断城市经营。
- 系统只有数值面板，没有可观察的因果后果。
- 只有几栋建筑能升级，无法形成完整文明发展。

## 商业级文明系统硬标准

### 1. 城市文明结构

首发目标必须具备完整城市文明骨架：

- 家庭：迁入、迁出、人口、收入、满意度、需求。
- 住宅：容量、等级、服务覆盖、居民生活动画。
- 就业：岗位、通勤、缺工、停工、收入变化。
- 道路：连通、断路、拥堵、通勤和物流影响。
- 产业：原料、加工、产出、库存、效率、停摆。
- 仓储：容量、溢出、调拨、优先级。
- 市场：货物供应、居民消费、缺货后果。
- 服务：医疗、教育、娱乐、治安/秩序等可扩展服务。
- 财政：税收、维护费、建设成本、城市预算压力。
- 成长：建筑等级、街区繁荣、主题岛解锁、文明阶段演进。

任何一个系统不得只是静态字段，必须至少产生一种可观察后果。

### 2. 可观察运行

模拟结果必须能在地图上看见：

- 缺工：建筑变慢、停工标识、居民通勤不足。
- 缺料：生产暂停、仓库/搬运路线异常。
- 断路：居民/物流绕行或失败，服务覆盖中断。
- 缺货：居民需求下降，市场状态变化。
- 仓满：生产建筑停摆或改派运输。
- 服务不足：居民满意度下降，长期触发迁出。

UI 只能解释世界，不能替代世界。

### 3. 动态引擎标准

地图必须是可交互、可拖拽、可缩放、可全屏的动态世界：

- PixiJS 场景分层：地形、道路、建筑、人物、车辆、船只、材料、VFX、UI 提示。
- 实体对象池、视口裁剪和 LOD 必须支撑压力目标。
- 人物、物流和建筑动画由模拟状态驱动。
- 晨昼暮、水、云影、树叶、炊烟、灯火、施工和经营活动必须持续运动。
- 目标压力：500 户家庭、300 栋建筑、150 个可见移动实体稳定运行。

### 4. 美术资产标准

最终资产必须满足批量生产与审计：

- 28 类建筑，每类 0–8 级。
- L0 是明确废墟/荒地。
- L8 是完整营业、街区繁华、人流和功能物充足。
- 不同建筑必须在轮廓、占地、色彩、功能物、动画上可盲测区分。
- 资产必须包含源文件、导出图集、pivot、碰撞、动画槽位、LOD 和 manifest。
- 程序化灰盒只用于验证，不得作为最终美术。

### 5. 音乐关系标准

音乐是温和增强，不是体力系统：

- 用户听任意歌曲都可参与，不指定歌手、歌单或风格。
- 普通材料主要来自城市自然掉落和城市运行。
- 听完歌曲只给稀缺材料、蓝图或轻量加速，不阻塞基础进度。
- 音乐事件可跳过，答错无惩罚，不形成独立强制货币。

## 里程碑调整

### 当前阶段判断

当前项目仍处于“商业级灰盒 + 金标生产链早期”：

- 已有模拟核心、道路、物流、服务、材料、稀缺奖励、Pixi 动态骨架。
- 已有少量金标 manifest 样例和程序化视觉切片。
- 但还没有完整 28 类建筑资产、完整文明 UI、正式角色动画、正式美术和完整长期平衡。

因此不能宣称接近最终商业级游戏。

### 下一阶段目标

下一阶段必须优先补齐：

1. 文明系统矩阵：家庭、就业、市场、服务、财政、道路、产业的完整因果链。
2. 建筑升级系统：从灰盒 level 到真实 0–8 级进度、成本、视觉状态和城市后果。
3. 资产生产门禁：将样例 manifest 从 3 个扩展到 6 个金标建筑，并提高 validator 对 L0–L8 的要求。
4. 动态街区表现：不是单栋建筑动，而是街区整体从荒地到繁华。
5. 长稳与性能：自动跑长时间城市模拟并记录退化、拥堵、迁出和性能。

## 主控原则

- 如果一个任务只让画面“更像游戏”，但不推动真实模拟、动态引擎或资产管线，它优先级下降。
- 如果一个任务能让城市运行更真实、资产更可量产、表现更可验证，它优先级上升。
- 任何“最终效果”必须有测试、截图/录像或可运行构建作为证据。
