# 《小耳岛》商业级文明系统目标

> 2026-06-27 方向更新：本文件由 `commercial-launch-master-plan.md` 统领。项目主线已从“岛屿养成 + 听歌材料 + 固定 28 类建筑”调整为“架空明清江南水乡城市文明模拟”。旧的四岛、听歌材料和 28 类建筑表述只作为历史原型或可复用工程遗产，不再作为最终商业级主线验收。

## 目标声明

《小耳岛》的最终目标不是轻量网页玩具，也不是只展示美术概念的互动页面，而是一款可长期运营、可持续扩展、具备完整文明模拟深度的商业级横屏城市建设游戏。

项目后续所有代码、美术、动效、系统和工具任务，都必须服务于这个目标：

`活着的城市文明 × 统一年代东方水乡美术 × 可观察的真实运行机制 × 可扩展商业级生产流水线`

最终玩法全面对齐《凯撒大帝》类城市建设：自由规划城市、铺路架桥、吸引外来人口、建设住宅和产业、建立仓储物流和市场消费、通过财政与公共服务治理城市风险，并让村落逐步成长为繁华水乡城市。

音乐、掉落材料、岛屿解锁和固定点位修复不再进入主循环。若未来保留音乐联动，只能作为非核心外部入口或氛围/活动层，不得阻塞基础城市发展。

## 不再接受的低标准

以下产物只能作为临时灰盒，不能作为最终目标验收：

- 单张大图或静态插画冒充游戏世界。
- 几何图形、AI 感贴图或程序化占位冒充最终建筑资产。
- 建筑升级只改变局部装饰，整体街区仍然空旷、荒凉或同质化。
- 角色、物流、生产、服务动画与模拟状态无关。
- 任务、奖励、音乐或平台入口强行打断城市经营。
- 系统只有数值面板，没有可观察的因果后果。
- 只有几栋建筑能升级，无法形成完整文明发展。
- 建筑、交通、人物或产业跨时代混搭，破坏架空明清江南水乡设定。

## 商业级文明系统硬标准

### 1. 城市文明结构

首发目标必须具备完整城市文明骨架：

- 家庭：迁入、迁出、人口、收入、满意度、需求。
- 住宅：容量、等级、服务覆盖、居民生活动画。
- 就业：岗位、通勤、缺工、停工、收入变化。
- 道路：连通、断路、拥堵、通勤和物流影响。
- 产业：原料、加工、产出、库存、效率、停摆。
- 仓储：容量、溢出、调拨、优先级。
- 市场：货物供应、居民消费、缺货后果。
- 服务：医疗、教育、娱乐、治安/秩序等可扩展服务。
- 财政：税收、维护费、建设成本、城市预算压力。
- 成长：住宅发展、街区繁荣、城市阶段、行政能力、文明阶段演进。
- 人口生命周期：外来人口抵达、找房、临时停留、正式入住、稳定生活和离城。

任何一个系统不得只是静态字段，必须至少产生一种可观察后果。

### 2. 可观察运行

模拟结果必须能在地图上看见：

- 缺工：建筑变慢、停工标识、居民通勤不足。
- 缺料：生产暂停、仓库/搬运路线异常。
- 断路：居民/物流绕行或失败，服务覆盖中断。
- 缺货：居民需求下降，市场状态变化。
- 仓满：生产建筑停摆或改派运输。
- 服务不足：居民满意度下降，长期触发迁出。

UI 只能解释世界，不能替代世界。

### 3. 动态引擎标准

地图必须是可交互、可拖拽、可缩放、可全屏的动态世界：

- PixiJS 场景分层：地形、道路、建筑、人物、车辆、船只、材料、VFX、UI 提示。
- 实体对象池、视口裁剪和 LOD 必须支撑压力目标。
- 人物、物流和建筑动画由模拟状态驱动。
- 晨昼暮、水、云影、树叶、炊烟、灯火、施工和经营活动必须持续运动。
- 目标压力：500 户家庭、300 栋建筑、150 个可见移动实体稳定运行。

### 4. 美术资产标准

最终资产必须满足批量生产与审计：

- 建筑类别不设固定上限，由城市模拟和商业级内容规模决定。
- 所有建筑必须符合 `design/world-bible.md` 的统一年代设定。
- 建筑体系必须覆盖住宅、道路交通、农业资源、手工业、仓储商业、公共服务、行政礼制、景观文化和街区型内容。
- 高级城市必须形成商业街、夜市、码头仓区、官署街、书院街、园林住宅区等高密度繁荣街区。
- 不同建筑必须在轮廓、占地、色彩、功能物、动画上可盲测区分。
- 资产必须包含源文件、导出图集、pivot、碰撞、动画槽位、LOD 和 manifest。
- 程序化灰盒只用于验证，不得作为最终美术。

### 5. 废弃/降级内容

以下内容不再作为最终主线：

- 固定 28 类建筑上限。
- 固定岛屿数量和岛屿解锁。
- 听歌捡材料或听歌奖励作为核心成长。
- 固定建筑点位修复。
- 单张大图式静态场景。

这些内容若保留，只能降级为历史原型、活动、彩蛋或可复用工程模块。

## 里程碑调整

### 当前阶段判断

当前项目仍处于“商业级灰盒 + 金标生产链早期”：

- 已有模拟核心、道路、物流、服务、部分旧材料/奖励模块、Pixi 动态骨架。
- 已有少量金标 manifest 样例和程序化视觉切片。
- 但还没有可扩展建筑/街区资产库、完整文明 UI、正式角色动画、正式美术和完整长期平衡。

因此不能宣称接近最终商业级游戏。

### 下一阶段目标

下一阶段必须优先补齐：

1. 文明系统矩阵：人口生命周期、就业、市场、服务、财政、道路、产业和风险的完整因果链。
2. 建筑和街区体系：从固定建筑清单改为可扩展、年代一致、功能可辨的城市建筑谱系。
3. 美术全阶段生产线：从灰盒、概念、金标、Alpha 量产、Beta 完整化到 RC 冻结。
4. 动态街区表现：不是单栋建筑动，而是街区整体从荒村到盛世水都。
5. 长稳与性能：自动跑长时间城市模拟并记录退化、拥堵、迁出和性能。

## 主控原则

- 如果一个任务只让画面“更像游戏”，但不推动真实模拟、动态引擎或资产管线，它优先级下降。
- 如果一个任务能让城市运行更真实、资产更可量产、表现更可验证，它优先级上升。
- 任何“最终效果”必须有测试、截图/录像或可运行构建作为证据。
