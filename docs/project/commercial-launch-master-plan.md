# 《小耳岛》商业级完整上线总计划

## 1. 产品定位

《小耳岛》的最终目标是一款可正式上线、可长期运营的东方水乡城市文明模拟游戏，而不是轻量网页原型、岛屿养成或视觉 Demo。

最终定位：

- 类型：架空明清江南水乡题材城市建设 / 文明模拟游戏。
- 玩法参照：《凯撒大帝》类城市规划、人口、产业、物流、市场、财政、服务和风险治理。
- 核心体验：从荒地村落规划道路、住宅、产业和公共服务，逐步发展为人口流动、商业繁荣、船运密集、灯火连绵的水乡城市。
- 商业级标准：系统闭环完整、状态可观察、画面动态可信、美术年代统一、内容规模充足、性能稳定、测试充分、可部署、可维护。

明确废弃为主线：

- 固定 28 类建筑上限。
- 固定岛屿数量与岛屿解锁。
- 听歌捡材料或听歌奖励作为核心成长。
- 固定建筑点位修复式养成。
- 单张大图式静态场景。
- 与架空明清江南水乡时代冲突的建筑、交通、服饰和技术。

## 2. 上线质量目标

正式上线版本必须满足：

- 自由铺路、建桥、规划水路和放置建筑。
- 外来人口抵达、找房、找工、临时停留、正式入住、就业、消费、纳税和迁出。
- 住宅、道路、生产、仓储、物流、市场、财政、公共服务和城市风险形成真实闭环。
- 居民、挑夫、推车、船只、商贩、工匠、巡丁、医师等可见实体由模拟状态驱动。
- 缺路、缺工、缺货、仓满、财政赤字、疾病、火灾、犯罪、低满意度产生可观察后果。
- 后期城市形成商业街、夜市、码头仓区、官署街、书院街、庙会街、园林住宅区等高密度街区。
- 300+ 建筑、500+ 家庭、150+ 可见移动实体稳定运行。
- 存档读档、构建部署、自动测试、长时间运行和性能测试稳定。

## 3. 完整阶段路线

| 阶段 | 目标 | 阶段产出 | 完成标准 |
| --- | --- | --- | --- |
| P0 商业定位与项目中枢 | 冻结方向，消除旧原型冲突 | 总目标、世界观、建筑谱系、人口生命周期、城市阶段、美术流水线、任务看板、仪表盘、产物索引 | 所有文档统一指向东方水乡城市文明模拟 |
| P1 城市灰盒 MVP | 先做真实城市，不先堆美术 | 铺路、放建筑、住宅、外来人口、就业、通勤、生产、仓库、市场、税收、基础财政 | 小城可从 0 人发展为稳定村镇，规划错误会造成停滞 |
| P2 完整城市模拟闭环 | 让城市像城市一样运行 | 多商品需求、多产业链、仓储优先级、市场补货、道路效率、税率、维护费、满意度、城市吸引力 | 食物、就业、税负、服务、道路和财政共同影响兴衰 |
| P3 动态可视化引擎 | 让模拟状态在地图上可见 | Pixi 分层、相机、全屏、实体池、居民/物流/船运/施工/风险动画、环境动效 | 不开面板也能看出城市主要状态 |
| P4 公共服务、风险与治理 | 从资源摆放进入城市治理 | 水源、医疗、治安、消防、教育、宗教、娱乐、服务图层、火灾、疾病、犯罪、人口外流 | 服务不足真实影响住宅、人口、财政和城市吸引力 |
| P5 建筑体系与城市阶段 | 建立商业级内容骨架 | 住宅、交通、农业、手工业、仓储、市场、服务、行政、文化、宗教、景观、街区型建筑；六阶段城市 | 后期繁荣由街区、人流、灯火、商业、文化、行政共同体现 |
| P6 美术金标垂直切片 | 证明最终画质方向可达 | 金标建筑、金标街区、角色、环境动效、UI 视觉规范 | 摆脱灰盒和 AI 感，功能隐藏名称后仍可辨认 |
| P7 Alpha 内容扩展 | 扩展为完整可玩版本 | 40–60 类建筑、8–12 条产业链、完整服务/风险、存档、新手引导、自动测试 | 可连续游玩 2–4 小时，达到内部测试质量 |
| P8 Beta 商业打磨 | 从能玩提升到可上线 | 80+ 建筑或街区方向、完整 UI/UX、音效、视觉审计、性能优化、用户测试修复 | 新用户能理解，中后期有目标，稳定性达到外测要求 |
| P9 Release Candidate | 冻结上线版本 | 功能、内容、数值、美术冻结；完整测试报告、发布包、回滚方案 | 没有阻塞级崩溃、死锁、资源复制、数值爆炸 |
| P10 正式上线与持续运营 | 支持上线后维护扩展 | 部署、监控、热修复、内容更新、平衡调整 | 问题可追踪、可修复、可迭代 |

## 5. 自动执行机制

后续开发不按临时想法推进，而按固定循环执行：

1. 读取总目标、当前阶段、任务看板和进度仪表盘。
2. 识别最高优先级缺口。
3. 拆成 3–5 个可并行任务。
4. 分配到对应生产线，并明确文件所有权、输入依赖、输出产物、验收标准和测试命令。
5. 执行代码、文档、资产或测试工作。
6. 集成产物并运行验证。
7. 更新任务看板、集成日志、进度仪表盘、产物索引和 QA 记录。
8. 提交 Git 并推送 GitHub。
9. 汇报真实产出、测试结果、进度变化和下一轮任务。

默认优先级：

1. 方向冲突。
2. 核心模拟缺口。
3. 可观察动态表现。
4. UI 可理解性。
5. 美术金标质量。
6. 内容规模。
7. 性能稳定。
8. 发布质量。

如果遇到阻塞，必须记录阻塞并切换到不依赖该阻塞的任务，不允许虚假标记完成。

## 5.1 2026-07-12 执行节奏校准

长期总目标不变，仍然是商业级东方水乡城市文明模拟游戏。当前项目已经完成方向统一、旧原型隔离、城市灰盒闭环、治理链路、物流动作、长跑 QA 和首批金标占位视觉接入，因此后续不应继续按早期 P0 文档重构节奏推进。

当前默认阶段调整为 **P1.5 商业级垂直切片收敛期**。

执行要求：

1. 每轮只选择一个主目标。
2. 优先做能让玩家看见、操作或验证的增量。
3. 系统内部重构必须说明它如何支撑下一步可见或可玩结果。
4. 文档记录以阶段判断、风险、产出和下一步为主，不再重复堆长篇流水账。
5. 测试按 `execution-strategy.md` 的 Tier 0-4 分级执行，避免低风险文档/视觉小改消耗最高成本验证。

近期三轮优先顺序：

1. Starter 建筑第一眼改观。
2. 道路与街区质感。
3. 活动密度与状态反馈。

物流、经济表、服务容量、浏览器 E2E 和长跑 QA 继续推进，但近期必须优先服务于垂直切片或真实操作闭环。

每轮用户汇报必须包含：

- 本轮完成内容。
- 实际修改文件。

- 测试命令和结果。
- 当前阶段进度变化。
- 整体商业级完成度变化。
- 下一轮自动任务。

## 7. 商业级完成度规则

- 只有文档，没有代码：不能算系统完成。
- 只有代码，没有测试：不能算商业级完成。
- 只有静态画面，没有状态驱动：不能算动态引擎完成。
- 只有建筑数量，没有功能差异：不能算建筑体系完成。
- 只有能跑，没有稳定性：不能算上线完成。

## 8. 美术全阶段上线要求

美术不是首批金标建筑任务，也不是开发末期补皮肤。商业级上线必须按 `design/art-production-roadmap.md` 从 ART-P0 到 ART-P11 持续推进：

| 美术阶段 | 上线意义 | 不可跳过的产出 |
| --- | --- | --- |
| ART-P0 美术方向冻结 | 防止资产各画各的 | 世界视觉圣经、年代白/黑名单、材料、色板、线条、透视、城市密度 |
| ART-P1 灰盒辨识 | 先保证系统可读 | 地形、道路、水岸、桥梁、住宅、市场、仓储、生产、服务、行政灰盒和状态符号 |
| ART-P2 概念谱系 | 建立完整建筑语言 | 住宅、商业、生产、服务、行政、文化、景观和街区概念谱系 |
| ART-P3 金标切片 | 证明最终画质方向 | 金标建筑、金标街区、正式角色、状态动画、环境动效 |
| ART-P4 角色体系 | 让城市人口有身份 | 外来人口、正式居民、职业角色、阶层差异和入住前后视觉差异 |
| ART-P5 状态动画 | 让建筑状态可观察 | 正常、缺工、缺货、仓满、停摆、施工、风险、高繁荣状态动画 |
| ART-P6 环境密度 | 解决空地和局部升级 | 水岸、园林、街边杂物、灯火、摊位、院落、广场、节庆装饰 |
| ART-P7 UI 视觉 | 支撑复杂城市管理 | 状态栏、建造菜单、详情面板、图层、顾问、引导和图标体系 |
| ART-P8 Alpha 量产 | 扩展到可玩规模 | 40–60 类建筑视觉方案、核心角色动画、街区资产和环境资产 |
| ART-P9 Beta 完整化 | 达到外测丰富度 | 80+ 建筑/街区方向、全城市阶段视觉覆盖、灾害和节庆表现 |
| ART-P10 RC 冻结 | 上线前清退风险 | 全资产清单、占位替换、年代审计、功能盲测、截图验收 |
| ART-P11 运营扩展 | 支撑上线后更新 | 新建筑、新街区、节日、新地图、装饰和热更新资产规范 |

上线前的美术验收必须证明：没有核心灰盒残留，没有错时代资产，没有明显 AI 感，没有建筑同质化，后期城市能形成连续繁华街区，且所有关键动效都由模拟状态驱动。
