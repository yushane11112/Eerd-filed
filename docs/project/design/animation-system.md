# 《小耳岛》动态城市动画制作体系

## 1. 目标与不可妥协原则

本体系用于把真实城市模拟状态转换为可读、可追溯、可扩展的动态画面。动画不能自行制造生产、运输、营业或居民活动；渲染层只能读取模拟快照、离散事件和渲染时钟，绝不能反向修改经济结果。

### 1.1 强制原则

- **禁止无状态漂移假动画**：没有行为目标的居民不得随机游荡；没有物流订单的车辆不得空跑；停工建筑不得继续生产；没有船运任务的船不得以“繁华装饰”为由循环航行。
- 每个有游戏含义的动作必须能追溯至 `BuildingEntity`、`AgentEntity`、`LogisticsOrder`、天气/昼暮状态或明确的表现事件。
- 模拟 Tick 决定事实，渲染帧只做位置插值、动作混合、粒子采样和镜头反馈。
- 装饰性环境动画可以持续循环，但不得冒充生产结果。水流、树叶、旗帜、云影等必须被标记为 `ambient`。
- 暂停模拟时，生产、运输、施工和人物行为动画冻结；纯环境动画默认降至 25% 速度，设置中可选择完全冻结。
- 同一建筑类型必须有专属生产动作和功能轮廓，不得用统一发光点、统一冒烟或统一人物绕圈替代。
- 动画不得遮挡道路入口、掉落材料、停工提示和建筑选择反馈。

## 2. 动画运行架构

### 2.1 数据流

```text
SimulationSnapshot + SimulationEvent + SceneTime
                    │
                    ▼
          AnimationStateResolver
  （状态映射、边沿检测、优先级、去抖）
                    │
                    ▼
           AnimationIntent[]
  （实体、槽位、片段、速度、相位、附件、音效）
                    │
                    ▼
       AnimationGraph / Visual Controller
 （混合、插值、LOD、可见性、对象池、图集实例）
                    │
                    ▼
        PixiJS 分层渲染 + Audio Bus
```

`AnimationStateResolver` 必须保存上一帧已消费的模拟快照摘要，用于识别状态边沿，例如 `idle → working`、订单 `waiting → assigned`、建筑等级变化和天气变化。边沿事件只触发一次，持续状态按 Tick 驱动。

### 2.2 动画意图

后续实现应增加与模拟契约隔离的渲染类型：

```ts
type AnimationDomain =
  | 'ambient' | 'citizen' | 'building' | 'logistics'
  | 'shipping' | 'construction' | 'weather' | 'feedback'

interface AnimationIntent {
  entityId: EntityId
  domain: AnimationDomain
  slot: string
  clip: string
  phase: 'enter' | 'loop' | 'exit' | 'oneshot'
  priority: number
  normalizedProgress?: number
  playbackRate: number
  direction?: 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7
  attachment?: ResourceKind | 'tool' | 'umbrella' | 'lantern'
  startedAtTick: Tick
}
```

动画意图是渲染内部协议，不写回 `SimulationSnapshot`。同一实体同一槽位最多有一个主片段，按优先级抢占：

1. 拆除、受阻安全反馈；
2. 施工与升级；
3. 运输、服务、生产；
4. 行走与一般行为；
5. 待机；
6. 环境装饰。

### 2.3 模拟状态到动画状态映射

| 模拟事实 | 动画状态 | 进入条件 | 退出条件 | 禁止表现 |
| --- | --- | --- | --- | --- |
| `constructing` | `construction.active` | 建筑进入施工状态 | 状态改变或进度完成 | 正常营业、成品装车 |
| `upgrading` | `construction.upgrade` | 升级事务开始 | 等级写入快照 | 直接闪白换皮 |
| `working` | `production.loop` | 有工人、原料、容量且周期推进 | 周期暂停或状态改变 | 无进度时持续生产 |
| `delivering` | `logistics.loading/unloading` | 存在匹配订单和承运者 | 装卸阶段完成 | 无订单出现货车 |
| `serving` | `service.active` | 存在服务对象/服务事务 | 服务完成或无对象 | 空建筑持续拥挤 |
| `blocked` | `blocked.idle` | 模拟给出 `statusReason` | 阻塞解除 | 烟火旺盛、满负荷机器 |
| `idle` | `idle.staffed` / `idle.empty` | 无有效工作周期 | 工作或施工开始 | 假装产出 |
| Agent `commuting` | `locomotion.walk` | 有有效路径及下一节点 | 抵达或路径失效 | 原地走路不位移 |
| Agent `working` | `occupation.*` | 到达雇主交互点 | 下班、任务取消 | 在住宅内播放作坊动作 |
| Agent `delivering` | `carry.walk` / `vehicle.move` | 已分配有效订单 | 交付、取消或等待 | 携带错误货物 |
| Order `in_transit` | 货物附件可见 | 承运者持有订单 | 订单交付/取消 | 货物提前出现在目的地 |
| 昼暮变化 | `lighting.transition` | `SceneTime` 跨段 | 插值完成 | 瞬间换色 |
| 天气变化 | `weather.enter/loop/exit` | 天气状态改变 | 下一天气稳定 | 室内外效果无差别 |

生产循环的 `normalizedProgress` 必须由 `productionProgress / durationTicks` 得出。动作关键帧与生产阶段绑定，例如备料 0–20%、加工 20–75%、收尾 75–95%、入库 95–100%。模拟未推进时动画相位不得自行越过下一阶段。

## 3. 人物八方向动作体系

### 3.1 方向与命名

人物采用八方向：`N、NE、E、SE、S、SW、W、NW`，资源键统一为：

```text
citizen/{body}/{outfit}/{action}/{direction}/{frame}
```

镜像仅允许 `E↔W`、`NE↔NW`、`SE↔SW`，且以下资源不得镜像：带文字招牌、单肩货物、非对称工具、固定衣襟、明确左右手工序。美术验收必须检查镜像后衣襟和工具方向。

### 3.2 基础动作集

| 动作 | 帧数 | 播放帧率 | 循环 | 状态来源 |
| --- | ---: | ---: | --- | --- |
| `idle-breathe` | 6 | 6 fps | 是 | 无任务且驻留点有效 |
| `walk` | 8 | 10 fps | 是 | 路径速度大于 0 |
| `walk-carry-light` | 8 | 10 fps | 是 | 承运轻型货物 |
| `walk-carry-heavy` | 10 | 10 fps | 是 | 承运木、石、砖等重物 |
| `push-cart` | 8 | 10 fps | 是 | 货车订单移动 |
| `work-tool` | 10–16 | 8 fps | 是 | 到达职业交互点 |
| `serve` | 10 | 8 fps | 按事务 | 服务事务存在 |
| `shop` | 8 | 8 fps | 按事务 | 采购事务存在 |
| `sit/eat/drink/read/watch` | 8–12 | 6–8 fps | 按事务 | 对应服务状态 |
| `board/disembark` | 8 | 10 fps | 否 | 船运阶段边沿 |
| `react-success` | 8 | 12 fps | 否 | 事务成功反馈 |
| `react-blocked` | 6 | 6 fps | 限时循环 | 路径或事务受阻 |

人物身体基准单元为 48×64 px；含扁担、伞、长工具的动作单元为 72×72 px；高 DPI 源文件按 2 倍尺寸绘制，运行时按 1 倍逻辑尺寸显示。角色脚底锚点固定为 `(0.5, 0.88)`，所有方向不得跳锚。

### 3.3 行为衔接

- 转向优先使用最近的八方向，方向抖动需设置 120 ms 滞后。
- 行走速度与路径插值严格同步；动画步频按世界速度缩放，脚底滑移误差不得超过一个角色脚宽。
- 抵达交互点后先播放 4–8 帧进入动作，再进入职业循环；离开时播放退出动作。
- 路径失效时停止位移并进入 `react-blocked`，不得穿越建筑、河流或继续原路径。
- 同屏居民允许外观组合复用，但相邻居民不得出现完全相同的服装、动作相位和颜色组合。
- 人群密度来自真实家庭和事务抽样。LOD 降级只能减少可见代表人数，不得改变人口、产能或订单。

## 4. 建筑、物流、船运与施工动画

### 4.1 建筑通用槽位

每个建筑资产包可声明下列槽位；不适用的槽位必须显式填 `none`，不得用通用占位动画冒充：

| 槽位 | 内容 | 状态约束 |
| --- | --- | --- |
| `base` | 主体静态层与等级外观 | 始终存在 |
| `idle-detail` | 门帘、旗帜、轻烟等低强度细节 | 建筑已建成 |
| `staff-entry` | 工人进出与开门 | 工人抵达/离开 |
| `input-receive` | 原料卸入 | 有入库订单 |
| `production-primary` | 核心生产动作 | `working` 且进度推进 |
| `production-secondary` | 辅助工序 | 指定进度区间 |
| `output-ready` | 成品可见 | 成品库存大于 0 |
| `output-dispatch` | 装车、装船或搬出 | 有出库订单 |
| `service` | 接待、授课、演出等 | `serving` 且有对象 |
| `blocked` | 熄火、关门、缺货牌等 | `blocked`，按原因选择 |
| `construction` | 脚手架、搬料、施工 | `constructing/upgrading` |
| `night` | 灯笼、窗光、灯塔光束 | 暮色且建筑可运行 |
| `weather` | 雨檐、水迹、风向响应 | 对应天气 |

建筑状态切换采用 150–350 ms 的可打断混合；不得通过整体缩放呼吸表现“运行”。大型机械必须有明确轴心，轮、磨盘、绞盘的旋转速度由生产进度决定。

### 4.2 物流

- 搬运订单创建后才允许生成或唤醒承运者。
- 装货动画发生在来源建筑出口，完成后货物附件才绑定到承运者。
- 运输期间附件种类和订单 `resource` 一致；木料、石料、布匹、鱼获、盐袋和药材具有不同轮廓。
- 抵达目的地后先播放卸货，再由下一模拟快照确认库存变化；网络/帧延迟时允许短暂等待，不得提前隐藏货物。
- 订单取消：未取货则收起承运者；已取货则根据模拟决策返仓或原地等待，不由动画层销毁货物。
- 货车轮速必须匹配位移；转弯时车身按路径切线旋转，转角使用 100–180 ms 平滑。

### 4.3 船运

- 船只只由港口、渡口、渔港、船坊或明确航运订单生成。
- 船体采用路径切线朝向，至少提供 8 方向船体或可旋转俯视资产；船尾水迹仅在速度大于阈值时出现。
- 靠泊分为减速、对位、系缆、装卸、解缆、离港六阶段。
- 渔船出航、下网、等待、收网、返港分别绑定渔业任务阶段；不得绕岛无限循环。
- 暮色航行开启航灯；灯塔光束只在暮色、天气或导航状态允许时运行。
- 水面波纹属于环境层，船尾水迹属于实体效果层，两者生命周期分离。

### 4.4 施工与升级

施工动画必须覆盖“从旧状态到新状态”的真实过渡：

1. 场地围挡与测量；
2. 材料搬入；
3. 脚手架搭建；
4. 基础/墙体/屋面分阶段显现；
5. 落瓦、挂牌、清场；
6. 工人离场与居民/职员入驻。

每一级升级至少改变一项主体结构和一项环境活动。禁止只用尘土遮罩后瞬间换图。施工进度由模拟建设进度驱动，断料、断路或暂停时工人停下并显示对应状态。等级 0–8 的阶段资产可分片揭示，但新等级完整主体只在等级事务确认后成为正式 `base`。

## 5. 昼暮、天气、粒子、骨骼与音画反馈

### 5.1 昼暮与天气

- 晨、昼、暮使用连续光照插值，标准过渡 8–15 秒；镜头切换不得重置时间相位。
- 晨：冷暖交界、薄雾、开门与上工；昼：中性高亮、生产最清晰；暮：暖窗、灯笼、收摊、返家和夜航灯。
- 晴、细雨、微风、薄雾分别控制粒子密度、植被摆幅、水面响应、人物附件和环境音。
- 下雨时室外人物使用伞、斗笠或加速通行；室内生产不叠加雨粒子。
- 风向是全场共享参数，旗帜、烟、树叶、雨丝不得各自随机朝向。
- 天气只改变表现和模拟已定义的参数，动画层不得自行改变产量或移动速度。

### 5.2 粒子使用边界

适合粒子：烟雾、蒸汽、火星、尘土、落叶、雨、薄雾、萤火、船尾碎浪、拾取轨迹。

不适合粒子：屋瓦、人物、货物、生产机械、船体、可交互材料主体。此类对象必须使用精确精灵、序列帧或骨骼。

粒子必须绑定发射原因和生命周期：

- 窑火火星仅在烧制阶段；
- 炊烟仅在食肆工作或住宅做饭时段；
- 施工尘土仅在施工动作击打关键帧；
- 停工后在 0.5 秒内停止新增粒子，存量自然消散；
- 离开视口后停止发射，不补播离屏期间粒子。

### 5.3 骨骼使用边界

- 人物主体首版优先八方向序列帧，保证工笔轮廓和动作一致性。
- 骨骼适用于大幅连续形变且可复用的对象：树冠、长旗、船帆、巨型水车皮带、戏台帷幕。
- 不使用骨骼扭曲建筑主体、屋檐、桥体或刚性车辆。
- 骨骼网格顶点应控制在单对象 80 个以内，骨骼数不超过 12；超出需证明序列帧不可替代。

### 5.4 音画反馈

- 音效触发点来自动画关键帧，但事务是否成功由模拟决定。
- 脚步、工具、装卸、船桨、钟声按屏幕距离和缩放衰减；同类声音设置 80–150 ms 随机音高/音量微差。
- 同屏同类生产音最多 4 路，超出按距离聚合成环境声床。
- 建成反馈采用挂牌/钟磬、居民欢呼、短促粒子和镜头轻推，不使用强闪白。
- 拾取反馈包括实体压缩、弧线飞入、仓库落点和轻音效；库存确认失败时必须回弹，不得假装入账。
- 暮色环境声降低生产高频，提高水声、虫鸣和远处人声；不得覆盖音乐播放。

## 6. 图集、尺寸与制作规范

### 6.1 图集规格

- PixiJS 使用 TexturePacker 兼容 JSON Hash 图集，启用 trim，但保存原始尺寸与 pivot。
- 单张图集推荐 2048×2048，桌面高配上限 4096×4096；移动端不得依赖 4096 图集。
- RGBA PNG/WebP 使用预乘 Alpha；禁止含白边、黑边和未经清理的半透明噪点。
- 同一动作所有帧保持统一画布、脚底/建筑基座锚点和光源。
- 建筑以逻辑格为标尺：1 格 64×32 px 等距地砖；资产按最高外扩范围预留，不得裁掉烟、长工具或屋檐。
- 普通建筑单级主体建议控制在 512×512 逻辑像素内；4×4、5×4 大型建筑允许 768×768；超出部分拆为主体、前景、效果附件。

### 6.2 帧率标准

- 人物行走 10 fps，快速反馈 12 fps，工作 8 fps，待机 6 fps。
- 建筑机械 8–12 fps；火焰、水花可 12–15 fps；烟、雾由粒子或 8 fps 序列完成。
- 动画以渲染秒为采样单位，但生产动作相位由模拟进度钳制。
- 1×、2×、4×模拟速度下，动作速度同步提高；超过 18 fps 的片段采用跳帧而非加载额外帧。
- 所有循环首尾速度和轮廓连续，禁止明显“吸回第一帧”。

### 6.3 资源命名

```text
building/{buildingType}/level-{0..8}/{slot}/{clip}-{direction?}
citizen/{archetype}/{outfit}/{action}/{direction}
vehicle/{kind}/{loadState}/{action}/{direction}
ship/{kind}/{loadState}/{action}/{direction}
environment/{kind}/{weather}/{clip}
effect/{domain}/{clip}
```

每个建筑资源包同时提交 `animation-manifest.json`，记录槽位、帧率、循环、锚点、触发状态、进度区间、附件点、音效标记和 LOD 替代方案。

| --- | --- | --- | --- |
| 旧码头 | 绞盘、系缆、跳板开合 | 木箱装卸、货船靠离 | 多泊位排程、搬运队列、港灯 |
| 青石渡口 | 售票、候船、上下客 | 行李搬运 | 双向渡船按班次靠泊 |
| 听雨桥 | 行人过桥、桥亭避雨 | 小推车通行 | 桥头摊贩与连续人流，不生成船 |

### 7.1 阻塞状态的差异化表现

- 缺工：设备静止、门开但工位空，不播放“缺货牌”。
- 缺原料：原料区空、工人检查库存，炉火/机械停止。
- 仓满：成品堆满指定区域、装卸口等待。
- 断路：入口出现受阻提示，承运者停在最后可达节点。
- 财政不足：维护性细节降低、服务窗口缩减，不把建筑重新画成废墟。
- 暂停：所有事实动画定格，不显示故障。

## 8. LOD、裁剪与对象池

### 8.1 LOD 分级

| 等级 | 屏幕条件 | 人物 | 建筑 | 粒子/音频 |
| --- | --- | --- | --- | --- |
| LOD0 | 近景，缩放 ≥ 1.15 | 八方向完整动作、附件、表情 | 主副工序、装卸、服务全开 | 100%，独立定位音 |
| LOD1 | 中景，0.72–1.15 | 6–8 帧动作，减少表情 | 主工序与关键附件 | 60%，同类音聚合 |
| LOD2 | 远景，0.4–0.72 | 每 2–4 人合并为代表实体 | 低帧率主轮廓动画 | 25%，仅大烟雾/水流 |
| LOD3 | 极远或边缘 | 不渲染个体 | 静态主体＋状态标识＋暮灯 | 5%，仅全局环境声 |

LOD 切换使用 250 ms 淡化，不能造成实体闪现。降低 LOD 不改变模拟状态、路径、订单和生产进度。

### 8.2 对象池

- 分池管理 `CitizenVisual`、`VehicleVisual`、`ShipVisual`、`BuildingEffectVisual`、`ParticleEmitter` 和 `WorldDropVisual`。
- 池化对象释放时必须清除实体 ID、纹理、附件、音效句柄、事件监听、相位、滤镜和父容器。
- 池容量按压力目标预热：居民 180、陆运 48、船只 24、建筑效果 160、掉落 36；上限由设备档位调整。
- 不可见对象停止动画采样与粒子发射，但保留由快照计算的最终位置；重新进入视口时直接同步事实状态，不补播全部历史。
- 大型建筑按实际包围盒裁剪，不能仅以锚点判断。

### 8.3 性能预算

- 目标：中端横屏设备 50–60 FPS；单帧动画解析 ≤ 2 ms，场景同步 ≤ 4 ms，渲染提交 ≤ 10 ms。
- 同屏动画精灵建议 ≤ 450，粒子建议 ≤ 1,200，独立滤镜 ≤ 8。
- 每 10 Tick 执行一次远景实体 LOD 评估，近景每帧仅更新可见动作。
- 图集按岛屿与功能区按需加载；进入新岛前预取，离开后保留最近使用集合，不一次载入 28×9 全量建筑资源。

## 9. 验收录像脚本

所有录像固定 1920×1080、60 fps、横屏全屏，关闭调试 UI；另保存一份带状态叠层的同镜头录像。状态叠层显示 Tick、实体 ID、建筑状态、生产进度、订单 ID、路径和当前动画槽位。

### 9.1 R01 状态真实性（90 秒）

1. 选择布坊，展示有工人、有原料时纺线、染色、晾布按进度发生。
2. 移除原料，确认在一个模拟周期内进入阻塞，生产动作和新增粒子停止。
3. 恢复原料，物流订单创建，搬运者装货、沿路移动、卸货后恢复生产。
4. 暂停 5 秒、切换 2×和 4×，确认逻辑与动作同步。

通过标准：每个可见动作均能在叠层中找到对应状态或订单；无无状态漂移。

### 9.2 R02 人物八方向与寻路（60 秒）

1. 使用包含直线、连续转角和桥梁的闭合测试路。
2. 记录居民空手、轻货、重货、推车四种移动。
3. 中途拆断道路，验证停止、受阻和重新寻路。

通过标准：八方向齐全，脚底无明显滑移，不穿模，不在路径失效后继续前进。

### 9.3 R03 建筑身份蒙测（每类 20 秒）

对 28 类建筑分别录制：待机 4 秒、核心工序 8 秒、物流/服务 4 秒、暮色 4 秒。隐藏名称和 UI，由三名评审仅凭轮廓与动画判断功能。

通过标准：主要功能类别识别率 100%，具体建筑识别率 ≥ 85%；不得把农业、桥梁、盐场、灯塔识别成通用亭阁。

### 9.4 R04 0–8 级施工成长（每类 45 秒）

以相同镜头、相同昼间天气，逐级展示施工开始、材料搬入、结构形成、完工和入驻。最后定格 0 级与 8 级分屏。

通过标准：每一级都有主体或附属结构变化及活动变化；8 级正常运行且不保留废墟观感。

### 9.5 R05 物流与船运因果链（90 秒）

1. 记录稻田收割、粮袋装车、沿路运输、粮仓卸货。
2. 记录渔船离港、下网、收网、返港、卸鱼。
3. 删除对应订单，确认车辆/船只不再凭空运行。

通过标准：货物不瞬移，附件与资源一致，船只只在任务存在时航行。

### 9.6 R06 昼暮天气（75 秒）

以固定机位展示晨→昼→暮、晴→微风→细雨→薄雾。画面同时包含民居、窑、树、河面、灯塔与行人。

通过标准：光照连续、风向统一、雨具合理、室内不下雨、暮灯与建筑状态一致。

### 9.7 R07 LOD 与压力（120 秒）

载入 500 户、300 栋建筑、150 个可见移动实体的基准城市，从 LOD3 平滑缩放到 LOD0，再横向拖拽全城。

通过标准：LOD 无明显闪烁，实体重新入镜时状态正确；中端目标设备 P95 帧时 ≤ 20 ms，无持续内存增长。

### 9.8 R08 音画与拾取（45 秒）

展示近景生产声、远景聚合、暮色环境、材料拾取成功与库存失败回弹。

通过标准：声音不抢占音乐，关键帧同步误差 ≤ 80 ms，失败时不播放成功入库反馈。

## 10. 交付与审计清单

每个动画子任务必须交付：

- 可导入图集、源文件和 `animation-manifest.json`；
- 状态映射表及适用的建筑等级；
- LOD0–LOD3 替代方案；
- 透明背景单动作预览和游戏内录像；
- 帧率、尺寸、锚点、附件点、关键帧音效标记；
- 性能数据与对象池复用验证；
- “状态取消、路径中断、暂停、离屏回归”四类异常录像。

动画审计必须逐项拒绝：

- 无模拟状态仍移动的居民、车辆或船；
- 停工仍冒出生产粒子或成品；
- 货物在运输完成前出现在目标库存表现；
- 不同建筑复用同一通用生产动画；
- 只用发光、上下漂浮、整体缩放表达工作；
- 施工用遮罩瞬间换皮；
- 农田、桥梁、盐场、灯塔等被通用楼阁或船只装饰替代；
- LOD 降级导致事实状态改变；
- 暂停后事实动画仍继续推进。

只有 R01–R08 全部通过，且 28 类建筑完成蒙测与逐级录像，动画系统才可进入最终视觉验收。
