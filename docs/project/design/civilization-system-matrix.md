## 1. 结论先行

当前项目已经不是“零系统”的展示原型：公共契约里有家庭、建筑、道路、生产、库存、物流、服务、财政、世界掉落和音乐稀缺奖励的基础状态；经济代码已经实现了生产输入/输出、库存容量、道路寻路物流、服务供给、税收与维护费的最小机制，并有测试覆盖部分失败路径。

但这离商业级文明模拟仍有明显距离。最大问题不是“缺几个字段”，而是缺少能让城市长期自洽运行的系统闭环：

1. 人口没有完整生命周期：迁入、就业分配、通勤、收入、消费、迁出没有形成可验证链路。
2. 住宅只是容量和家庭挂点，还不是会受服务、道路、收入、繁荣影响的城市细胞。
3. 市场目前更接近食物服务建筑，不是价格、货源、需求、消费和缺货后果的经济中心。
4. 道路有连通寻路，但没有容量、拥堵、道路等级、服务半径、物流优先级和可视化压力。
5. 财政只有税收与维护费结算，缺建设成本、预算压力、赤字后果、政策调节和长期平衡。
6. 繁荣/文明阶段、建筑升级、街区演化和主题岛解锁尚未进入运行时闭环。
7. 普通材料掉落和音乐奖励已有契约目标，但需要被明确纳入城市运行和升级消耗，避免成为外置奖励按钮。

所以，下一步不应直接铺 28 类建筑或做完整美术量产。正确路线是先把 P0 灰盒因果链补齐，再扩展 P1 长期平衡，最后进入 P2 商业级密度和内容规模。否则会得到一个画面更丰富、但内部仍空心的城市。

## 3. P0/P1/P2 三阶段实现顺序

这里的 P0/P1/P2 是文明系统落地优先级，不等同于项目总流水线的 P0–P6。原则是先做“最小真实闭环”，再做“长期平衡”，最后做“商业级规模和表现”。

### P0：最小真实城市闭环

目标：让住宅、家庭、就业、道路、生产、仓储、市场、服务、财政至少形成一条可运行、可测试、可观察的闭环。

必须完成：

1. 家庭迁入/迁出最小规则：住宅容量、满意度、就业机会和服务可达性共同决定迁入；长期低满意触发迁出。
2. 就业分配和通勤：家庭产生 worker，按道路可达分配岗位；断路或岗位不足导致缺工。
3. 生产—仓储—物流闭环：保留现有生产/库存/物流机制，补齐建筑等级对容量和产能的影响。
4. 市场真实消费：家庭到市场购买 food/goods，市场扣库存，家庭需求恢复，商户/家庭收入和税收可追溯。
5. 服务覆盖最小扩展：医疗、教育、娱乐沿用现有规则，但加入覆盖质量、容量和长期满意影响。
6. 财政建设成本：建造、升级、道路至少要扣 treasury；资金不足必须阻止或延迟动作。
7. 地图可观察提示：缺工、缺料、断路、缺货、仓满、服务不足必须能在建筑或道路上看见。

P0 不做：

- 不做完整 28 类建筑数值表。
- 不做复杂价格市场和多阶层家庭。
- 不做高级拥堵模型。
- 不做四岛完整解锁。

P0 通过门禁：

- 住宅—就业—生产—仓储—市场/服务—财政可连续运行 60 分钟，无资源复制/丢失/死锁。
- 玩家不打开复杂调试面板，也能从地图看出至少三类失败原因。
- 断路、缺工、缺料、缺货、仓满、服务不足均有自动化测试。

### P1：长期成长和平衡

目标：把 P0 闭环扩展为可持续经营，而不是一次性演示。

必须完成：

1. 繁荣/文明阶段：定义街区繁荣分、城市阶段和建筑/道路/服务解锁条件。
2. 建筑 0–8 级系统规则：每级至少改变容量、产能、服务、维护费、外观密度或岗位之一。
3. 财政压力：税率影响满意和迁入；维护不足导致效率下降或服务降级；赤字有明确但轻压力的后果。
4. 道路等级和基础拥堵：道路等级影响速度/容量/维护；物流和通勤在高压路段变慢。
5. 仓储优先级和区域配送：支持资源白名单、优先仓库、溢出/损耗策略。
6. 普通材料掉落：接入城市运行来源、拾取上限、队列和升级消耗。
7. 音乐稀缺奖励：实现事件去重、每日上限、保底、稀缺资源库存和非阻塞消耗点。

P1 不做：

- 不追求全量正式美术。
- 不把价格经济做成硬核金融模拟。
- 不引入灾难式失败或强惩罚。

P1 通过门禁：

- 8 模拟小时无订单无限堆积、人口无限增长、财政爆炸或满意度锁死。
- 阶段升级不能靠单一刷资源完成，必须依赖人口、服务、产业、财政和材料的组合条件。
- 音乐奖励关闭时基础城市仍可成长，只是稀缺外观/蓝图/加速变慢。

### P2：商业级规模、密度和可运营内容

目标：把系统扩展到商业级首发规模，支撑 500 户家庭、300 栋建筑、150 个可见移动实体和 28 类建筑 0–8 级。

必须完成：

1. 28 类建筑系统表：每类明确岗位、容量、配方、服务、维护、升级成本、动画状态和失败表现。
2. 四岛文明阶段：每岛有不同产业/服务/道路/材料主题，但共享统一系统契约。
3. 高密度可观察表现：人物、车船、市场、服务、施工、仓储、掉落和音乐反馈全部由模拟状态驱动。
4. 长稳与性能门禁：压力场景平均帧率、内存、订单数量、掉落数量、事件队列均有硬阈值。
5. 内容与工具链：系统表、资产 manifest、升级规则和测试数据必须自动校验，不能靠人工同步。
6. 平衡与可运营：首日、三日、七日、长期目标的材料、税收、满意、升级和音乐稀缺奖励节奏可模拟。

P2 通过门禁：

- 500 户、300 建筑、150 可见移动实体压力测试满足项目性能目标。
- 28 类建筑隐藏名称仍能通过功能辨识测试，且每类失败状态可从地图读出。
- 关闭 UI 面板观察城市 5 分钟，能看到真实通勤、物流、消费、服务、施工和掉落事件，而不是循环装饰动画。

## 4. 当前项目离商业级还差什么

以下判断故意保守。合同类型或文档目标不等于实现完成。

### 4.1 系统深度不足

当前经济代码证明了几个“系统零件”存在：生产会消耗和产出，物流会沿路搬货，服务会影响需求，财政会结算税收维护费。但商业级城市模拟需要的是零件之间的长期闭环。现在家庭、就业、市场、住宅、财政和繁荣阶段之间还没有足够强的因果关系。

最危险的误判是把 `HouseholdState`、`BuildingDefinition.jobs`、`EconomyState` 这些字段当成已经完成系统。它们只是承载系统的容器，不能替代迁入、就业、通勤、消费、纳税、迁出和升级规则。

### 4.2 可观察表现还没有被系统完整驱动

目标文档要求“UI 只能解释世界，不能替代世界”。目前经济系统能输出部分状态原因，但还缺一套从事件/状态到地图表现的强绑定规范。没有这套绑定，后续很容易出现“面板上说缺工，地图上还在热闹营业”的伪模拟。

### 4.3 市场和财政过浅

市场现在本质是 food 服务点，不是经济系统核心。财政现在是周期性加减 treasury，不是城市规划约束。商业级经营游戏的压力来自空间、资源、人口和预算同时牵制；如果市场和财政不加深，游戏会变成“等资源—点升级”的轻放置。

### 4.4 繁荣阶段缺席会拖垮建筑升级

建筑有 0–8 级目标，但如果没有街区繁荣和文明阶段，升级就只能靠材料数值堆砌。那会直接削弱“活着的城市文明”支柱：玩家不会感觉城市在进化，只会感觉建筑在换皮。

### 4.5 音乐奖励边界必须守住

项目定位已经明确：音乐只能给稀缺材料、蓝图或轻量加速，不能阻塞基础进度。后续如果为了留存把音乐奖励做成体力或主线门槛，会破坏产品支柱，也会让城市模拟沦为奖励包装。

## 5. 建议的近期任务拆分

建议下一轮不要泛泛说“完善文明系统”，而是拆成可验收任务：

1. `POP-JOBS-01`：实现家庭迁入、就业分配、通勤失败和收入回流。
2. `MARKET-01`：把市场从 food service 扩展为真实消费建筑，接入 household goods/food 需求和税收。
3. `HOUSING-01`：住宅容量、入住、空置、拥挤、升级和满意度影响。
4. `FISCAL-01`：建设/升级/道路成本、资金不足阻断、税率满意惩罚。
5. `PROSPERITY-01`：定义街区繁荣分、文明阶段和首批解锁条件。
6. `OBS-CAUSE-01`：建立状态原因到地图表现的统一映射表和测试夹具。
7. `DROPS-MUSIC-01`：普通材料掉落与音乐稀缺奖励的概率、上限、保底、消耗边界。

这些任务完成前，不建议宣称项目进入商业级内容量产。可以继续做金标资产样例，但只能作为垂直切片验证，不能替代系统闭环。
