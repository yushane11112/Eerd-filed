# 《小耳岛》2.5D 等距城市建模生产体系

版本：1.0  
任务：MODEL-DESIGN-01  
适用范围：建筑、道路、桥梁、地形构件、人物、车辆、船只、生产机械及可动画场景物件  
制作工具：Blender 4.x LTS  
运行目标：PixiJS 分层 2.5D 等距场景  
关联规范：`visual-system.md`、`animation-system.md`

## 1. 目标与生产原则

本规范定义从概念设计、白模、高低模、材质、绑定准备、批量渲染到引擎数据交付的完整生产流水线。最终资产必须服务真实城市模拟：建筑的生产、物流、营业、停工、施工与升级状态均可由引擎独立驱动，不得将整座城市烘焙成不可交互的单张图片。

不可妥协原则：

1. **统一世界尺度**：全部资产使用同一 Blender 单位、等距网格、相机和光照模板。
2. **功能先于装饰**：建筑轮廓、入口、生产院落和动画机械必须首先表达用途。
3. **模块化但不同质化**：共享结构构件和材质体系，不共享终局剪影与功能布局。
4. **逐级真实成长**：0–8 级为非破坏式结构演进，不是九张无关系皮肤，也不是简单叠加装饰。
5. **模拟与表现一致**：门、货位、岗位、烟囱、机械、船位和服务点均提供引擎锚点。
6. **可批量复现**：所有正式序列由固定模板和脚本渲染，禁止人工移动相机后逐张导出。
7. **可审计交付**：每个阶段必须通过自动检查与人工门禁，未通过不得进入下一阶段。

## 2. 世界单位、网格与等距相机

### 2.1 统一单位

- Blender 单位制使用 `Metric`，`Unit Scale = 1.0`。
- `1 BU = 1 m`。
- 一个逻辑地块为 `6 m × 6 m`，运行时对应 `96 × 48 px` 的 2:1 等距菱形。
- 半格模数为 `3 m`，仅供院墙、廊道、岸线、田埂、盐池、栈桥和装饰分区使用。
- 标准成人模型身高为 `1.68 m`；门净高为 `2.2–2.5 m`；普通单层檐口为 `3.6–4.5 m`。
- 水位固定为世界 `Z = 0 m`；陆地标准地坪为 `Z = 0.35 m`。
- 建筑原点设在入口侧前缘中央地块的地面接触点，原点 `Z` 必须等于地坪。
- 正式导出前所有对象必须应用 Scale；Rotation 仅对明确需要运行时旋转的部件保留。

### 2.2 占地模数

| 模数 | 建议占地 | 典型资产 |
| --- | --- | --- |
| XS | 1×1 | 小摊、井、树、材料堆、灯笼架 |
| S | 2×2 | 药铺、小民居、值守房 |
| M | 3×2 / 3×3 | 茶楼、食肆、作坊、仓库 |
| L | 4×3 / 4×4 | 客栈、书院、戏台、农场 |
| XL | 5×4 以上 | 盐场、船坊、完整产业院 |
| Linear | 4×1 以上 | 桥梁、镇门、堤岸、连续长廊 |

- Footprint 必须由整数格组成；视觉外挑檐可超出占地，但不得侵入相邻建筑的行走空间。
- 建筑入口落在 footprint 边缘格中心，并至少保留 `1.2 m` 净宽。
- 作坊、仓储和港口必须预留装卸交互点，不得只保留人物入口。
- 农田、果园、茶园、药圃和盐场以生产地貌为主体，房屋不得占视觉面积 25% 以上。

### 2.3 相机模板

- 使用正交相机，不使用透视相机。
- 世界轴投影必须形成固定 2:1 等距关系，屏幕斜线约为 `±26.565°`。
- 标准模板相机旋转：
  - `Z = 45°`
  - `X = 60°`
  - `Y = 0°`
- 若 Blender 欧拉轴定义导致朝向相反，只允许整体增加 `180° Z`，不得调整俯角。
- 正交缩放由资产占地脚本计算，不能逐资产手调。
- 默认朝向导出为南东可见面；需八方向的车辆、船只和人物按统一方向表渲染。
- 所有资产共用相机数据块 `CAM_ISO_MASTER`，正式文件内不得复制并修改相机。

### 2.4 渲染方向

方向编号固定如下：

| 编号 | 世界方向 | 资源后缀 |
| ---: | --- | --- |
| 0 | 北 | `N` |
| 1 | 东北 | `NE` |
| 2 | 东 | `E` |
| 3 | 东南 | `SE` |
| 4 | 南 | `S` |
| 5 | 西南 | `SW` |
| 6 | 西 | `W` |
| 7 | 西北 | `NW` |

建筑默认只制作一个主朝向和一个可选镜像朝向；道路、桥梁、车辆、船只、人物与方向性机械按实际需求制作 4 或 8 向。带文字、单侧货物、单侧船桨及非对称结构不得运行时镜像。

### 3.2 集合结构

每个建筑 `.blend` 必须包含：

```text
COL_REF             概念图与比例参考，不渲染

COL_SHARED          跨等级共享主体
COL_ANIM            可动画拆件
COL_COLLISION       碰撞代理，不渲染
COL_ANCHOR          引擎锚点 Empty
COL_RENDER          灯光、接景和渲染辅助
```

等级集合使用链接集合与 Geometry Nodes/驱动器组织，不复制整栋建筑九次。任何等级都必须能通过一个自定义属性独立切换和渲染。


- 禁止 `Cube.001`、`final_final`、中文对象名和无意义缩写。
- 材质槽顺序在所有 LOD 与等级间保持一致。
- 重命名后自动检查脚本必须更新清单，不允许引擎清单保留失效对象名。

## 4. 模块化构件库

### 4.1 构件分类

统一构件库至少包括：

- 屋顶：硬山、悬山、歇山、茅草、木瓦、耐火窑顶、仓库长屋面。
- 墙体：白灰、青砖、夯土、木板、竹编及半开敞作坊墙。
- 木构：柱、梁、枋、檩、斗拱简化件、栏杆、格扇、板门。
- 院落：院墙、月门、地坪、排水沟、台阶、货坪、晒场。
- 水岸：石驳岸、木桩岸、下水阶、栈桥、桥墩、防浪墙。
- 生产：染缸、窑炉、水轮、磨盘、织机、木工台、盐池闸、船台。
- 生活：桌椅、竹筐、推车、晾晒架、灯笼、招牌、麻袋和货箱。

### 4.2 构件使用规则

- 模块连接面必须落在 `0.25 m` 网格，轴向尺寸优先为 `0.5 m` 的整数倍。
- 同一结构构件可以跨建筑复用，但比例、组合、院落组织和主识别体不能照搬。
- 任何单一屋顶模块不得在 28 类建筑中的 30% 以上作为主屋顶直接复用。
- 书院、戏台、镇门和山亭可使用更精细木构；普通民居、商铺不得滥用重檐和斗拱。
- 生产机械必须按真实功能建模，不能以“古风装饰”替代工序。
- 套件库每次升级必须保留语义版本；已发布资产不得因套件覆盖而产生无审计变化。

## 5. 建模生产流程

### 5.1 概念与指标卡

建模开始前，每类建筑必须冻结一张指标卡：

- footprint、入口方向、最高点、层数和院落开口。
- 主识别体、两个辅助识别物。
- 0、3、5、7 级主体阶段缩略图。
- 2、4、6、8 级环境密度和活动阶段。
- 生产输入、输出、岗位、服务与动画槽位。
- 禁用轮廓与不可出现的装饰。
- 25% 缩略图识别目标及相邻建筑对比图。

没有批准的指标卡不得进入白模。

### 5.2 白模

- 只使用灰度材质，以体块、占地、入口、遮挡和天际线为目标。
- 必须同时评审单栋、2×2 街区、最高密度街区及四向道路接入。
- 在 25%、50%、100% 三种显示比例检查功能识别。
- 用标准人物、推车和货物代理验证尺度。
- 0–8 级白模必须一次性展示，防止只精修终局而忽略成长逻辑。
- 白模阶段不得投入瓦片、窗格、雕花等细节。

### 5.3 高模

高模仅用于确实影响法线、轮廓或材质烘焙的结构：

- 屋脊、瓦当、石块破损、木构倒角、雕刻、生产机械和大型工具。
- 不制作逐片屋瓦高模；使用屋面大形、关键瓦口和材质法线组合。
- 不制作不可见背面细节和相机永远看不到的室内。
- 主体硬边倒角按真实尺度控制，避免塑料玩具感。
- 高模命名与低模一一对应，以 `_high` 后缀标识。

### 5.4 低模

- 优先维护轮廓、檐口、门窗深度和生产机械可读性。
- 不可见底面、重复内部面和被永久遮挡面应删除。
- 曲线段数按最终像素贡献决定；小于 1 px 的几何起伏改用贴图。
- 屋面、墙体、院落和可动画部件拆分，禁止整栋单网格阻碍状态切换。
- 所有可开关、旋转、摆动、装卸或替换的部件必须独立对象。
- 法线统一朝外，使用 Auto Smooth/自定义法线；禁止依赖负缩放镜像。

### 5.5 白模、高模、低模交付关系

| 阶段 | 用途 | 是否进引擎 | 必须保留 |
| --- | --- | --- | --- |
| Blockout | 轮廓、尺度、等级成长 | 否 | 是 |
| High | 烘焙与关键表现 | 否 | 是 |
| Low | 正式渲染与动画 | 是，转序列帧 | 是 |
| Collision | 占地、点击与遮挡 | 是，数据 | 是 |
| Proxy | 远景、性能测试 | 可选 | 是 |

## 6. UV、材质与纹理通道

### 6.1 UV 规则

- 正式低模必须使用唯一 UV；重复瓦面、墙面和木构可使用第二套平铺 UV。
- UV0：唯一烘焙、AO、污渍和特殊标记。
- UV1：可平铺基础材质与统一笔触。
- UV 岛之间至少保留 8 px 间距（以 2048 纹理计）。
- 屋面、墙体、木构、地坪和生产物件按材质族统一 texel density。
- 需要逐级替换的招牌、布幅和货物不得与主体不可逆合图。
- 带方向文字和图案的 UV 禁止镜像。

### 6.2 纹理密度

| 资产级别 | 建议密度 | 最大单套纹理 |
| --- | ---: | ---: |
| 小道具 | 256 px/m | 512² |
| 普通建筑 | 256–384 px/m | 2048² |
| 地标建筑 | 384 px/m | 4096² 源文件，运行输出需拆分 |
| 人物/车辆/船只 | 512 px/m 关键区 | 2048² |

最终以屏幕可读性为准，不允许为了高模指标制造运行时不可见细节。

### 6.3 材质通道

Blender 源材质采用受控 PBR，批量渲染后输出为预乘 Alpha 序列。最低通道要求：

- Base Color：受统一东方设色色板约束。
- Roughness：区分湿石、木、瓦、布、金属和水迹。
- Normal：只保留中频结构，不添加颗粒噪声。
- Ambient Occlusion：用于构件接触关系，强度不得压黑墙面。
- Emission：灯笼、窑火、窗光和灯塔灯室独立通道。
- Material ID：屋顶、墙、木、石、布、金属、植被、地面。
- Shadow Catcher/Contact：独立输出接地阴影，供引擎按昼暮调整。

禁止：

- 扫描照片直接平铺。
- 大面积程序噪声、颗粒或锐化。
- 纯黑 AO、纯白高光和高饱和金属。
- 将动态灯火烘死在白天主体贴图中。

## 7. 屋顶、墙体与院落专项规范

### 7.1 屋顶

- 屋脊线必须沿世界轴，坡度在同类建筑中保持一致。
- 普通建筑屋顶以硬山/悬山为主，飞檐仅给公共地标。
- 瓦面由整体块面、前两排瓦口和关键脊饰组成，不逐片复制。
- 破损等级使用可替换瓦片组、缺口和临时覆盖物，不能用随机噪点表达。
- 屋顶升级需改变跨度、进深、层级或翼楼关系，而非只换颜色。

### 7.2 墙体

- 墙厚具有真实体积，门窗开洞不能贴平面假装。
- 墙脚、排水和台基按潮湿水乡环境建模。
- 白墙面积保持干净，污渍集中在墙脚、檐下和排水附近。
- 0–2 级可见修补痕迹；5 级以后应从“修复”转向“完整经营”，8 级不得仍满墙裂缝。

### 7.3 院落

- 院落是功能空间，不是填空装饰。
- 作坊院落必须呈现输入、加工、暂存和输出流线。
- 商业院落必须呈现迎客、排队、座位或后勤关系。
- 住宅院落呈现生活、晾晒和儿童活动，不出现工业货堆。
- 高等级通过附属空间、道路接驳和活动密度提升，不以塞满亭子解决空地。

## 8. 0–8 级非破坏式升级体系

### 8.1 等级结构

| 等级 | 建模目标 | 主要变化 |
| ---: | --- | --- |
| 0 | 遗址/荒地 | 地基、残件、功能线索，保留未来占地可读性 |
| 1 | 基础恢复 | 核心功能体首次可运行 |
| 2 | 运转稳定 | 增加必要院落、入口和基础道具 |
| 3 | 主体扩建 | 更换或扩展主要体量和屋面 |
| 4 | 流程完善 | 增加生产/服务附属区及道路关系 |
| 5 | 街区成形 | 主体与翼楼、围合或产业院形成完整组织 |
| 6 | 高密运营 | 增加货位、摊位、员工区和环境活动 |
| 7 | 地标终型 | 形成独有终局剪影和完整功能容量 |
| 8 | 繁华状态 | 完善周边、灯火、人流、库存与专属动画槽位 |

### 8.2 非破坏式实现

- 共享部分位于 `COL_SHARED`，等级变化由集合可见性和部件替换控制。
- 不允许每级复制全部网格后独立修改，避免修复无法同步。
- 主体结构阶段为 L1/L3/L5/L7；环境功能阶段为 L2/L4/L6/L8。
- 每一级至少改变一项结构或一项可运行环境；任何“只加一盏灯”的等级不合格。
- 升级中需保留旧级可见部件列表、新增部件列表和移除部件列表，供施工动画按阶段切换。
- 8 级资产必须仍遵守 footprint、入口和道路连接，不能因扩建覆盖通行节点。
- Level manifest 必须声明：
  - 主体集合。
  - 可动画部件。
  - 锚点。
  - 碰撞。
  - 接地范围。
  - 前后景分层。
  - 施工揭示顺序。

## 9. 动画拆件、Pivot 与绑定准备

### 9.1 建筑拆件

以下对象必须独立：

- 门、窗、帘、旗、招牌、灯笼。
- 水轮、磨盘、绞盘、吊杆、船台和窑门。
- 烟囱、炉口、排水口对应的特效发射点。
- 原料、在制品、成品和货位显示组。
- 脚手架、施工材料、落瓦与挂牌部件。
- 前景遮挡、主体和后景层。

### 9.2 Pivot 规则

- 门轴位于真实铰链。
- 水轮、车轮、磨盘位于旋转轴中心。
- 吊杆位于支承转轴，吊钩为独立骨骼或对象。
- 旗帜和布幅位于固定边。
- 船只原点位于水线中心、纵向质心附近。
- 人物原点位于双脚地面投影中心。
- 所有 pivot 朝向采用统一右手坐标，禁止依赖父级负缩放纠正。

### 9.3 人物绑定准备

- 首版人物最终以八方向序列帧为主，但源模型必须可复用绑定。
- 标准骨架至少包含 root、pelvis、spine、head、arms、hands、legs、feet。
- 工具、背篓、扁担、货物和伞使用附件骨或 socket。
- 服装不得与身体不可逆合并；至少支持体型、服装、头发和职业附件替换。
- 关节拓扑优先满足行走、负重、弯腰、坐、划船和工具动作。
- 绑定前模型面向世界 `-Y`，Apply Transform，root 位于地面原点。

### 9.4 车辆与船只准备

- 车辆将车身、车轮、车辕、货物分离；轮半径与移动速度可计算匹配。
- 船只将船体、桅杆、帆、桨、舵、货物、灯和水迹锚点分离。
- 船体需标记水线、船头、船尾、靠泊点和装卸点。
- 不同载重至少提供空载、半载、满载三种吃水或货物显示状态。
- 船坊在造船体不得复用可航行成船而不拆施工阶段。

## 10. LOD 与面数预算

虽然运行时以序列帧为主，LOD 仍用于源场景渲染性能、远景导出和后续实时 3D 扩展。

| 类别 | LOD0 三角面 | LOD1 | LOD2 | 说明 |
| --- | ---: | ---: | ---: | --- |
| XS 道具 | 1k–3k | 500–1.5k | 100–500 | 成组道具按组预算 |
| S 建筑 | 12k–25k | 6k–12k | 2k–5k | 不含重复植被 |
| M 建筑 | 25k–45k | 12k–22k | 4k–9k | 含功能院落 |
| L 建筑 | 45k–75k | 22k–38k | 8k–15k | 地标可申请例外 |
| XL 产业区 | 70k–110k | 35k–55k | 12k–22k | 分块渲染 |
| 人物 | 12k–22k | 6k–10k | 2k–4k | 含服装，不含附件 |
| 车辆 | 12k–30k | 6k–15k | 2k–6k | 轮与货物独立 |
| 船只 | 20k–50k | 10k–25k | 4k–10k | 大型船可单审 |

- 面数不是质量目标；轮廓、阴影和最终像素贡献优先。
- 单个不可见小道具不得超过 2k 三角面。
- 重复植被使用实例，不得实体复制。
- LOD 切换不得改变 footprint、入口、主要轮廓和动画轴心。
- 最终序列帧的 LOD 按相机缩放选择图集，不在运行时混用 3D 网格。

## 11. 批量渲染与透明序列

### 11.1 渲染模板

- 使用 Blender Eevee，固定色彩管理、正交相机和灯光组。
- 背景透明，输出 RGBA、预乘 Alpha。
- 主光方向固定，避免不同资产阴影互相矛盾。
- 接地阴影单独输出；建筑主体不得把整块地面烘进图片。
- 白天主体、暮色灯光、阴影、发光、前景遮挡和特效附件分层输出。
- 1× 逻辑像素输出用于运行时；2× 输出用于高 DPI 和美术归档。

### 11.2 序列规范

```text
{asset_id}_L{level}_{state}_{direction}_{frame:04d}.png
```

示例：

```text
main_kiln_L05_working_SE_0012.png
citizen_worker_walk_NE_0004.png
tide_ship_cargo_move_W_0007.png
```

- 同一片段所有帧画布尺寸、pivot、相机、光照完全一致。
- Trim 由图集工具执行，源序列不手工裁切。
- 建筑循环建议 8–24 帧；机械可用独立部件运行时旋转时，不重复渲染主体。
- 人物按动画规范输出 8 方向。
- 渲染脚本根据 manifest 自动切换等级、状态、方向、帧范围和输出层。
- 每次批量渲染生成校验报告、缩略表和 contact sheet。

### 11.3 引擎图集

- TexturePacker 兼容 JSON Hash。
- 推荐 2048² 图集；移动端禁止依赖单张 4096²。
- 建筑主体、人物、交通、环境特效分别打包。
- 保存 sourceSize、spriteSourceSize、pivot、duration 和 animation tag。
- 图集变更必须具备稳定资源键，禁止运行时依赖帧在图集中的物理顺序。

## 12. 引擎锚点、碰撞与资产清单

### 12.1 锚点类型

每栋建筑按功能提供：

- `origin`：建筑地面原点。
- `entrance`：居民入口，可多个。
- `worker`：岗位交互点。
- `input`：原料卸货点。
- `output`：成品装货点。
- `service`：顾客、学生、病人或观众交互点。
- `smoke/fire/water`：特效发射点。
- `vehicle/boat`：车辆或船只停靠点。
- `audio`：主要空间音源。
- `ui`：状态提示锚点。
- `construction`：施工人员、材料和脚手架节点。

锚点使用 Empty，朝向轴必须有效；只提供位置而无方向的装卸点不合格。

### 12.2 碰撞数据

- `footprint`：占地格集合，决定建造合法性。
- `obstacle`：不可行走区域，可由多个凸多边形组成。
- `occluder`：前景遮挡区域，用于人物淡出或分层。
- `clickHull`：选择区域，应覆盖主体但不吞噬相邻道路。
- `waterHull`：港口与船只水域关系。
- `heightClass`：低、中、高、地标，用于裁剪边距。

碰撞代理必须低复杂度，不得直接使用渲染网格。引擎数据导出为 JSON，坐标由脚本从 Blender 世界单位转换为逻辑格和局部像素。

### 12.3 Manifest 最低字段

```ts
interface ModelAssetManifest {
  assetId: string
  version: string
  footprint: Array<{ x: number; y: number }>
  origin: { x: number; y: number; z: number }
  levels: Record<number, {
    spriteLayers: string[]
    animationSlots: string[]
    anchors: string[]
    collisionProfile: string
    constructionReveal: string[]
  }>
  bounds: { width: number; height: number; top: number }
  lod: string[]
  sourceBlend: string
}
```

## 13. 自动检查脚本

项目必须提供 Blender Python 检查器，并在批量渲染前强制执行。至少检查：

- Blender 版本、单位制、相机模板和渲染配置。
- 对象、集合、材质和骨架命名。
- 未应用 Scale、负缩放、非流形、重复面、反向法线和孤立顶点。
- 原点、pivot、世界朝向及地面高度。
- Footprint 越界、入口未落边、锚点缺失或重复。
- 材质槽顺序、缺失纹理、绝对路径和超规格纹理。
- UV 越界、重叠异常、密度偏差和过小间距。
- LOD 缺失、三角面超预算和轮廓偏差。
- L0–L8 集合齐全、每级变化量、共享对象错误复制。
- 动画帧范围、循环首尾跳变、骨架缺失和附件 socket。
- 不可渲染对象误入、参考图误启用、隐藏物体残留。
- 输出文件名、Alpha 边缘、画布、pivot 和 manifest 一致性。

脚本输出：

- 机器可读 JSON。
- 人工可读 HTML/Markdown 报告。
- 错误、警告、资产统计和门禁结论。
- 失败项对应 Blender 对象名和修复建议。

任何 Error 阻断渲染；Warning 超过批准阈值阻断提交。人工不得通过修改报告文件绕过检查。

## 14. 28 类建筑核心模型轮廓

以下为硬性建模输入。每类必须维持独立主体、院落组织和天际线；“高等级统一加亭、船、重檐、塔楼”视为不合格。

| 建筑 | 核心模型轮廓 | 关键拆件/空间 | 禁止同质化规则 |
| --- | --- | --- | --- |
| 旧码头 | 多指状木石泊位向水面展开 | 吊杆、货棚、系缆柱、货位 | 不做成单亭栈桥；主体必须是货运埠 |
| 青石渡口 | 宽下水石阶连接低矮候船院 | 雨棚、票牌、靠泊点 | 不复制码头吊装区；强调人流而非货堆 |
| 听雨桥 | 单体宽拱跨水，桥面连续 | 桥栏、桥阶、桥头摊位 | 不变成亭桥楼阁群；桥拱必须是主体 |
| 临水客栈 | 两层客房翼楼围合迎客院 | 客房窗、前厅、晾被院 | 不复制茶楼露台；强调住宿房间节奏 |
| 半日茶楼 | 开敞二层楼与临河阶梯露台 | 茶灶、说书角、茶旗 | 不做客栈封闭翼楼；不加无关船坞 |
| 小满食肆 | 前堂低檐、后厨高烟口 | 灶间、蒸笼、外摆棚 | 不复制茶楼二层主体；以厨房流线识别 |
| 云锦布坊 | 横向长晾架与染织院 | 染缸、织机、排水沟、布幅 | 不用通用作坊棚替代；布架必须主导剪影 |
| 榫卯木作 | 大跨度敞口装配棚 | 原木架、锯台、半成木构 | 不出现染缸式院落；突出梁架和长木料 |
| 青瓦瓷窑 | 低长龙窑或厚重馒头窑 | 窑门、烟囱、泥坯架、柴垛 | 不做普通带烟囱房；窑体必须可辨 |
| 丰年粮仓 | 架空长仓、重复仓门和高粮囤 | 晒场、麻袋台、装卸口 | 不做民居组团；保持低长、防潮轮廓 |
| 草木药铺 | 紧凑前铺与细密晒药后院 | 药柜、药碾、晒架 | 不复制食肆外摆；道具尺度更细密克制 |
| 溪山书院 | 中轴讲堂、两侧书斋与静院 | 月门、碑刻、藏书楼 | 不做宫殿；院落秩序强于华丽屋顶 |
| 水上戏台 | 高台口面向观演广场 | 前台、后台、鼓架、帷幕 | 不做茶楼；舞台开口和观演轴线不可缺 |

| 临水花园 | 曲水、叠石、游廊构成低平景观 | 花窗、荷池、曲桥 | 不以大亭为中心；水院与植物才是主体 |
| 层层稻田 | 连续梯田面和灌溉高差 | 田埂、水渠、田舍 | 不做房屋型资产；田舍不得抢占轮廓 |
| 四时果园 | 成行树冠形成块面，路径穿插 | 分拣棚、果梯、蜂箱 | 不复制茶园条带；树阵和采摘节点为核心 |

| 山野药圃 | 多形态分区药畦和育苗棚 | 标签架、晾根架、药篓 | 不做整齐单作物农田；分区生态必须多样 |
| 听风竹坊 | 竖向竹林与横向剖竹长棚对比 | 竹材堆、编织架、成品院 | 不复制木作原木场；突出竹长杆和编织工序 |
| 云岫山亭 | 山脊单亭与顺坡观景平台 | 石阶、望栏、题刻 | 不扩成书院或宫殿群；亭体保持单一克制 |
| 潮生渔港 | 多泊位低矮鱼棚与晒网架 | 卸鱼台、鱼市、修网区 | 不复制货运码头吊杆体系；突出鱼货和网具 |
| 白浪盐场 | 大尺度规则盐池网格 | 闸门、卤水渠、盐堆、盐仓 | 不以房屋为主体；不得添加装饰船制造繁华 |
| 远航船坊 | 长船台包围逐步成形的船体 | 龙骨、脚手架、吊装架、下水坡 | 不做普通码头；在造船体与施工轴线必须主导 |
| 归潮灯塔 | 单一竖向高塔立于礁岸 | 灯室、守塔屋、防浪墙 | 不形成亭阁群或城堡；不得在塔脚停泊装饰船 |

### 14.1 全局防同质化指标

- 28 类 L7 白模正视剪影两两重合率不得超过 70%。
- 每类主识别体在 25% 缩略图中必须可辨。
- 相邻建筑的最高点位置、主轴方向、屋面数量和院落开口至少三项不同。
- 亭、塔、船、重檐和拱桥只能出现在功能合理类别。
- 任何五栋连续建筑不得使用完全相同的主体屋顶组合。
- 8 级繁华由真实功能密度和活动表达，不由无意义装饰堆叠表达。

## 15. 阶段评审门禁

### G0：指标卡冻结

- 建筑用途、占地、主识别体、升级路径和动画槽位完整。
- 通过视觉、模拟、动画和建模负责人联合评审。

### G1：白模门禁

- 0–8 级白模、人物比例、道路接入和街区组合通过。
- 25% 缩略图可辨，28 类无明显同质化。
- 自动检查无单位、原点、命名和 footprint 错误。

### G2：结构低模门禁

- 模块拓扑、入口、院落、生产流线和动画拆件完成。
- 无非流形、负缩放、错误 pivot 和不可解释超面数。

### G3：高模与烘焙门禁

- 关键轮廓与材质细节有效，烘焙无穿帮、黑边和法线错误。
- 不可见细节、过度瓦片和程序噪声已清理。

### G4：材质与灯光门禁

- 与视觉色板一致，白天和暮色分层正确。
- 在街区中无资产色温漂移、塑料感或颗粒噪声。

### G5：绑定与动画准备门禁

- 所有拆件、pivot、骨架、socket、锚点和状态槽位齐全。
- 生产、物流、施工、停工状态均能独立切换。

### G6：批量渲染门禁

- 自动脚本全绿；所有帧画布、锚点、Alpha 和命名一致。
- Contact sheet、循环预览和 8 方向预览通过。

### G7：引擎集成门禁

- Footprint、点击、遮挡、入口、装卸、特效和 UI 锚点一致。
- 建筑升级不跳位，人物不穿墙，运输单位准确停靠。
- 低、中、高缩放下均保持清晰和正确裁剪。

### G8：城市级终验

- 单栋、街区、全城三级画面通过。
- L0 到 L8 呈现从遗址到繁华文明的连续成长。
- 28 类隐藏名称后仍可辨认，无亭子化、船只滥用和空地填塞。
- 动画全部能追溯到模拟状态，性能达到项目预算。

任何门禁失败必须回到对应生产阶段修复；禁止在图集或引擎端用临时缩放、位移、遮罩掩盖源资产错误。

## 16. 交付清单

每个正式资产包必须包含：

- 批准的指标卡和概念图。
- Blender 源文件及所用链接库版本。
- L0–L8 白模、低模与必要高模。
- UV、材质、纹理源文件。
- 动画拆件、骨架、附件和 pivot。
- 锚点、碰撞和 footprint 数据。
- 批量渲染脚本配置与透明序列。
- 图集、manifest 和资源版本。
- 自动检查报告。
- 单栋、街区、等级成长和运行状态评审图/录像。
- 已知限制、例外批准和后续修改记录。

资产只有在 G8 通过并进入统一 manifest 后才视为完成；仅提交概念图、整岛效果图、静态最高级图片或未绑定的模型均不构成游戏资产交付。
