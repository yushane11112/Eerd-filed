# 《小耳岛》原创东方水乡视觉系统

版本：1.0  
任务：ART-DESIGN-SYSTEM  
适用范围：场景、28 类建筑、人物、交通、环境动画、材料掉落与场景内 UI  
基准引擎：PixiJS 等距动态场景  

## 1. 设计目标

《小耳岛》的画面不是一张“江南风格插画”，而是一座能够被读懂、能够持续运转、能够从荒地成长为繁华城镇的动态微缩文明。

每个画面必须同时满足四个目标：

1. **功能可读**：隐藏名称后，玩家仍能凭轮廓、院落组织、道具和活动认出建筑用途。
2. **状态可信**：生产、停工、运输、营业、缺货和升级均由模拟状态驱动，不能无条件循环播放。
3. **成长完整**：0–8 级改变的不只是主体，而是地块、道路、院落、附属设施、人物密度和活动强度。
4. **东方原创**：吸收江南水乡的空间语言、工笔设色的克制轮廓和民间生活细节，不复制任何现有游戏的构图、建筑、人物、UI 或装饰组合。

关键词：温润、清透、细密、烟火、秩序、灵动。  
禁用关键词：仙侠、宫殿、景区古镇、通用亭阁、废土、战争、塑料模型、厚重油画、过度梦幻。

## 2. 世界尺度与等距透视

### 2.1 投影基准

- 使用固定 2:1 等距菱形网格。
- 逻辑地块基准为 `96 × 48 px`，对应当前 `tileWidth: 96`、`tileHeight: 48`。
- 单层标准建筑高度为 72–96 px；二层为 128–168 px；塔类最高可达 300 px。
- 所有资产使用正交等距投影，不允许出现广角透视、消失点收缩或不同建筑各自拥有不同俯视角。
- 屋脊、水岸、道路边缘必须沿两个世界轴方向绘制；斜线屏幕角度统一为约 `26.565°`。
- 垂直构件保持屏幕垂直，不向中心倾斜。
- 默认可见屋顶占建筑立面与屋顶总投影面积的 42%–55%；高塔可降至 32%–42%。

### 2.2 坐标与锚点

- 建筑原点位于 footprint 前侧中央地块的地面中心。
- Sprite 锚点为建筑入口侧最下方接地点，禁止以图片中心作为锚点。
- 建筑 footprint、入口、碰撞区域和美术底座必须一致；透明留白不得改变逻辑占地。
- 所有楼层、院墙、树木和附属设施均落在完整或半格模数上。
- 跨格物件仅允许桥梁、长廊、栈桥、晒场、盐池和连续田埂使用 1/2 格连接。
- 水面资产以水位线作为垂直基准；码头、船只和桥墩必须共享同一水位。

### 2.3 层级与遮挡

场景由后到前固定为：

1. 深水与浅水底色。
2. 水纹、岸边泡沫与水下细节。
3. 地形、田地和道路。
4. 地面装饰、低矮作物和材料掉落。
5. 建筑主体与桥梁。
6. 树冠、棚顶、船只和运输单位。
7. 居民与建筑活动部件。
8. 烟、蒸汽、落叶、灯光和天气特效。
9. 场景提示、选择描边和 UI 锚点。

深度排序使用地面接触点，而不是图片顶端。跨多个深度区间的大型建筑需拆为前景、主体、后景三个部件，防止人物穿过屋顶或被整张图片错误遮挡。

## 3. 建筑模数与空间构成

### 3.1 基础模数

| 模数 | 逻辑占地 | 典型用途 | 高度建议 |
| --- | --- | --- | --- |
| S | 2×2 | 小店、药铺、民居 | 90–150 px |
| M | 3×2 / 3×3 | 作坊、客栈、仓库、码头 | 130–210 px |
| L | 4×3 / 4×4 | 书院、戏台、园林、农场 | 160–250 px |
| XL | 5×4 及以上 | 盐场、完整产业院落 | 180–280 px |
| Linear | 4×1 及以上 | 桥、镇门、长堤 | 按功能确定 |

- 居住和商业建筑主体占 footprint 的 45%–62%。
- 作坊主体占 30%–48%，其余必须留给可读的生产院落。
- 农业、盐业和园林主体建筑不得超过地块 25%；生产地貌或景观才是主角。
- 港口水上占地应达到视觉面积 35%–60%。
- 最高级不是把主体铺满全地块；应形成“主体＋附属功能＋交通空间＋生活细节”的高密度组织。

### 3.2 建筑构件库

所有建筑从统一构件语言中组合，但不得共享相同终局轮廓。

- 墙体：白灰墙、夯土墙、青砖墙、木板墙、竹编墙。
- 屋面：小青瓦、板瓦、茅草、木瓦；生产建筑可使用局部耐火砖顶。
- 木构：深茶木柱、赭木梁、灰褐旧木；不可统一使用高饱和红柱。
- 门窗：格扇、支摘窗、板门、仓门、作坊敞口；按功能选择，不做随机拼贴。
- 基座：青石、河卵石、夯土、木桩、水上石墩。
- 附属：雨棚、晒架、货架、炉灶、辘轳、石槽、晾衣杆、推车、竹筐。

飞檐只用于书院、戏台、镇门、山亭等公共或标志建筑。民居和普通商铺使用克制的硬山或悬山屋顶。禁止所有 8 级建筑都出现重檐、塔楼、亭阁、拱桥和船。

### 3.3 建筑轮廓差异规则

- 28 类建筑的正面剪影两两重合面积不得超过 70%。
- 同一类别可共享材质，但必须至少在主轴方向、屋面数量、最高点位置和院落开口中的三项不同。
- 每栋建筑必须定义一个主识别体和两个辅助识别物。
- 主识别体在 25% 缩略图下仍应可辨。
- 辅助识别物不能只依赖颜色，应依靠形状或运动。
- 最高点不得全部位于建筑中心；连续街区应形成错落天际线。

### 4.1 建筑专属色彩

统一城镇色板之上，每类建筑只允许一个 8%–15% 面积的识别色：

- 港口：靛蓝绳结或深海青。
- 客栈：枣红织物。
- 茶楼：茶褐与黛绿。
- 食肆：暖赭与蒸笼竹色。
- 布坊：低饱和藕粉、靛青布幅。
- 木作：新木蜜褐。
- 瓷窑：窑火橙与瓷青。
- 药铺：草绿与药材黄褐。
- 书院：墨青。
- 戏台：胭脂红，仅用于帷幕与戏服。
- 农业：随作物生长周期变化，不以建筑色抢占地貌。
- 盐场：冷白和浅青灰。
- 灯塔：灰白塔身与暮色暖灯。

识别色不能铺满屋顶或墙体，避免每栋建筑像不同游戏的素材。

## 5. 人物与动物比例

### 5.1 人物尺度

- 成年人物站立高度为 34–40 px，约等于单格屏幕高度的 0.75。
- 儿童为成人的 70%–78%。
- 头部占身高 20%–23%，采用亲和但非大头 Q 版比例。
- 肩宽为身高 24%–29%；手臂和工具必须清楚但不夸张。
- 建筑单层檐口约为 2.2–2.7 个成人身高。
- 门高为 1.55–1.8 个成人身高，避免人物像巨人或建筑像玩具。

### 5.2 人群设计

- 基础体型至少 6 种：成人男、成人女、老人男、老人女、少年、儿童。
- 每种体型至少 4 个服装色组、3 个头饰或发型变体。
- 职业通过工具、围裙、背篓、肩担、袖套等识别，不依赖头顶图标。
- 常服使用靛青、灰绿、茶褐、米白、藕灰；高饱和颜色仅给戏服、节庆和小面积配件。
- 同屏重复人物的服装、发型和步态相位必须打散。

### 5.3 人物动画规格

基础动画：

- `idle`：4–6 帧，轻微呼吸或观察，1.6–2.4 秒。
- `walk`：8 帧，8–10 fps。
- `carry`：8 帧，步幅较小，负重有上下惯性。
- `work`：6–12 帧，按职业制作，不允许所有职业共享挥锤动作。
- `interact`：6–10 帧，用于购买、交付、入座、开门。
- `celebrate`：8 帧，仅在建成或事件成功时短暂播放。

动作必须以地面接触点稳定为先。脚底滑动超过 2 px、负重不随身体移动、工具穿过身体均判定不合格。

### 5.4 动物

- 鸡、鸭、猫、狗、麻雀、白鹭、牛和驴按区域出现。
- 动物不是随机装饰：鸭靠水、麻雀靠粮仓、白鹭靠田与浅水、驴靠运输节点。
- 每种动物至少有移动、停留和反应三种状态。
- 同屏动物不超过可见居民数量的 25%。

## 6. 线稿、材质与笔触

### 6.1 线稿

在 1× 资产分辨率下：

- 主体外轮廓：1.5–2.0 px，深灰褐 `#4A443B`，不使用纯黑。
- 建筑结构线：1.0–1.4 px，`#625B50`。
- 材质细线：0.6–0.9 px，透明度 45%–70%。
- 人物外轮廓：1.0–1.3 px。
- 远景和低对比物件：0.5–0.8 px。

线宽需要随深度与重要性变化，不能使用整张图统一的矢量描边。屋檐前缘、桥拱和大型机械轮廓可加重 10%–20%，墙面裂纹、瓦缝和木纹必须减弱。

### 6.2 笔触

- 墙体：大面积平涂＋3%–6% 明度起伏的干刷，不做随机噪点。
- 青瓦：以屋面块面为主，只刻画前两排瓦口和关键脊线；禁止逐片等距复制。
- 木材：沿木构方向绘制 2–4 条节制纹理，避免照片纹理贴图。
- 石材：边缘有少量缺口，内部纹理不超过面积 12%。
- 夯土：柔和色层与少量横向夯筑痕。
- 布料：使用大色块、折线和受风变形，避免无结构渐变。
- 植物：树冠先以 3–5 个大团块组织，再添加少量叶簇；禁止逐叶生成或均匀散点。

### 6.3 纹理频率

- 画面 70% 面积保持低频、干净、可呼吸。
- 20% 用于中频结构，如瓦口、窗格、田埂和货物。
- 10% 以内用于高频焦点，如招牌、工具、人物和生产活动。
- 同一建筑同时出现的独立纹理类型不超过 5 种。
- 禁止全屏纸张噪点、胶片颗粒、锐化边缘和统一旧化滤镜。

### 7.2 色彩约束

- 单栋建筑面积最大的三个颜色必须来自基础色板。
- 平均饱和度控制在 22%–48%，焦点小物可达到 58%–68%。
- 纯白、纯黑和荧光色禁用。
- 相邻建筑屋顶明度差控制在 4%–12%，形成街区统一但不粘连。
- 低等级更偏灰土和低对比；高等级通过清洁度、色彩层次、灯火与活动增加繁华感，不靠整体提高饱和度。
- UI 和场景共享颜色，但 UI 必须比其下方场景至少高 3:1 的局部对比度。

## 8. 晨、昼、暮光照

光照变化由统一场景色层、局部灯光和阴影参数完成，不为每个时段重画整套建筑。

| 时段 | 主光方向 | 色温 | 环境处理 | 阴影 |
| --- | --- | --- | --- | --- |
| 晨 | 屏幕左上至右下 | 暖黄 `#F3C985` | 低对比薄雾，远景偏青灰 | 长度 0.75×物高，透明度 18% |
| 昼 | 屏幕左上至右下 | 中性暖白 `#FFF0D2` | 色彩最清晰，水面反光增强 | 长度 0.38×物高，透明度 22% |
| 暮 | 屏幕右上至左下的暖侧光 | 橙粉 `#E89A72` | 天空与远景偏蓝灰，局部灯火开启 | 长度 0.85×物高，透明度 28% |

- 建筑固有明暗在资产中保留 65%，时段光照贡献 35%。
- 阴影颜色统一采用偏冷灰青，不使用纯黑。
- 接触阴影独立于投射阴影，始终保留 14%–22% 透明度，保证物体落地。
- 暮色灯火只出现在有人使用或正在营业的建筑。
- 灯光影响半径不超过 0.75 格，小范围照亮门口、窗沿或摊位；禁止全建筑发橙光。
- 雾不覆盖前景交互物；远景雾化按深度增加，最大不透明度 22%。

## 9. 水体系统

### 9.1 水体分层

水体至少由以下层组成：

1. 深浅水底色。
2. 低频流向纹理。
3. 岸边接触线和局部泡沫。
4. 船尾、水轮、落雨和投物产生的交互波纹。
5. 日光或暮光反射。

### 9.2 动画

- 主流纹理位移速度为 2–5 px/s，不做快速滚动。
- 大水面使用 8–14 秒的缓慢明暗循环，振幅不超过 6%。
- 岸边波纹每 2.5–5 秒随机出现，持续 1.2–2 秒。
- 船尾水迹仅在船移动时生成，停船后 1.5 秒内衰减。
- 水轮影响水面时产生连续但不规则的扇形扰动。
- 雨滴波纹使用对象池；高密度雨天降低单个波纹生命周期与透明度。

### 9.3 水岸规则

- 自然岸：泥、草、芦苇与河卵石，不使用整齐重复边线。
- 城镇岸：青石驳岸、排水口、石阶和系船点。
- 农业岸：田埂、水闸和狭窄灌渠。
- 海工岸：防浪石、盐池闸门、船台和耐候木桩。
- 同一连续岸线的高度、颜色和水位必须一致。

## 10. 道路与桥梁

### 10.1 道路等级

| 等级 | 路面 | 宽度 | 边缘 | 使用场景 |
| --- | --- | --- | --- | --- |
| 0 | 踩踏草径 | 0.35–0.5 格 | 不规则草边 | 遗址 |
| 1–2 | 夯土路 | 0.55–0.7 格 | 排水沟、木板过泥 | 初建 |
| 3–4 | 碎石与局部青石 | 0.7–0.85 格 | 路肩、路标 | 村镇 |
| 5–6 | 连续青石路 | 0.85–1 格 | 石沟、门前台阶 | 成熟 |
| 7–8 | 主街青石＋次巷混铺 | 主街 1–1.25 格 | 排水、树池、摊位区 | 繁华 |

- 道路必须真实连接建筑入口。
- 路面纹理以段落变化而非每格随机变化；每 4–8 格更换一次细节组合。
- 交叉口留出可读通行区，不放大型树、摊位或掉落物。
- 高级道路不是金边或发光，而是更完整、干净、排水良好并拥有生活设施。

### 10.2 桥梁

- 桥宽必须匹配道路宽度。
- 桥面坡度、拱高和人物步态一致。
- 桥下保持可通航净空；不可通航的小桥需由关卡或水道数据明确。
- 桥头摊位、牌坊和灯笼属于高等级附属层，不能遮挡桥体主轮廓。

## 11. 植被系统

### 11.1 植物层级

- 地被：草、苔、野花，低频分布。
- 灌木：2–3 个团块组成，不沿建筑均匀排一圈。
- 小乔木：果树、茶荫树、庭院树。
- 大乔木：柳、樟、竹簇，作为地标和分区边界。
- 生产植物：稻、茶、药草、果树，必须按生产逻辑排列。

### 11.2 树木造型

- 树冠使用 3–5 个主团块，明暗面方向与场景光一致。
- 树干应在枝叶间局部可见，不能像漂浮绿色云团。
- 同类树至少 5 个轮廓变体和 3 个明暗变体。
- 树冠最大水平重复间隔不少于 7 个实例。
- 柳树、竹林和果园拥有独立运动方式，禁止共享整体旋转摆动。

### 11.3 动画

- 风静：叶片局部 1°–2° 摆动，周期 3–6 秒。
- 微风：枝叶 2°–4°，不同枝组相位错开 15%–35%。
- 风雨：整体 4°–7°，叶片局部附加快速抖动。
- 稻田和茶垄使用区域波传播，不逐株独立计算。
- 落叶每棵树同时不超过 3 片，非秋季仅偶发。

## 12. 场景动画与状态映射

### 12.1 原则

- 动画只表现模拟结果，不决定模拟结果。
- 同一状态至少有 2–4 个可轮换的短动作，避免机械循环。
- 所有循环动画必须支持确定性相位偏移，不同实例不能同步。
- 远景单位降低帧率而不降低移动速度。
- 暂停游戏时，生产、人物、运输和施工动画暂停；水、云影等纯环境动画可按设置选择轻微继续。

### 12.2 建筑状态

| 模拟状态 | 必须表现 | 禁止表现 |
| --- | --- | --- |
| `constructing` | 地基、脚手架、材料堆、工人施工 | 正常营业、满员生产 |
| `idle` | 门窗轻动、少量待机人物 | 假生产、持续冒烟 |
| `working` | 专属机械、生产人员、原料到成品过程 | 通用闪光点 |
| `delivering` | 装卸、搬运或车辆靠站 | 货物瞬间消失 |
| `serving` | 顾客进入、排队、入座或接受服务 | 无人建筑自动播放人群 |
| `blocked` | 对应原因的静态迹象，如空料架、满仓、关闭炉火 | 整栋变红、持续警报闪烁 |
| `upgrading` | 搭架、施工遮挡、局部拆装、最终落成 | 直接淡化切图 |

### 12.3 性能等级

- 高：150 个可见移动实体，完整粒子、阴影和环境动画。
- 中：100 个可见实体，远景人物 6 fps，粒子减半。
- 低：60 个可见实体，远景人物使用方向步态或群组动画，关闭非交互投影。
- 无论等级如何，运输、生产状态和人物位置均不能显示错误。

## 13. 0–8 级成长系统

升级单位是完整地块，不是孤立主体。每一级必须在“主体、功能、环境、活动”四栏中至少改变两栏；奇数级优先改变主体，偶数级优先补全环境和运行。

| 等级 | 阶段 | 主体变化 | 地块与道路 | 活动与细节 | 密度目标 |
| --- | --- | --- | --- | --- | --- |
| 0 | 遗址 | 残墙、旧地基或荒废生产地貌 | 断路、杂草、积水 | 0–1 个调查细节，无正常生产 | 10%–22% |
| 1 | 清理 | 修正地基，出现最小可用主体 | 清出入口和单条土径 | 1–2 名施工者，材料堆 | 22%–32% |
| 2 | 启用 | 主体封闭或基础设施可工作 | 接通道路、水渠或栈桥 | 首个低效率功能动画 | 30%–40% |
| 3 | 成形 | 增加一处功能翼房或核心设备 | 院落边界、排水和货物区 | 2–4 名工作者或使用者 | 40%–50% |
| 4 | 稳定 | 主体材质翻新，功能区完整 | 石路接入、围墙或生产分区 | 稳定生产循环和首次运输 | 48%–58% |
| 5 | 扩建 | 增加第二主体、楼层或大型设备 | 扩展院落、后勤路线 | 工作与服务角色分工 | 58%–68% |
| 6 | 街区化 | 主体与附属建筑形成组合轮廓 | 与相邻道路、岸线和街区融合 | 顾客、运输、生活活动并存 | 66%–76% |
| 7 | 旺盛 | 完整终局主体轮廓出现 | 摊位、绿化、灯具、储运空间完善 | 高密度但有组织的人流物流 | 74%–84% |
| 8 | 极盛 | 功能专属终局形态，不再保留废墟 | 地块无无意义空地，与城市网络连续 | 正常营业、专属动画、昼暮差异 | 82%–92% |

### 13.1 密度定义

密度不是屋顶覆盖率，而是有功能或经过设计的地块面积，包括：

- 建筑主体。
- 生产场地、农田、盐池、晒场。
- 必要道路、院落、装卸场。
- 有明确用途的园林、水景和绿化。

纯草地、无用途泥地、随机石块和用于填空的亭子不计入密度。

### 13.2 连续成长约束

- 上一级的主识别体在下一级必须保留或合理演化，不能突然变成另一类建筑。
- 每次升级新增面积不超过上一级地块设计面积的 22%，避免跳变。
- 0→1 可以清除 40%–70% 废墟；2 级后每级废墟残留至少减少一半，5 级起正常经营区域不得出现废墟。
- 8 级不能只是 7 级增加灯笼；必须完成一个功能、街区或运输层面的终局变化。
- 农业与盐业的高等级成长体现在生产面积、灌溉、分区、工人和物流，不转化为楼阁群。
- 民居高等级形成街坊，不转化为大宅地标。
- 生产建筑高等级增加生产链可见性，不转化为商业景点。

### 13.3 全城密度

- 城镇初期允许自然空地形成呼吸区。
- 当全城平均等级达到 5，建筑之间的道路、岸线和功能边界必须连续。
- 当全城平均等级达到 7，主镇有效设计覆盖率不低于 82%。
- 最高阶段无面积超过当前可见主镇 3% 的无功能空地。
- 保留的开放空间必须明确属于广场、码头、晒场、田地、花园、水道、消防间隔或交通节点。

## 14. UI 与场景融合

### 14.1 视觉原则

- UI 是一本轻薄的“岛镇手账”，不是悬浮科幻 HUD。
- 默认画面至少 78% 面积留给地图。
- 同时最多开启一个大型面板。
- 场景内提示优先，管理数据进入右侧抽屉。
- UI 不覆盖当前选中建筑主体和主要道路交叉口。

### 14.2 UI 材质与形状

- 面板底色：暖白 `#F2EAD8`，92%–96% 不透明度。
- 细边：青灰 `#8A9890`，1 px。
- 圆角：大面板 16 px，小卡片 10–12 px；不使用过度胶囊化。
- 阴影：`0 8px 24px rgba(41, 56, 51, 0.16)`，禁止重黑浮层。
- 标题字体优先宋体或有书卷气的衬线字体，正文使用清晰黑体。
- 图标采用 1.5 px 手绘几何线，端点圆润；禁止混用写实图标和通用 emoji。

### 14.3 场景提示

- 建筑可操作状态以入口附近的小型木牌、灯火或工地标记表示。
- 选中描边使用浅宣纸色外发光＋青绿内线，总宽不超过 3 px。
- 缺货、停工等问题先显示单一克制图标，点击后在抽屉解释原因链。
- 材料掉落本体必须是木捆、石堆、砖垛、绳卷或布包，不使用金币光球。
- 稀缺材料可有 1.2 秒的柔和光晕呼吸，但不持续跳动。

### 14.4 缩放适配

- 远景：隐藏人物细节和小型图标，只保留建筑状态、道路和运输流。
- 中景：默认玩法尺度，显示人物、材料和生产动画。
- 近景：增加工具、招牌和院落细节，不改变素材透视。
- UI 尺寸基于屏幕像素，不随地图缩放。

## 15. AI 感规避规则

以下任一问题出现即退回重画：

1. 建筑轴线、窗格、瓦脊或桥栏在结构上无法闭合。
2. 同一资产内出现两个不同透视角度。
3. 门窗、台阶、船只与人物比例互相矛盾。
4. 功能物件随机堆砌，无法解释使用流程。
5. 轮廓左右近似镜像但细节无意义变形。
6. 文字、招牌或旗帜出现乱码、伪文字或不可读笔画。
7. 重复出现亭子、塔、船、灯笼作为通用“升级感”。
8. 画面边缘融化、物体相互粘连、屋檐穿墙或人物缺肢。
9. 全图覆盖纸纹、颗粒、噪点、雾化或过度锐化。
10. 光源方向不统一，投影与体积明暗矛盾。
11. 装饰密度均匀，没有主次、留白和功能分区。
12. 每一级仅整体放大、换色或添加无功能装饰。
13. 同类建筑的九级资产无法稳定叠放，锚点或占地跳动。
14. 最高级仍有大量无用途草地，或低级已呈现完整豪华建筑。
15. 生产动画与建筑功能不符，或停工时仍正常工作。

### 15.1 生产流程

- AI 或生成工具只可用于前期构思、材质参考和局部变体探索。
- 最终资产必须经过人工结构校正、透视校正、线稿统一、色板映射、功能校验和逐帧动画清理。
- 不允许把生成式整图直接裁切成游戏资产。
- 建筑先完成黑白 footprint 草图和功能流程图，再进入线稿与设色。
- 每栋建筑先通过 0、4、8 三级关键帧评审，再补齐 1、2、3、5、6、7 级。
- 所有文字使用项目内正式字形或独立文本层，不从生成图中保留。

## 16. 资产拆分与导出规格

### 16.1 建筑资产结构

每个建筑等级至少拆分：

- `base`：地面、地基、田地或盐池。
- `back`：后侧树木、烟囱、后墙。
- `body`：建筑主体。
- `front`：前景屋檐、院墙、树冠等遮挡层。
- `activity`：机械、旗帜、布幅、门窗等循环动画。
- `fx-anchor`：烟、灯光、施工、装卸等运行时挂点数据。
- `mask`：可点击区域、遮挡区域和必要的水面裁切蒙版。

大型建筑不得导出成一张包含所有前后景的扁平 PNG。

### 16.2 分辨率

- 设计母版按逻辑 2× 分辨率制作。
- 运行时提供 1× 和 2× 两套纹理；高分屏优先使用 2×。
- 单个普通建筑 1× 包围盒建议不超过 `768 × 768 px`。
- 大型地标或 XL 生产区可达 `1024 × 1024 px`，超出则拆分。
- 人物单帧建议 `48 × 64 px` 或 `64 × 80 px`，按动作包围盒统一。
- 地形与道路采用可拼接图块或 9-slice 组合，避免整岛大图。

### 16.3 文件格式

- 静态透明资产：PNG-24 或经验证无色带的 WebP lossless。
- 动画图集：PNG/WebP atlas＋JSON；同一动画帧尺寸与锚点固定。
- 大面积无透明背景：WebP quality 85–92，需通过色带检查。
- UI 图标：SVG 或高分辨率 PNG；SVG 禁止运行时复杂滤镜。
- 所有纹理使用预乘 Alpha，并在引擎中保持统一配置。

### 16.4 命名

```text
assets/buildings/{building-id}/level-{0..8}/
  base.webp
  back.webp
  body.webp
  front.webp
  activity-{state}.json
  activity-{state}.webp
  anchors.json
  masks.json
```

人物：

```text
assets/characters/{body-type}/{outfit}/{action}-{direction}.json
assets/characters/{body-type}/{outfit}/{action}-{direction}.webp
```

环境：

```text
assets/environment/{family}/{variant}-{season}-{time}.webp
```

### 16.5 元数据

每级建筑 `anchors.json` 至少包含：

- `origin`：逻辑原点。
- `entrance`：人物和道路入口。
- `delivery`：物流交付点。
- `workerSpots[]`：工作动画位置与朝向。
- `customerSpots[]`：服务使用位置。
- `smoke[]`、`light[]`、`waterFx[]`：特效挂点。
- `occlusionPolygon`：人物遮挡范围。
- `bounds`：裁剪包围盒。
- `footprint`：与模拟定义一致的地块列表。

数值以母版像素和逻辑格坐标同时记录，禁止手工在渲染代码中为每张图猜偏移。

### 16.6 动画图集

- 循环动画首尾姿态连续，不重复首帧造成停顿。
- 单个循环建议 6–16 帧。
- 建筑机械为 8–12 fps；水、旗布为 10–16 fps；人物为 8–12 fps。
- 图集边缘扩展 2 px，帧间 padding 4 px，避免纹理渗色。
- 相同状态不同建筑不可强行统一帧数，但必须提供持续时间。
- 动画事件标记包含 `footstep`、`pickup`、`release`、`impact`、`smoke`、`delivery` 等，用于同步音效和粒子。

## 17. 逐项制作与验收流程

### 17.1 单栋建筑交付物

每类建筑必须交付：

1. 功能流程图：原料、工作位置、成品、访客、物流入口。
2. footprint 黑白图和四向旋转预览。
3. 0、4、8 级并排概念图。
4. 0–8 级完整分层资产。
5. `idle / working / blocked / upgrading` 最低四种状态；服务和物流建筑增加对应状态。
6. 晨、昼、暮三时段合成预览。
7. 25%、50%、100% 三种缩放截图。
8. 与相邻道路、人物、货车或船只的比例图。
9. 元数据、图集和引擎预览。

### 17.2 单栋验收

- [ ] footprint 与模拟定义逐格一致。
- [ ] 四向旋转无透视错误或锚点跳动。
- [ ] 隐藏名称后，5 名评审中至少 4 人能认出功能类别。
- [ ] 与其他 27 类建筑不存在终局轮廓高度雷同。
- [ ] 0、4、8 级缩略图可一眼区分。
- [ ] 0–8 级没有主体缩小、功能倒退或道路断裂。
- [ ] 5 级后无废墟残留，8 级无无功能空地。
- [ ] 专属生产流程完整且与模拟状态一致。
- [ ] 停工、缺料、满仓、无工人均有不同的克制表现。
- [ ] 人物、门窗、台阶、货物和交通工具比例一致。
- [ ] 晨昼暮光源、投影和灯光符合统一规范。
- [ ] 线宽、材质、色板和纹理频率符合本规范。
- [ ] 不存在乱码、结构融化、重复生成细节和通用亭阁化。
- [ ] 图集无裁切、抖动、白边、色带或 Alpha 渗色。
- [ ] 运行时裁剪包围盒覆盖全部动画，但不过度扩大。

### 17.3 街区验收

- [ ] 相邻建筑入口真实接入道路。
- [ ] 屋顶、墙面和道路不会因同色粘成一片。
- [ ] 主街、次巷、生产后勤线和水运线可从画面读出。
- [ ] 高等级街区密度增加但交通空间仍清楚。
- [ ] 空地均可解释为生产、交通、园林、广场或水系。
- [ ] 人物和物流路线不会穿墙、穿水或穿过静态货物。
- [ ] 同屏循环动画相位打散，无整齐同步摆动。
- [ ] 人流密度与住宅、岗位、商业和服务状态一致。

### 17.4 全城验收

- [ ] 四岛具有统一画法和不同产业身份。
- [ ] 主镇、农业岛、山林岛和潮汐岛不共享错误的终局模板。
- [ ] 28 类建筑隐藏名称后均能依据轮廓和活动区分。
- [ ] 全城 8 级状态有效设计覆盖率不低于 85%。
- [ ] 无超过可见主镇面积 3% 的无功能空草地。
- [ ] 农田、茶园、药圃、果园和盐场仍以生产地貌为主体。
- [ ] 船只只出现在允许且功能合理的位置。
- [ ] 晨昼暮切换不改变资产位置、不产生色阶断层。
- [ ] 150 个可见实体下，动画降级不会破坏状态真实性。
- [ ] 1280×720 与 844×390 横屏下，关键建筑、材料和 UI 可读。

## 19. 最终质量红线

- 不再使用整岛生成图作为可玩地图主体。
- 不接受只有静态正视图、没有分层和状态动画的建筑交付。
- 不接受 252 张等级图仅靠批量换色、缩放或通用装饰生成。
- 不接受最高级仍像废墟、地块大片空置或所有建筑趋同为亭阁群。
- 不接受“看起来在工作”但与真实生产、库存、物流和人物状态无关的动画。
- 不接受以颗粒、雾、锐化和复杂滤镜掩盖结构问题。
- 不接受复制现有商业游戏的建筑、角色、界面、配色组合或标志性构图。

本规范是后续建筑概念、资产制作、动画制作、渲染接入和视觉审计的共同基线。任何偏离必须先形成可验证的替代规则，并由主控会话更新本文档后再执行。
