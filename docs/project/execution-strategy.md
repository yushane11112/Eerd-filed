# 《小耳岛》目标与执行节奏校准

更新时间：2026-07-12

## 1. 不变的最终总目标

《小耳岛》的最终目标仍然是稳扎稳打做成商业级东方水乡城市文明模拟游戏，而不是短期视觉 Demo、网页原型或一次性技术样例。

最终交付必须同时满足：

- 城市规划自由度：道路、桥梁、水路、住宅、产业、仓储、市场、服务和行政设施可由玩家规划。
- 模拟因果完整：人口、住房、就业、生产、库存、物流、消费、税收、财政、服务、满意度、迁入迁出和风险治理形成闭环。
- 状态可观察：居民、货车、船只、服务访问、施工、停工、拥堵、仓满、缺货、缺工和低满意度能在地图或 UI 中被玩家理解。
- 商业级表现：美术年代统一、建筑功能可辨、街区有密度、动画由状态驱动、性能和测试可支撑长期迭代。
- 可持续协作：所有阶段判断、任务优先级、验证结果和接续方式必须写入仓库，不能依赖某一次 Codex 对话记忆。

## 2. 当前阶段判断

当前不再按早期 P0“商业定位与项目中枢重构”执行。

当前阶段应定义为：

**P1.5 商业级垂直切片收敛期**

含义：

- P0 方向统一和项目中枢已经完成。
- P1/P2 中大量城市灰盒闭环、治理链路、物流和 QA 基础已经进入代码。
- 当前最大短板不是“再写更多规划”，而是把已有模拟能力集中呈现为一个玩家一眼能看懂、能操作、能验证的垂直切片。
- 之后每轮优先选择能同时提升“可玩感、可见变化、系统闭环”的任务。

## 3. 近期优先级

默认优先级从 2026-07-12 起调整为：

1. **可见垂直切片**：starter 城市第一眼必须明显更像城市，包括建筑体块、道路铺装、街区边界、集市外摆、仓储堆场、民居灯火和居民/货运活动。
2. **可操作闭环**：治理卡、建造、道路、物流、服务、升级和财政必须尽量接入真实运行时动作，而不是只停留在解释文案。
3. **核心模拟自洽**：物流吞吐、仓储容量、服务排队、升级成本、居民需求和财政压力继续收敛成长期可平衡系统。
4. **QA 分层提效**：按变更风险选择验证强度，避免每个小改动都使用最高成本流程。
5. **文档减重**：文档记录事实、阶段判断、风险和下一步，不再重复堆长篇流水账。

## 4. 近期不优先事项

以下事项在没有直接支撑垂直切片前暂缓：

- 继续新增大量物流微动作，但画面和玩家操作没有变化。
- 继续写大段新规划文档，而没有代码、画面、测试或可玩闭环产出。
- 继续扩大金标 manifest 样例数量，但不接入主画布或验收截图。
- 继续追求精确完成百分比，把它当作真实进度。
- 每个纯文档或轻量视觉调整都强制跑完整长稳和全量测试。

## 5. 每轮执行原则

每轮只设一个主目标，并满足以下要求：

- 主目标必须能用一句话说明玩家或项目获得了什么。
- 产出必须能被代码、截图、测试、文档或提交记录验证。
- 优先完成一条闭环，不同时铺开多条半成品链路。
- 如果某项工作只提高内部结构，必须说明它下一步如何转化为玩家可见或可测结果。
- 每轮结束必须提交并推送 GitHub，保证跨电脑接续稳定。

## 6. 验证分级

按变更风险选择验证，不再机械要求每轮都跑最高级别。

| 等级 | 适用变更 | 必须验证 |
| --- | --- | --- |
| Tier 0 | 纯文档、任务看板、接续手册 | `git diff --check` |
| Tier 1 | 局部代码、纯工具函数、低风险 UI 文案 | 目标测试 + 开发构建 |
| Tier 2 | 主画布、视觉、交互、玩家路径 | 目标测试 + 开发构建 + 浏览器截图或交互验证 |
| Tier 3 | 模拟核心、经济、物流、存档、共享协议 | 目标测试 + `npm test` + `npm run build` |
| Tier 4 | 阶段收口、跨电脑交付、发布候选 | `npm test` + `npm run build` + 必要浏览器 E2E/长跑 QA |

验证结果必须写入 `docs/project/qa.md`。如果跳过某项验证，需要说明原因。

## 7. 未来三轮默认冲刺

下一轮默认从视觉垂直切片开始：

1. **Starter 建筑第一眼改观**：民居、粮仓、集市、码头、稻田和道路在主画布上有更大轮廓、更强功能差异和更少灰盒感。
2. **道路与街区质感**：石路、土路、桥面、田埂、仓储堆场、集市外摆和水岸边界形成清晰城市结构。
3. **活动密度与状态反馈**：居民、货车、服务访问、市场人流、仓储忙碌、缺货/仓满/停工状态在地图上更容易被看见。

这三轮每轮都应保留截图或浏览器验收记录。

## 8. 跨电脑接续规则

其他电脑或新 Codex 对话必须优先读取本文件。若本文与旧聊天记录冲突，以本文、`HANDOFF.md`、`progress-dashboard.md` 和最新 Git 提交为准。

默认继续方式：

1. 拉取 `codex/commercial-launch-plan-docs` 最新代码。
2. 阅读 `docs/project/README.md`、`docs/project/HANDOFF.md`、本文件和 `docs/project/progress-dashboard.md`。
3. 按“未来三轮默认冲刺”和 `progress-dashboard.md` 的下一轮任务选择一个主目标。
4. 按验证分级执行。
5. 更新文档、提交并推送 GitHub。
