# 《小耳岛》阶段质量门禁

> 2026-06-27 方向更新：本门禁由 `commercial-launch-master-plan.md`、`design/world-bible.md`、`design/building-taxonomy.md`、`design/population-lifecycle.md` 和 `design/art-production-roadmap.md` 共同约束。旧的 28 类建筑、四岛、听歌材料主线不再作为商业级上线门禁。

## 0. 商业级上线总门禁

上线前必须全部满足：

- 城市可从荒地发展到繁华水乡城市。
- 外来人口抵达、找房、临时停留、正式入住、就业、消费、纳税和迁出完整。
- 道路、桥梁、水路、住宅、生产、仓储、物流、市场、财政、服务和风险真实互相影响。
- 缺路、缺工、缺货、仓满、财政赤字、疾病、火灾、犯罪、低满意度有可观察后果。
- 建筑类别可扩展，且全部符合架空明清江南水乡年代设定。
- 后期城市必须形成商业街、夜市、码头仓区、官署街、书院街、园林住宅区等繁荣街区。
- 美术全阶段计划 ART-P0 到 ART-P10 完成上线范围内验收，无核心灰盒资产残留。
- 300+ 建筑、500+ 家庭、150+ 可见移动实体稳定运行。
- 存档读档、构建部署、长时间运行和自动测试稳定。
- 项目内有完整任务看板、集成日志、进度仪表盘、产物索引和 QA 记录。

## 0.1 年代一致性门禁

任意建筑、人物、交通、产业或道具出现现代电力、汽车、铁路、现代工厂、民国洋楼、蒸汽朋克或未来机械，直接退回概念阶段。

## 0.2 人口生命周期门禁

人口不得直接作为数字增加。至少必须区分外来人口和正式居民，并能解释入住失败、等待、成功入住和离城原因。

## 0.3 美术全阶段门禁

美术完成度不能只看首批金标。必须按 `design/art-production-roadmap.md` 追踪美术方向、灰盒辨识、概念谱系、金标切片、角色体系、状态动画、环境密度、UI 视觉、Alpha 量产、Beta 完整化和 RC 冻结。

## 1. 门禁制度

质量门禁是版本推进的必要条件，不是建议清单。任何阶段只有在全部硬门禁通过、证据归档并由指定负责人签署后，才能进入下一阶段。

### 1.1 判定状态

| 状态 | 含义 |
| --- | --- |
| Pass | 所有硬门禁通过，允许推进 |
| Conditional Pass | 仅存在不影响下游的限时整改项；必须注明负责人和关闭版本 |
| Fail | 存在硬门禁失败、证据缺失或下游无法安全开始 |
| Revoked | 通过后发生重大变更，原签署失效，必须重新验收 |

Conditional Pass 不适用于安全、存档、确定性、核心循环、资产版权、P0/P1 缺陷和目标设备性能。

### 1.2 缺陷等级

- P0：崩溃、数据丢失、存档损坏、安全/隐私问题、无法启动或无法回滚。
- P1：核心流程阻断、模拟结果错误、资源复制/丢失、严重性能退化、主要资产缺失。
- P2：显著影响理解、操作、视觉品质或音频体验，但有可用绕行。
- P3：局部瑕疵，不影响主要体验。

Alpha 门禁要求 P0/P1 清零；Beta 和 RC 要求 P0/P1/P2 清零。例外只能由主控、QA Lead 和对应总监共同书面批准。

### 1.3 门禁证据

每次门禁评审必须归档：

- 候选版本、构建号、提交哈希和 Schema/存档/资产版本。
- 测试报告、性能捕获、兼容矩阵和已知缺陷。
- 游戏内无剪辑录像与截图。
- 资产 manifest、校验报告和许可来源。
- 评审结论、签署人、整改项和截止版本。

缺少任一强制证据即判定 Fail，不接受口头承诺。

## 2. G0：产品与创意立项门禁

**准入**

- 用户反馈、现有原型和项目能力已完成审计。

**必须交付**

- 产品愿景、创意支柱、受众、体验目标和核心循环。
- 首发范围与明确不做项。
- 竞争差异、商业/平台约束、音乐奖励原则。
- 高风险清单、预算假设、里程碑和负责人。

**通过标准**

- 所有负责人能一致描述产品，不再以“废土、塔防或强制听歌”解释体验。
- 首次 10/30 分钟、首日和长期目标可被测试。
- “轻压力”与“真实城市模拟”已有分层方案，不依赖失败惩罚制造深度。
- 28 类建筑、四岛、横屏全屏、真实动态与音乐稀缺奖励被纳入范围。

**签署**

- 主控/制作人、创意总监、设计总监、技术总监、美术总监、QA Lead。

**返工触发**

- 核心循环、目标受众、平台或艺术方向发生改变。
- 新增大系统导致成本或技术风险超过原估算 20%。

## 3. G1：技术预研门禁

**准入**

- G0 Pass；目标设备和性能预算冻结。

**必须交付**

- 固定 Tick、确定性随机、快照、读档和回放验证。
- 等距地图、300 建筑、150 动态实体压力 Spike。
- 模型/精灵/骨骼动画方案和状态驱动演示。
- DCC 到 Prefab 自动导入及资产校验最小链路。
- 资源分包、裁剪、对象池、压缩、音频和输入 Spike。
- 技术决策记录与未决风险。

**通过标准**

- 相同种子、快照与操作序列产生相同模拟结果。
- 暂停、倍速、离屏和读档不会使动画与模拟脱节。
- 目标中端设备复杂场景稳定 ≥50 FPS，且有 CPU/GPU/内存明细。
- 资产导入可自动发现命名、单位、枢轴、等级、挂点、纹理和预算错误。
- 存档和公共契约具备版本与迁移策略。

**签署**

- 技术总监、工具链负责人、性能负责人、动画技术负责人、QA Lead。

**硬失败**

- 只提供录屏而无可运行构建和性能捕获。
- 正式资产仍需逐个手工修正才能进入引擎。
- 状态驱动动画无法覆盖施工、生产和物流。

## 4. G2：可玩灰盒门禁

**准入**

- G1 Pass；灰盒范围、公共类型和输入规则冻结。

**必须交付**

- 完整的住宅—就业—生产—仓储—搬运—市场/服务闭环。
- 道路铺设、建筑放置、旋转、拆除、全屏、拖拽和缩放。
- 停工原因、仓储和路线可视化调试工具。
- 普通材料随机掉落与拾取；歌曲稀缺奖励模拟。
- 灰盒城市布局和 10/30 分钟测试脚本。
- 至少 8 名目标用户的可玩测试记录。

**通过标准**

- 8/10 以上测试者无需口头教学完成首次建造和拾取。
- 7/10 以上测试者能解释至少三条系统因果链。
- 货物不瞬移；断路、缺工、缺料和仓满均真实阻断运行。
- 拖拽/拾取/建造关键操作成功率 ≥95%，无高频误触。
- 连续 60 分钟无不可恢复卡关、资源复制或存档错误。

**签署**

- 设计总监、系统策划、客户端负责人、UI/UX 负责人、QA Lead。

**返工触发**

- 核心乐趣依赖奖励数值而非城市运行本身。
- 玩家必须反复打开复杂面板才能理解城市。
- 灰盒布局无法容纳高繁荣阶段的城市密度。

## 5. G3：垂直切片门禁

**准入**

- G2 Pass；视觉圣经、建模、材质、动画、VFX、灯光、UI 和音频规范 Approved。

**必须交付**

- 一个正式品质主镇街区。
- 柳岸民居、层层稻田、丰年粮仓、小满食肆、青瓦瓷窑、旧码头六类金标建筑。
- 六类均有 L0/L1/L4/L8，至少两类完成 L0–L8。
- 正式人物、搬运车、船只、天气、昼暮、施工、UI、音频和存档。
- 15–20 分钟垂直切片构建、资产源文件、性能和用户测试报告。

**视觉门禁**

- 隐藏名称后，80% 以上评审者能辨认六类建筑功能。
- L0 与 L8 盲测差异清晰，L8 不保留废墟观感。
- 建筑比例、透视、色板、线条、材质和阴影统一。
- 不使用整岛静态图、AI 整图或程序几何作为最终画面。
- 街区没有无用途大块空地，建筑之间不存在“都变成亭子/船”的同质化。

**动画门禁**

- 生产、搬运、服务和施工可追溯到模拟状态或事件。
- 暂停后逻辑动画冻结；倍速与读档保持阶段一致。
- 六类建筑具有独立专属动作，不得共享统一光点和烟雾作为核心表现。
- 水、植被、烟、灯火与天气平滑，无整体漂移和穿帮。

**技术门禁**

- 目标设备平均 ≥50 FPS，1% Low ≥40 FPS。
- 常态 Draw Calls ≤180，压力峰值 ≤260。
- 桌面纹理显存 ≤256MB，移动端 ≤160MB。
- 首屏压缩资源 ≤20MB；无明显 GC 卡顿。

**玩法门禁**

- 正式画面下核心系统仍然清晰，未被美术遮挡或 UI 淹没。
- 普通掉落与音乐奖励严格分离。
- 关键流程 20 分钟内无阻断缺陷。

**签署**

- 主控/制作人、创意总监、设计总监、技术总监、美术总监、音频负责人、QA Lead。

**返工触发**

- 任一金标资产在后续批量生产中被证明不可扩展。
- 单建筑实际生产成本或周期超过计划 30%。
- 用户认为画面仍是“静态图”“AI 感”“局部升级”或“建筑雷同”。

## 6. G4：完整制作/Alpha 门禁

**准入**

- G3 Pass；金标模板、工具、批次与产能计划冻结。

**必须交付**

- 四岛、全部首发系统和 28 类建筑 L0–L8 已集成。
- 人物、交通、环境、UI、VFX、灯光、音频和内容完整。
- 所有内容通过自动资产验证和系统测试。
- Feature Complete Alpha 构建。
- 8 模拟小时长稳、存档迁移、断网/恢复和异常退出报告。

**建筑资产门禁**

每个 `建筑×等级` 必须拥有：

- Approved 概念与等级演化依据。
- 灰盒比例、占地、入口和城市布局验证。
- 最终模型、LOD、碰撞、选择代理和遮挡层。
- 通过检查的 UV、材质、贴图与显存预算。
- 必要绑定、挂点、动画、VFX、灯光和音频。
- 版本化 Prefab、manifest 和自动校验报告。
- 正式场景截图、转台、状态录像和性能结果。

任一建筑任一级缺项，28×9 完成率不得标记为 100%。

**系统门禁**

- 所有核心系统可达且无占位逻辑。
- 无 P0/P1 缺陷；P2 缺陷有明确关闭版本。
- 不存在死锁、资源复制、资源无故丢失、人口无限增长或财政数值爆炸。
- 旧存档按迁移策略加载，失败时提供安全回退而非覆盖。

**内容门禁**

- 四岛高繁荣布局形成完整功能城市。
- 28 类建筑隐藏名称仍具功能辨识度。
- L0–L8 每级变化满足结构/活动语法。
- 所有生产和服务建筑拥有正确的专属工作表现。

**签署**

- 各专业负责人、技术总监、美术总监、设计总监、QA Lead、主控/制作人。

**返工触发**

- 发现系统性资产错误；立即暂停相关批次，修正规范、模板和工具后全量重验。
- Alpha 后仍需增加核心系统、重做城市坐标或更换渲染技术。

## 7. G5：Beta 门禁

**准入**

- G4 Pass；功能和内容锁定，只允许修复、平衡和优化。

**必须交付**

- Content Complete Beta 构建。
- 目标浏览器、分辨率、输入设备和性能档位兼容矩阵。
- 最终数值、教学、可用性、可访问性、混音和色彩报告。
- 长稳、压力、存档、回放、加载、内存与包体报告。
- 发布清单、监控事件和隐私审查草案。

**通过标准**

- P0/P1/P2 缺陷清零。
- 500 户、300 建筑、150 可见实体压力场景平均 ≥50 FPS。
- 连续 8 模拟小时无内存持续增长、订单堆积、死锁或存档损坏。
- 所有目标环境核心流程通过率 100%。
- 新手关键操作完成率、停工理解率和拾取成功率达到 G2 后设定的最终目标。
- 城市最繁荣阶段视觉密度、灯光、音频和动态表现不因性能降级失去核心体验。

**签署**

- QA Lead、性能负责人、UI/UX 负责人、音频负责人、技术总监、设计总监、主控/制作人。

**硬失败**

- 通过大范围关闭居民、动画、天气或灯火换取帧率。
- 仍存在无法解释的随机模拟差异或不可重现存档问题。
- 任何未授权或来源不明资产进入候选包。

## 8. G6：Release Candidate 门禁

**准入**

- G5 Pass；代码、内容、资产、Schema 和配置冻结。

**必须交付**

- CI 生成的 `1.0.0-rc.N` 包、校验和、SBOM 和符号文件。
- 全量冒烟、回归、兼容、性能、安全、隐私和许可报告。
- 存档升级/降级验证、监控仪表盘、报警和回滚演练。
- 发布说明、客服已知问题、事故响应联系人和数据保留策略。
- 72 小时候选版本稳定性观察。

**通过标准**

- RC 期间无新增 P0/P1/P2。
- 同一提交和依赖锁可重复生成相同内容清单。
- 冷启动、热启动、全屏切换、音频权限、异常退出与恢复全部通过。
- 回滚能够恢复上一稳定版本，且不会破坏新旧玩家存档。
- 线上监控可以识别崩溃、帧率、加载、存档失败和音乐奖励异常。

**签署**

- 发布负责人、QA Lead、技术总监、主控/制作人；涉及隐私和许可的负责人共同签署。

**RC 变更规则**

- 只接受经过缺陷委员会批准的阻断性修复。
- 每次改动必须生成新的 `rc.N+1`，并重新执行受影响门禁和完整冒烟。
- 禁止顺手重构、调色、补内容和无关优化。

## 9. 建筑单资产质量门禁

每个建筑的每个等级都必须通过 A0–A8，完整建筑再通过 A9。失败时退回最近一个能够消除根因的环节，而不是只在末端补丁。

| 门禁 | 阶段 | 通过标准 | 失败退回 |
| --- | --- | --- | --- |
| A0 | 功能简报 | 语义、占地、入口、岗位、容量、生产/服务、停工和升级变化完整 | 系统策划 |
| A1 | 概念 | 三视图、等距图、剪影、等级演化、拆件与材质区明确；功能可辨认 | 概念美术 |
| A2 | 灰盒 | 比例、透视、道路/水路、遮挡、镜头和邻接通过正式场景验证 | 概念或灰盒建模 |
| A3 | 模型 | 拓扑、结构、LOD、碰撞、枢轴、模块与专属轮廓合格 | 建模 |
| A4 | UV/材质 | Texel Density、接缝、材质槽、风格、压缩与显存达标 | UV/材质；结构问题退建模 |
| A5 | 绑定/挂点 | 骨骼、约束、蒙皮、入口、装卸、服务、VFX、音频和遮挡点完整 | 绑定；拆件错误退建模 |
| A6 | 动画/VFX | 状态驱动、无穿插、暂停/倍速/读档正确，专属工序可读 | 动画/VFX；状态缺口退契约 |
| A7 | Prefab | 类型、等级、LOD、碰撞、材质、状态机、音频和 manifest 自动校验通过 | 工具/客户端或上游资产 |
| A8 | 场景 | 正式街区、昼暮、天气、生产链、升级和压力场景通过 | 定位根因后回对应环节 |
| A9 | 建筑完整性 | L0–L8 演化连贯、L0/L8 差异显著、九级均无缺项 | 等级设计或对应资产环节 |

### 9.1 A9 额外规则

- L0、L1、L3、L5、L7 的主体轮廓必须可通过剪影对比确认变化。
- L2、L4、L6、L8 的院落、道路、摊位、灯火、居民或机械活动必须可见。
- L8 必须正常营业、有人流/物流和完整环境，不能继续呈现废墟。
- 同一制作族允许共享材质和构件，不允许共享最终轮廓与核心动作。
- 港口外建筑不得无理由附带船只；景观建筑不得伪造生产；所有动作符合建筑用途。

### 9.2 建筑盲测

每批建筑至少由 10 名未参与制作的评审者完成：

- 功能识别：隐藏名称，正确率 ≥80%。
- 等级排序：随机展示九级，主阶段 L0/L1/L3/L5/L7 排序正确率 ≥90%。
- 终态感知：L8 被描述为“完整、繁华、正在运行”的比例 ≥80%。
- 同质化检查：不得有三类以上建筑被认为是同一建筑换皮。

不达标时退回概念与等级演化，不允许仅用 UI 标签补救。

## 10. 专业交付门禁

### 10.1 玩法/系统

- 规则、状态、边界、反馈、存档和分析事件齐全。
- 自动化覆盖主要状态转换和失败路径。
- 设计表与运行时数据一致，禁止双份手工配置。

### 10.2 城市布局

- 所有建筑有合法占地、入口、道路/水路和作业空间。
- 25/50/75/100% 发展阶段均可玩、可读且无大面积无用途空地。
- 最高密度仍保留主干路、消防式通行空间和视觉焦点。

### 10.3 建模/材质

- 单位、轴向、枢轴、比例、法线、拓扑、LOD、碰撞与命名自动通过。
- 无隐藏重复面、非预期穿插、破损 UV、超预算纹理和无用材质槽。
- DCC 转台和引擎实景均通过，不能只在单一灯光下成立。

### 10.4 动画/VFX

- 状态和事件映射完整；暂停、倍速、读档、离屏恢复正确。
- 无滑步、穿插、漂移、循环跳帧或粒子无限增长。
- 核心动作在最远可交互缩放下仍能读懂。

### 10.5 灯光

- 晨昼暮连续过渡；灯光符合营业和场景时间。
- 不因调色丢失 UI、道路、人物和材料可读性。
- 动态灯预算和阴影预算通过。

### 10.6 UI/UX

- 主要流程键鼠和触摸均可完成。
- 面板层级、返回、取消、错误、加载和空状态完整。
- 全屏切换和视口变化不丢失相机位置或操作目标。

### 10.7 音频

- 事件不重复触发、不爆音、不堆叠失控。
- 环境、建筑、人物、UI 和音乐奖励拥有清晰优先级。
- 满负荷城市仍保持响度、并发和 CPU 预算。

### 10.8 客户端/工具

- 类型检查、测试、构建、资产校验和存档回放全部通过。
- 无跨层违规依赖、无未版本化 Schema、无静默吞错。
- 工具具备失败提示、批处理、日志和可重复结果。

## 11. 最终发布 Definition of Done

只有以下各项全部为真，`1.0.0` 才能发布：

1. G0–G6 全部 Pass，且没有被重大变更 Revoked。
2. 28 类建筑的 A0–A9 全部通过，252 个等级版本在资产矩阵中无空项。
3. 四岛、全部核心系统、完整 UI、音频、灯光、VFX、人物和交通资产已集成。
4. 所有可见城市活动由真实模拟状态驱动，没有假生产、假运输和静态整岛替代。
5. 全屏、拖拽、缩放、建造、拾取、存档、读档和音乐奖励完整可用。
6. 压力、长稳、兼容、存档迁移、安全、隐私和许可全部签署。
7. P0/P1/P2 缺陷为零；P3 均有发布后版本和负责人。
8. 构建可复现，监控可用，回滚演练通过。
9. 源码、源资产、Prefab、manifest、文档、测试、许可证和发布包完整归档。
10. 主控/制作人、设计总监、技术总监、美术总监、QA Lead 和发布负责人共同签署。
