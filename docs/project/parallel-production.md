# 《小耳岛》并行生产中枢

版本：1.0  
主控会话：当前会话  
目的：把《小耳岛》从“单线程原型开发”切换为“游戏制作流水线式并行生产”。

## 1. 纠偏结论

此前项目已经具备模块化目录、任务看板和本地提交，但严格说还没有形成真正的并行生产。原因有三点：

1. 子任务没有同时启动，更多是主会话顺序推进。
2. 任务粒度仍偏“模块实现”，没有完全对齐游戏工业流水线中的概念、美术、建模、动画、引擎、QA 等工种。
3. 产物回流机制不够硬：没有明确每个子任务的输入、输出、文件所有权、验收证据和退回标准。

从本文件开始，后续执行按并行生产机制推进。

## 2. 主控职责

主控会话只做五件事：

1. 冻结公共协议和项目目标。
2. 拆解可并行任务并分配写入范围。
3. 维护任务看板、集成记录和验收清单。
4. 审查子任务产物，拒绝不符合标准的输出。
5. 集成代码/文档，运行测试、构建、本地提交；GitHub URL 提供后再推送远程。

主控不应该亲自重复子任务工作。若子任务产物不合格，应退回或重新拆分，而不是让主控临时补丁式糊上。

## 4. 子任务输入模板

每个子任务必须获得以下信息：

- 项目目标：横屏东方水乡真实城市模拟，不是静态岛屿图。
- 当前阶段：可运行灰盒已成立，正式高精良资产未成立。
- 写入范围：只允许修改指定文件或目录。
- 只读上下文：允许参考的契约、审计和设计文档。
- 输出要求：代码/文档、测试或验收证据、变更清单、已知限制。
- 协作约束：不是唯一 worker，不得回滚、覆盖或重复实现其他任务。

## 5. 子任务输出模板

每个子任务最终必须回报：

1. `status`：DONE / DONE_WITH_CONCERNS / BLOCKED。
2. `changed_files`：修改文件列表。
3. `summary`：完成了什么。
4. `verification`：运行了哪些测试、检查或人工验收。
5. `integration_notes`：主控合并时需要注意的接口、顺序或风险。
6. `known_limits`：哪些还没完成，不能被误认为完成。

没有输出模板的产物不能进入集成。

## 7. 集成顺序

同一轮并行任务完成后，按以下顺序集成：

1. 文档类规范：QA → 美术 → 建模/动画。
2. 公共协议：仅当必要时由主控修改。
3. 模拟核心：需求、满意度、迁入迁出。
4. 经济/物流/服务：生产、运输、市场和库存。
5. 渲染/动画：状态映射、可视反馈、性能预算。
6. UI：玩家可理解的面板、提示、调试视图。
7. 测试与构建：模块测试 → 全量测试 → build → 浏览器验收。
8. Git：本地 commit；远程 URL 可用后 push。

## 8. 退回标准

以下情况必须退回，不能合并：

- 只写愿景，没有可执行字段、接口、状态或验收标准。
- 高等级建筑仍保留大量无功能空地。
- 不同建筑最高级仍同质化为亭子、船、桥、小楼。
- 动画不是状态驱动，只是无条件循环特效。
- 模拟系统产生资源瞬移、复制、无故丢失或非确定性结果。
- 代码没有测试，或测试只覆盖快乐路径。
- 子任务修改了未授权目录。
