# 《小耳岛》高精良游戏正式生产流水线

## 1. 制作章程

### 1.1 产品定义

《小耳岛》是一款面向中国大众用户的横屏东方水乡城市模拟游戏。产品以低压力、可观察、可持续发展的文明小镇为核心体验，同时具备经典城市建设游戏所要求的真实道路、人口、就业、生产、仓储、物流、市场、财政与公共服务机制。

项目最终目标已明确升级为商业级城市/文明模拟游戏，而不是轻量网页原型。长期硬标准见 `docs/project/commercial-civilization-target.md`。后续所有子任务必须能回扣到完整文明系统、动态引擎或高精美术资产流水线之一；无法贡献这三类目标的需求不得优先进入主线。

首发版本必须形成以下闭环：

`自由规划城市 → 居民迁入与就业 → 真实生产和运输 → 城市服务与文明成长 → 普通材料随机落地并手动拾取 → 听完歌曲获得稀缺材料 → 建筑和街区持续升级`

### 1.2 创意支柱

| 支柱 | 玩家体验 | 制作约束 |
| --- | --- | --- |
| 活着的东方水乡 | 城市像一个真实运行的文明，而非静态布景 | 人物、建筑、物流和服务动画必须由模拟状态驱动 |
| 轻压力深模拟 | 机制可研究，但不以灾难、死亡或删档惩罚用户 | 可停工、短缺、降级和迁出；不得强制失败或连续催促 |
| 一眼可读的成长 | 从荒地与废墟逐步发展为功能完整、灯火繁盛的城镇 | 28 类建筑 0–8 级均有可验收的结构、功能和活动变化 |
| 尊重听歌偏好 | 音乐是温和奖励，不是限制玩法的体力系统 | 普通材料来自城市；听完任意歌曲仅结算稀缺材料 |
| 可触摸的世界 | 玩家能拖拽、缩放、全屏观察并直接拾取世界物件 | 主要操作发生在场景内，UI 不得长期遮挡城市 |

任何新设计必须至少强化一个支柱，且不得削弱其余支柱。无法映射到支柱的需求不进入当前版本。

### 1.3 受众与体验目标

- 核心受众：喜爱种田、经营、布置、观察角色生活的中国大众用户；不要求具备硬核城建经验。
- 次级受众：喜欢研究产业链、道路效率、城市布局和长期优化的模拟经营玩家。
- 首次 10 分钟：完成拖拽观察、铺路、放置住宅与生产建筑、看到居民迁入和首笔真实运输。
- 首次 30 分钟：理解停工原因、完成一次建筑升级、拾取一次普通材料、看到城市昼暮变化。
- 首日回访：城市状态保持连续，没有断签惩罚；出现新的可观察事件或可建设目标。
- 长期体验：优化街区和物流、收集建筑外观、发展四岛文明，而不是重复点击固定任务。

### 1.4 品质基线

- 美术采用原创东方工笔设色、水墨线条和江南水乡建筑语言，不复制现有产品资产、构图或界面。
- 最终场景不得使用整岛静态图冒充动态世界，不得使用程序化几何占位作为正式建筑。
- 生产、运输、人物、服务与施工表现必须可以追溯至模拟快照或带 Tick 的事件。
- 中端横屏设备目标 60 FPS，复杂城市稳定不低于 50 FPS。
- 压力场景基准：500 户家庭、300 栋建筑、150 个同时可见移动实体。
- 所有版本必须可重复构建、可回滚、可读档，并保留自动化测试和性能基线。

## 2. 生产组织与多会话协作

### 2.1 决策层级

| 角色/会话 | 最终责任 | 不得越权事项 |
| --- | --- | --- |
| 主控/制作人会话 | 产品目标、范围、里程碑、资源、最终验收 | 不跳过专业评审直接宣布资产完成 |
| 创意总监会话 | 题材、叙事气质、视觉与听觉方向 | 不修改模拟规则和技术预算 |
| 游戏设计总监会话 | 核心循环、系统关系、难度和体验节奏 | 不绕过技术评估承诺不可实现机制 |
| 技术总监会话 | 架构、公共契约、工具链、性能和构建 | 不擅自改变产品体验目标 |
| 美术总监会话 | 概念、建模、材质、动画、VFX、灯光统一性 | 不用表现层伪造模拟结果 |
| QA Lead 会话 | 测试策略、缺陷分级、发布阻断权 | 不降低既定质量门禁 |
| 发布负责人会话 | 候选版本、部署、监控、回滚 | 不接收未通过 RC 门禁的构建 |

主控会话维护唯一版本路线图、依赖图、风险清单和门禁状态。公共协议、资产规范、版本规则和验收标准只有主控会话可直接变更。

### 2.2 独立专业会话

每个会话拥有明确输入、输出与文件所有权；跨域变更必须提交接口变更请求，由主控会话裁决。

| RIGGING | 人物、机械、植被、船车绑定 | 骨骼、控制器、蒙皮和验证场景 |
| ANIMATION | 人物、建筑工序、物流、施工动画 | 动画片段、状态机、验收录像 |
| VFX | 水、天气、烟火、尘土、掉落与反馈 | 特效 Prefab、参数档、性能档 |
| LIGHTING | 晨昼暮、灯火、阴影、雾与色彩管理 | 灯光方案、场景配置、对照截图 |
| UI-UX | HUD、建造、详情、提示、手势和可访问性 | 交互原型、组件规范、可用性报告 |
| AUDIO | 环境、建筑、人物、UI、音乐奖励反馈 | 音频事件表、混音快照、响度报告 |

### 2.3 子任务交付协议

每个子任务必须包含：

1. 任务 ID、负责人会话、版本目标和文件/资产所有权。
2. 已冻结输入及其版本号，不接受口头或聊天中的隐含输入。
3. 产出清单、验收方法、性能预算和依赖。
4. 自动化测试、截图或录像、源文件、导出文件和变更记录。
5. 已知限制、未解决风险和集成步骤。
6. 明确状态：`Draft / Review / Approved / Integrated / Rejected / Superseded`。

子任务只有在下游会话可以无需猜测地继续生产时，才算交付。仅提交图片、代码或模型而缺少源文件、规格、测试和导入信息，均视为未交付。

## 3. 总体依赖图

```text
产品方向
  ├─> 玩法设计 ───────────────┐
  ├─> 系统策划 ─> 数值模拟 ───┼─> 可玩灰盒 ─> 垂直切片 ─> 完整制作
  ├─> 城市布局 ───────────────┤                         │
  └─> 艺术方向 ─> 概念美术 ───┤                         ├─> Alpha
                     ├─> 建模 ─> UV/材质 ─> 绑定 ─> 动画 ┤
                     └─> UI/UX、VFX、灯光、音频 ─────────┤
技术预研 ─> 客户端架构 ─> 工具链 ───────────────────────┘

Alpha ─> 内容锁定与系统完整 ─> Beta ─> 缺陷/性能/兼容收敛 ─> RC ─> 发布
                         QA、性能、可访问性、存档兼容贯穿全部阶段
```

阻断规则：

- 未冻结视觉圣经，不得批量生产模型和材质。
- 未通过体块与城市布局评审，不得进入细化建模。
- 未冻结建筑语义、占地、入口和动画挂点，不得制作最终绑定与动画。
- 未建立自动导入、命名校验和性能检查，不得开始 28×9 批量资产制作。
- 垂直切片未达到目标品质，不得以“先铺量后返工”为由进入完整制作。

## 4. 阶段流水线

每个阶段的硬门禁详见 `docs/project/gates.md`。阶段产出必须被归档到对应版本，并由主控、专业负责人和 QA 共同签署。

### 4.1 P0：创意与产品定义

**前置条件**

- 项目目标、平台、横屏与 Q 音乐嵌入场景已确定。

**负责会话**

- PRODUCT-DIRECTION 主责。
- GAMEPLAY-DESIGN、SYSTEM-DESIGN、ART-DIRECTION、TECH-DIRECTION、QA 参与。

**输入**

- 已确认的用户反馈、竞品研究、现有原型审计、技术现状。

**可验收交付物**

- 一页产品愿景、五项创意支柱、目标用户与关键场景。
- 首发版本的 Must/Should/Could/Won't 范围。
- 10 分钟、30 分钟、首日和长期体验目标。
- 风险登记册：模拟复杂度、资产规模、浏览器性能、音乐接口和内容产能。
- 初版 Definition of Fun 与 Definition of Done。

**返工条件**

- 核心循环仍依赖强制听歌、体力或复杂任务。
- 目标用户和经典城建深度发生冲突但无分层体验方案。
- 团队无法用一句话解释玩家为何回来。

### 4.2 P1：技术预研

**前置条件**

- P0 产品方向通过 G0。

**负责会话**

- CLIENT-ENGINE、TOOLS-PIPELINE、PERFORMANCE 主责。
- MODELING、ANIMATION、VFX、AUDIO、QA 支持。

**输入**

- 模拟规模、动态画面目标、资产质量目标和目标设备范围。

**可验收交付物**

- 固定 Tick 模拟、确定性随机、快照、存档与回放 Spike。
- 80×60 等距地图、300 建筑、150 动态实体渲染 Spike。
- 模型/精灵/骨骼动画技术选型和实机对比。
- 场景分层、裁剪、对象池、资源流式加载和纹理压缩验证。
- Blender/DCC → 校验器 → 引擎 Prefab 的最小自动导入链。
- 全屏、拖拽、滚轮和触屏手势验证。
- 音频事件、混音总线和浏览器自动播放策略验证。
- CPU、GPU、显存、内存、首屏体积和加载时间预算。

**返工条件**

- 仅在开发机上达标，目标中端设备低于 50 FPS。
- 动画技术不能被模拟状态精确控制。
- 资产导入依赖人工逐项修复，无法支持 252 个建筑等级版本。
- 快照无法恢复生产、施工、运输或动画阶段。

### 4.3 P2：可玩灰盒

**前置条件**

- G1 技术可行性通过；公共契约和坐标、单位、时间标准冻结。

**负责会话**

- GAMEPLAY-DESIGN、SYSTEM-DESIGN、CITY-LAYOUT、CLIENT-ENGINE 主责。
- UI-UX、ECONOMY-BALANCE、QA 支持。

**输入**

- 已验证引擎骨架、核心循环规格、首个岛屿灰盒。

**可验收交付物**

- 等距地图自由铺路、旋转放置、拆除、拖拽、缩放和全屏。
- 住宅、工作、原料、生产、仓储、搬运、市场、服务与财政的最小真实闭环。
- 停工原因链与可读调试面板。
- 普通材料随机掉落、点击/滑动拾取、30 节点和待投放队列。
- 歌曲有效完成、稀缺奖励概率、去重和保底模拟接口。
- 10 分钟无指导可玩测试脚本。
- 灰盒城市布局：住宅区、生产区、市场区、滨水区和公共服务区。

**返工条件**

- 动画或 UI 伪造物流，货物仍瞬移。
- 玩家无法理解道路、就业、缺料和停工之间的关系。
- 核心循环需要频繁进入表格面板才能操作。
- 拖拽与拾取、建造发生系统性误触。

### 4.4 P3：垂直切片

**前置条件**

- G2 灰盒乐趣、系统因果与技术预算通过。
- 视觉圣经、建模规范、动画状态机、UI 规范达到 Approved。

**负责会话**

- 主控会话统一指挥所有专业会话。
- 选择主镇一个完整街区作为唯一切片范围。

**输入**

- 冻结灰盒、首批代表性建筑、目标画质参考和性能预算。

**切片内容**

- 6 类代表建筑：柳岸民居、层层稻田、丰年粮仓、小满食肆、青瓦瓷窑、旧码头。
- 每类完整制作 0、1、4、8 四个关键等级；其中至少两类制作连续 0–8 全等级。
- 两类人物、搬运车和一类船只。
- 晨、昼、暮；晴、细雨；水面、植被、炊烟、灯火和施工 VFX。
- 完整建造、生产、运输、停工、升级、拾取和音乐奖励链路。
- 正式 UI、正式音频、正式存档和正式资源加载。

**可验收交付物**

- 15–20 分钟可独立游玩的候选构建。
- 源资产、模型、材质、绑定、动画、Prefab、音频和 UI 均通过最终生产链导入。
- 美术目标截图、状态驱动录像、性能捕获和用户测试报告。
- 一套已测算的单建筑生产成本、返工率与周产能。

**返工条件**

- 使用“后续会更好”解释当前画面达不到目标。
- 六类建筑隐藏名称后难以辨认功能。
- 0 级与 8 级仅有装饰差异，没有体量、结构和街区活动变化。
- 暂停、倍速、读档或断路后动画与模拟脱节。
- 切片无法稳定满足目标设备性能预算。

### 4.5 P4：完整制作

**前置条件**

- G3 垂直切片通过；生产成本、工具链、质量标杆和容量计划已冻结。

**负责会话**

- 各专业会话按批次并行生产，主控会话按周集成。

**输入**

- Approved 的设计与资产模板、切片金标资产、批次排期。

**可验收交付物**

- 四岛完整城市布局、全部核心系统、28 类建筑 0–8 级。
- 人物、车辆、船只、环境、UI、VFX、灯光和音频完整资产。
- 全部系统可由编辑器配置，禁止为单建筑写不可复用硬编码。
- 每批资产拥有自动命名、尺寸、骨骼、纹理、碰撞、挂点与性能校验报告。
- 每周可玩构建、每两周跨专业内容评审、每月里程碑评审。

**返工条件**

- 批量资产偏离垂直切片金标。
- 同类问题在三个资产上重复出现而未修改模板或校验器。
- 内容产量以降低轮廓差异、动画真实性或性能预算为代价。
- 资产进入引擎后才首次检查比例、遮挡或路网连接。

### 4.6 P5：Alpha

**前置条件**

- 全部首发功能和内容已接入；不再新增核心系统。

**负责会话**

- CLIENT-ENGINE、QA-AUTOMATION、PERFORMANCE 主责。
- 全体专业会话修复阻断问题。

**可验收交付物**

- Feature Complete 构建。
- 四岛、28×9 建筑、完整产业链、音乐奖励、存档和 UI 全流程可玩。
- 首轮全量本地化、音频、可访问性和新手体验。
- 8 模拟小时长稳、存档迁移、断网/恢复和异常退出测试。
- P0/P1 缺陷清零，P2 缺陷有负责人和关闭版本。

**返工条件**

- 核心循环任一环无法完成。
- 仍存在占位资产、临时 UI、假动画或手工拼接资源。
- 存档损坏、数值爆炸、订单死锁或不可恢复卡关。

### 4.7 P6：Beta

**前置条件**

- G4 Alpha 系统完整门禁通过；内容和接口锁定。

**负责会话**

- QA-AUTOMATION、PERFORMANCE、UI-UX、RELEASE-OPS 主责。

**可验收交付物**

- Content Complete 构建。
- 兼容矩阵、性能矩阵、内存与加载报告。
- 完整用户测试、平衡性报告、教学完成率和误触统计。
- 最终混音、最终灯光、最终 VFX 强度和色彩一致性。
- 全部 P0/P1/P2 缺陷清零，获批的 P3 缺陷进入发布后清单。

**返工条件**

- 为解决性能问题大面积关闭关键动态表现。
- 城市高繁荣阶段仍存在大片无功能空地或建筑同质化。
- 关键操作成功率、教学理解率或帧率不达标。

### 4.8 P7：Release Candidate

**前置条件**

- G5 Beta 质量锁定通过；代码、内容和资产全面冻结。

**负责会话**

- RELEASE-OPS 主责，QA Lead 与主控会话共同签署。

**可验收交付物**

- 可部署 RC 包、符号/源图、资产清单、校验和与 SBOM。
- 发布说明、监控指标、报警阈值和回滚方案。
- 冷启动、热更新、存档升级、全屏、音频权限和浏览器兼容终检。
- 72 小时候选版本稳定性观察，无新增阻断缺陷。

**返工条件**

- RC 后任何非阻断性代码或资产改动。
- 构建不可复现、版本号不一致、资源缺失或监控不可用。
- 回滚无法恢复旧版本和玩家存档。

## 5. 28 类建筑 0–8 级资产生产线

### 5.1 建筑范围

建筑按五个制作族分批，但每类必须保持独立功能轮廓和专属动作。

| 制作族 | 建筑 |
| --- | --- |
| 港口交通 | 旧码头、青石渡口、听雨桥、潮生渔港、远航船坊、归潮灯塔 |
| 商业民生 | 临水客栈、半日茶楼、小满食肆、柳岸民居、小耳镇口 |
| 作坊仓储 | 云锦布坊、榫卯木作、青瓦瓷窑、丰年粮仓、草木药铺、晒谷长仓、听风竹坊 |
| 农业生产 | 层层稻田、四时果园、溪边水磨、青岚茶园、山野药圃、白浪盐场 |
| 公共景观 | 溪山书院、水上戏台、临水花园、云岫山亭 |

### 5.2 等级设计语法

| 等级 | 城市语义 | 必须变化 |
| --- | --- | --- |
| L0 | 荒地、遗址或停用设施 | 功能不可运行；保留可识别遗迹和施工边界 |
| L1 | 基础恢复 | 主功能体首次出现，入口与道路接通 |
| L2 | 稳定运转 | 院落、储物、第一组人物活动和基础物流点 |
| L3 | 结构扩建 | 主体轮廓、层数、屋面或生产设施明显扩大 |
| L4 | 街区形成 | 围墙、道路衔接、摊位/附属棚、第二组活动 |
| L5 | 产业成熟 | 专属机械、容量和岗位增长，远景轮廓再次变化 |
| L6 | 文明装饰 | 灯火、绿化、标识、居民密度和高级物流表现 |
| L7 | 地标化扩建 | 主体体量、屋顶天际线或滨水界面形成终局轮廓 |
| L8 | 繁华终态 | 正常营业、人流、物流、专属庆成动作和完整街区填充 |

L0、L1、L3、L5、L7 必须更换结构轮廓；L2、L4、L6、L8 必须增加可见功能、活动与环境层。任何等级不得只改色、加牌匾或放统一亭子。

### 5.3 单建筑逐级制作步骤

每个建筑建立唯一资产卡，九个等级按同一生产链通过，不允许跳步。

1. **玩法与功能简报**
   - SYSTEM-DESIGN 提供用途、容量、岗位、生产配方、入口、装卸点、服务点、停工原因和升级功能。
   - CITY-LAYOUT 提供占地、地形、道路/水路连接、相邻留白和镜头可见距离。
   - 交付：`Building Brief v1`，未经签署不得概念设计。

2. **历史与视觉研究**
   - ART-DIRECTION 建立地域、年代、结构、材料和生活细节参考板。
   - 明确原创转译边界，排除直接复制的现有游戏与商业资产。
   - 交付：带来源的研究板和三条差异化视觉关键词。

3. **九级轮廓与演化概念**
   - CONCEPT-ART 先提交 L0/L1/L3/L5/L7 黑白剪影和等距体块。
   - 通过后补齐 L2/L4/L6/L8 的院落、活动、灯火和附属细节。
   - 必须提供正交三视图、等距关键视图、拆件图、材质分区、人物尺度和相邻建筑对比。
   - 交付：九级演化板、终态街区图、专属动作关键帧。

4. **灰盒模型与场景验证**
   - MODELING 按真实尺寸制作 L0–L8 低细节体块、占地、枢轴、入口和遮挡层。
   - 导入测试街区，验证透视、相邻间距、拖拽缩放、点击区域、道路和水岸关系。
   - 交付：灰盒 Prefab、体块转台、近中远景截图。

5. **高低模与模块拆件**
   - 制作主体、屋面、院墙、机械、门窗、道具、前景遮挡和损毁/施工件。
   - 可复用构件进入模块库；专属轮廓不得被模块化抹平。
   - 同时制作 LOD0/LOD1/LOD2、碰撞代理和选择代理。
   - 交付：清洁拓扑模型、模块清单、面数与尺寸报告。

6. **UV 与材质**
   - UV-MATERIAL 按建筑族使用统一 Texel Density、材质槽和图集策略。
   - 屋瓦、木构、石材、灰泥、布、金属、泥土和水渍分别建立可复用主材质。
   - 每级通过几何与道具体现成长，不得只靠贴图重绘。
   - 交付：UV 检查图、PBR/风格化贴图、材质实例、压缩后显存报告。

7. **绑定与动画挂点**
   - RIGGING 为水轮、织机、门窗、灯笼、船台、磨盘等建立层级与约束。
   - 定义入口、装卸、服务、烟口、灯位、角色站位、粒子、音频和遮挡挂点。
   - 交付：绑定文件、命名骨骼、动作范围测试和挂点 manifest。

8. **动画与 VFX**
   - ANIMATION 制作 idle、work、delivery、service、blocked、construction 和 level transition。
   - VFX 制作状态对应的烟、火、水、尘、蒸汽、落叶和反馈；禁止无状态永续满负荷特效。
   - 交付：动画片段、状态机、事件表、暂停/倍速/读档录像。

9. **灯光与音频**
   - LIGHTING 配置晨昼暮材质响应、窗灯、灯笼和阴影。
   - AUDIO 配置施工、生产、营业、停工和环境事件，设置距离衰减与并发上限。
   - 交付：三时段对照图、音频事件表和混音验证录像。

10. **引擎 Prefab**
    - TOOLS-PIPELINE 自动生成 Prefab，绑定等级模型、LOD、碰撞、挂点、材质、动画、VFX、音频和模拟 BuildingType。
    - 校验器阻断缺失入口、错误等级、越界包围盒、超预算贴图和未绑定状态。
    - 交付：版本化 Prefab、manifest、自动校验报告。

11. **场景与系统验收**
    - 在正式街区、生产链和压力场景中验证占地、遮挡、路径、物流、昼暮、天气、升级和性能。
    - 隐藏名称后由非制作人员辨认功能；L0/L8 盲测必须形成显著差异。
    - 交付：九级转台、九级场景截图、状态录像、性能捕获和 QA 签署。

12. **入库与变更控制**
    - 源文件、导出文件、缩略图、Prefab、manifest 和评审记录一起入库。
    - Approved 后修改结构、占地、挂点或状态机必须提升资产次版本并触发受影响环节回归。

### 5.4 建筑批次策略

- Batch A（金标）：柳岸民居、层层稻田、丰年粮仓、小满食肆、青瓦瓷窑、旧码头。
- Batch B（主镇生活）：青石渡口、听雨桥、临水客栈、半日茶楼、云锦布坊、榫卯木作、草木药铺。
- Batch C（主镇文明）：溪山书院、水上戏台、小耳镇口、临水花园。
- Batch D（风禾/青岚）：四时果园、溪边水磨、晒谷长仓、青岚茶园、山野药圃、听风竹坊、云岫山亭。
- Batch E（潮汐）：潮生渔港、白浪盐场、远航船坊、归潮灯塔。

Batch A 未全部通过金标门禁，不得启动 Batch C–E 的最终模型生产。后续批次可以提前做研究和概念草图，但不得跳过金标反馈。

## 6. 各专业制作标准

### 6.1 玩法与系统

- 所有规则写明输入、状态、输出、反馈、异常、存档和可观测指标。
- 系统策划必须提供因果链：玩家看到的问题 → 可查询原因 → 可执行解决方案。
- 不允许仅依靠提示文字解释不可见规则；道路、库存、岗位和服务必须有场景反馈。
- 新系统进入完整制作前需有灰盒和至少一次外部可玩测试。

### 6.2 城市布局与关卡

- 四岛均提供高低密度区、视觉焦点、主干路、支路、水路、生产区和留白用途。
- 高繁荣阶段建筑/功能景观覆盖目标约 85%；剩余区域必须是农田、园林、广场、水系、岸线或生产作业区。
- 每个街区提供 25%、50%、75%、100% 发展阶段布局验证。
- 镜头在最远缩放时可读城市结构，最近缩放时可观察人物和生产。

### 6.3 数值

- 使用确定性批量模拟验证 1、7、30 个游戏日的资源、人口、财政与物流。
- 普通材料不能使建筑升级失去节奏；稀缺材料不得阻塞基础文明发展。
- 每次调参记录假设、指标、结果和回滚值，禁止直接覆盖无版本表格。
- Alpha 前锁定数值结构，Beta 仅允许调整参数。

### 6.4 UI/UX

- 地图优先，同时最多一个大型面板。
- 所有关键操作提供鼠标和触摸路径；拖拽、拾取、放置、旋转和缩放不得冲突。
- 停工提示可从场景追踪到原因链，不展示无意义红点。
- 字号、对比度、色觉、动效减弱和输入容错进入 Beta 兼容矩阵。

### 6.5 客户端与工具链

- 模拟层不得引用 React/PixiJS，渲染层不得直接修改模拟状态。
- 共享契约采用版本化 Schema，并提供迁移器和兼容测试。
- 内容数据、Prefabs 和音频事件必须由校验器检查，不允许静默降级。
- CI 至少包含类型检查、单元测试、存档回放、资产校验、构建、包体与性能差异报告。

### 6.6 性能

- 每个资产与功能在进入主分支前提交增量成本，而不是 Beta 才集中优化。
- 目标预算：CPU 16.7ms 总帧；动画与渲染同步 ≤5ms；GPU ≤9ms；常态 Draw Calls ≤180。
- 桌面纹理显存 ≤256MB，移动端 ≤160MB；首屏压缩资源 ≤20MB。
- 离屏实体停止渲染更新；对象、粒子、动画实例必须池化。
- 超预算资产不得以“后续统一优化”进入 Approved。

### 6.7 QA

- 测试分为单元、集成、系统、内容、视觉、性能、兼容、长稳、存档和发布验证。
- 每项需求在实现前写验收用例；每个缺陷记录复现种子、快照、版本和证据。
- 视觉缺陷同样进入缺陷系统并分级，不接受只在聊天中反馈。
- 关键录像必须无剪辑、显示版本号和性能 HUD。

### 6.8 发布

- 所有发布构建来自 CI，禁止本地手工打包。
- 版本包含代码、内容、资产、Schema、存档和配置版本。
- 发布前完成监控、报警、灰度、回滚和数据保留验证。
- 音乐事件、用户存档与分析事件不得在日志中泄露个人隐私。

## 7. 版本、命名与资产规范

### 7.1 版本命名

- 项目版本使用 SemVer：`MAJOR.MINOR.PATCH`。
- 开发里程碑：
  - `0.1.x-prototype`
  - `0.2.x-graybox`
  - `0.3.x-vertical-slice`
  - `0.5.x-production`
  - `0.8.x-alpha`
  - `0.9.x-beta`
  - `1.0.0-rc.N`
  - `1.0.0`
- 构建号：`xiaoerdao-{version}+{YYYYMMDD}.{ciRun}.{shortSha}`。
- 数据 Schema、存档、Prefab 和资产包分别拥有独立整数版本；不允许只提升应用版本掩盖兼容变化。

### 7.2 资产命名

统一使用小写 ASCII、下划线分隔，不包含空格、中文或临时后缀：

`{domain}_{island}_{building}_{level}_{part}_{state}_{lod}_{variant}_{version}`

示例：

- `bld_main_kiln_l05_body_idle_lod0_a_v003.glb`
- `bld_tide_lighthouse_l08_lantern_work_lod0_a_v002.glb`
- `mat_main_kiln_rooftile_a_v004`
- `ani_main_kiln_fire_work_a_v003`
- `vfx_main_kiln_smoke_blocked_a_v002`
- `sfx_main_kiln_door_open_a_v001.ogg`
- `pfb_main_kiln_l05_v007.json`

规则：

- `final`、`new`、`copy`、`latest`、`fix2` 等词禁止出现。
- 等级固定两位：`l00`–`l08`；LOD 固定 `lod0`–`lod2`。
- 源文件与导出文件共享资产 ID，版本号不同必须有变更记录。
- 纹理后缀统一：`_basecolor`、`_normal`、`_orm`、`_emissive`、`_mask`。
- 骨骼、挂点、材质槽和动画状态使用项目词典，不得自由拼写。

### 7.3 目录和清单

每个资产包至少包含：

```text
source/
export/
textures/
animations/
prefab/
preview/
validation/
manifest.json
changelog.md
```

`manifest` 必须记录资产 ID、所有者、状态、依赖、单位、枢轴、包围盒、等级、LOD、纹理、骨骼、挂点、动画、VFX、音频、预算和许可来源。

## 8. 评审节奏与变更管理

### 8.1 固定节奏

- 每日：各会话异步提交状态、阻断、下一步和新增风险，不进行无证据“完成度”汇报。
- 每周一：主控排产与依赖评审，冻结本周集成范围。
- 每周三：专业评审；设计、美术、技术、QA 分轨审查半成品。
- 每周五：可玩构建评审，只评价实际集成结果，不以单独源文件代替游戏内效果。
- 每两周：跨专业里程碑评审和外部可玩测试。
- 每月：成本、产能、返工率、性能趋势和范围复盘。
- Alpha 起：每日缺陷会；Beta 起：每日候选构建与回归签署。

### 8.2 评审材料

任何评审必须提前提供：

- 版本号和变更摘要。
- 与上一批准版本的对照。
- 游戏内截图/录像，而非仅 DCC 视口。
- 性能、包体或内存变化。
- 未解决问题和希望评审者作出的具体决定。

没有材料的会议不得给出 Approved。

### 8.3 返工与变更

- 同一根因影响三个及以上资产时，暂停批量生产，先修改规范、模板或工具。
- Approved 资产发生占地、入口、骨骼、材质槽、动画事件或 Prefab Schema 变化，必须发起 Change Request。
- Change Request 记录原因、受影响资产、成本、风险、回滚和重新验收范围。
- 临时修复必须标记到期版本；到期未清理则阻断下一门禁。
- 任何会话不得回滚或覆盖其他会话产物；冲突由主控会话在集成分支解决。

## 9. 项目 Definition of Done

项目只有同时满足以下条件才算完成：

- 创意支柱、核心循环和目标用户体验在最终构建中成立。
- 道路、人口、就业、生产、仓储、物流、市场、财政和服务真实运行。
- 28 类建筑全部具有经批准的 L0–L8 概念、模型、材质、绑定、动画、VFX、灯光、音频、Prefab 和场景验收。
- 最高等级形成连续、繁华、功能明确的城市，不存在大片无用途空地或建筑同质化。
- 所有人物、生产、物流、服务和施工动画由模拟状态或事件驱动。
- 普通材料独立随机落地并可手动拾取；歌曲只结算稀缺材料且去重、概率、保底正确。
- 全屏、拖拽、缩放、建造、拾取和主要管理操作在目标输入设备上可用。
- 500/300/150 压力场景稳定不低于目标帧率，8 模拟小时无泄漏、死锁、数值爆炸或存档损坏。
- 无占位资产、无临时接口、无 P0/P1/P2 缺陷、无未批准许可风险。
- 构建可重复，存档可迁移，监控与回滚可用，源码、源资产、文档、测试与发布包齐全。
