# 《小耳岛》项目进度仪表盘

更新时间：2026-06-29

## 1. 当前阶段

当前阶段：P0 商业定位与项目中枢重构。

当前判断：

- 项目已有早期城市模拟、Pixi 渲染骨架、资产校验器、若干金标 manifest 样例和长稳测试。
- 旧文档中的四岛、听歌材料、固定 28 建筑等主线冲突已在总目标、流水线和门禁中完成降级。
- 本轮已把完整上线商业级目标、美术 ART-P0–P11 全阶段生产线和自动执行机制落到项目中枢。
- 第十二轮已把外来人口从直接生成住户推进为候选状态机，并建立第一版城市吸引力评分。
- 第十三轮已让等待中的外来人口在地图和小事流中可见、可定位。
- 第十四轮已建立建筑阶段、功能、连接方式和年代标签的运行时分类目录。
- 第十五轮已完成街区繁荣第一版：街区数据、指标和地图暖光/灯点/人流轻表现已接入。
- 第十六轮已把候选外来人口从瞬时入住推进为可见进城路径：等待、移动、抵达住宅后才正式入住。
- 第十七轮已把建筑目录的城市阶段接入建造菜单：当前阶段可见，未解锁建筑置灰，运行时放置也会被拒绝。
- 第十八轮已把候选外来人口进城路径从直线推进为道路优先寻路，有路时不会横穿地块。
- 第十九轮已把阶段晋升条件做成可见目标：当前阶段、下一阶段和人口/吸引力/街区要求能在界面上看到。
- 第二十轮已把听歌奖励入口从常驻主线卡片降级为默认收起的可选轻奖励入口，继续清理旧方向残留。
- 第二十一轮已把旧群岛引擎里的“听歌刷普通材料”默认关闭，只保留显式 legacy 兼容开关。
- 第二十二轮已把旧 `IslandCanvas` 群岛 Pixi 视图默认归档，只有显式 legacy/QA 参数才会启动旧渲染。
- 第二十三轮已把阶段晋升条件做成可点击顾问：人口、吸引力、街区缺口会引导到下一步操作。
- 第二十四轮已给阶段顾问接入原因诊断：住房、岗位、满意度、物流和街区卡点会直接显示。
- 第二十五轮已把阶段顾问接入地图覆盖：点击后可看到住房/外来人口、吸引力瓶颈或街区核心位置。
- 第二十六轮已把阶段覆盖升级为分层标记：住房、外来人口、瓶颈和街区核心有独立类型、颜色和短标签。
- 第二十七轮已在阶段面板加入覆盖图层开关：住房容量、服务覆盖、物流拥堵和道路连通可按需查看。
- 第二十八轮已让物流图层显示订单线路：发货点、收货点和方向线能同时看到。
- 第二十九轮已让服务图层显示服务范围：服务点之外可以看到半透明覆盖区域。
- 第三十轮已让服务图层标出未覆盖住宅：玩家能看到哪些民居需要补市场/服务点。
- 第三十一轮已让道路图层按建筑功能细分缺路入口：住宅、服务、仓储和生产缺口更容易分辨。
- 第三十二轮已让物流图层标出多订单热点：发货/收货线路之外能看到拥堵集中建筑。
- 第三十三轮已给覆盖图层增加摘要条：住宅/空位、服务缺口、物流热点和道路缺口可直接读数。
- 第三十四轮已给覆盖图层增加结构化指标：后续瓶颈/阶段面板可以直接读取图层数值。
- 第三十五轮已把图层结构化指标接入阶段面板：当前打开图层的治理读数可直接看到。
- 第三十六轮已让阶段面板图层指标可点击定位：读数不再只是摘要，可以直接跳到对应地图目标。
- 第三十七轮已把旧群岛 `IslandCanvas` 从正式组件目录迁入 `src/legacy/archipelago`，并新增 legacy 边界测试，防止旧原型继续污染正式 UI 搜索路径。
- 第三十八轮已抽出共享移动路径服务：候选外来人口不再在 `SimulationEngine` 内部自带寻路实现，而是使用 `src/simulation/world/movementPath.ts` 的道路优先路径，后续居民/物流可逐步共用。
- 第三十九轮已把图层结构化指标接入瓶颈治理卡：服务缺口、道路入口缺口和物流热点会生成可排序、可点击、可定位的治理建议。
- 第四十轮已让街区繁荣接入真实运行因子：服务覆盖、道路贴近和物流活动会提高街区繁荣与人流表现，繁荣不再只看建筑聚集。
- 第四十一轮已让物流 RoadRoutePlanner 复用共享移动路径服务：货运不再穿越普通水面或建筑占用格，桥路可通行，无有效道路时会保持物流失败而不是自动直线兜底。
- 第四十二轮已把共享移动路径接入工人通勤：工人获得岗位后会生成道路优先路径，逐 tick 从住宅入口移动到雇主入口，抵达后才进入 working 状态。
- 第四十三轮已补上工人返家循环雏形：工人完成固定工作班次后生成返家路径，沿共享道路回到住宅入口并恢复 home 状态；这还不是完整日夜作息，只是生活循环的第一段闭环。
- 第四十四轮已把市场/服务成功转化为可见居民出行：服务交付时生成 `service-visit` 居民 agent，沿住宅到服务建筑路径前进，到达后返家并移除；同一家庭同一需求不会重复刷出多个人影。
- 第四十五轮已把居民服务/购物从即时结算推进为抵达后结算：居民到达市场、药铺、书院或戏台后才扣库存、扣家庭收入、产生税收和恢复需求；长稳压力场景明确 `migrationOutThreshold: 0` 为禁用迁出，并按 500 户满规模重新校准历史订单灰盒上限。
- 第四十六轮已把真实服务访问接入街区繁荣热度：居民正在前往市场、药铺、书院或戏台时，对应市街/服务街区会获得繁荣与人流加成，地图人流不再只由静态建筑和物流推导。
- 后续重点继续从“规划统一”转向“代码主循环与运行时系统重构”。

## 3. 当前最大风险

- 旧方向残留：旧听歌掉落和旧群岛视图已默认隔离，旧群岛视图已迁入 legacy 目录；后续仍需审计旧 `src/game/**` 群岛引擎是否继续保留、迁移或删除未用 UI。
- 美术产能风险：商业级美术需要专业二维/三维/动画参与，工程只能先建立规范、灰盒、manifest 和金标样板。
- 模拟闭环风险：迁入已受吸引力约束，但就业、服务、财政、风险之间还没有完全形成长期自洽闭环。
- 视觉密度风险：街区繁荣已有第一版，但还需要与真实人流、服务覆盖和美术资产阶段继续绑定。

## 4. 下一轮默认任务

1. 将治理卡继续扩展为“问题 → 原因 → 推荐建造/铺路工具”的城市顾问闭环。
2. 将承运人可视路径继续统一到共享路径生命周期，减少物流与居民移动表现差异。
3. 规划历史订单归档/压缩任务，避免更长商业级长跑中主快照无限积累订单。
4. 审计旧 `src/game/**` 群岛引擎，决定迁入 legacy、保留迁移工具或删除未用 UI。
5. 继续把服务访问、工人通勤和物流路线汇总成城市热力/拥堵/繁荣可视图层。
