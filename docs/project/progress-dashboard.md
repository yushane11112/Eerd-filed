# 《小耳岛》项目进度仪表盘

更新时间：2026-07-10

## 1. 当前阶段

当前阶段：P0 商业定位与项目中枢重构。

当前判断：

- 项目已有早期城市模拟、Pixi 渲染骨架、资产校验器、若干金标 manifest 样例和长稳测试。
- 旧文档中的四岛、听歌材料、固定 28 建筑等主线冲突已在总目标、流水线和门禁中完成降级。
- 本轮已把完整上线商业级目标、美术 ART-P0–P11 全阶段生产线和自动执行机制落到项目中枢。
- 第十二轮已把外来人口从直接生成住户推进为候选状态机，并建立第一版城市吸引力评分。
- 第十三轮已让等待中的外来人口在地图和小事流中可见、可定位。
- 第十四轮已建立建筑阶段、功能、连接方式和年代标签的运行时分类目录。
- 第十五轮已完成街区繁荣第一版：街区数据、指标和地图暖光/灯点/人流轻表现已接入。
- 第十六轮已把候选外来人口从瞬时入住推进为可见进城路径：等待、移动、抵达住宅后才正式入住。
- 第十七轮已把建筑目录的城市阶段接入建造菜单：当前阶段可见，未解锁建筑置灰，运行时放置也会被拒绝。
- 第十八轮已把候选外来人口进城路径从直线推进为道路优先寻路，有路时不会横穿地块。
- 第十九轮已把阶段晋升条件做成可见目标：当前阶段、下一阶段和人口/吸引力/街区要求能在界面上看到。
- 第二十轮已把听歌奖励入口从常驻主线卡片降级为默认收起的可选轻奖励入口，继续清理旧方向残留。
- 第二十一轮已把旧群岛引擎里的“听歌刷普通材料”默认关闭，只保留显式 legacy 兼容开关。
- 第二十二轮已把旧 `IslandCanvas` 群岛 Pixi 视图默认归档，只有显式 legacy/QA 参数才会启动旧渲染。
- 第二十三轮已把阶段晋升条件做成可点击顾问：人口、吸引力、街区缺口会引导到下一步操作。
- 第二十四轮已给阶段顾问接入原因诊断：住房、岗位、满意度、物流和街区卡点会直接显示。
- 第二十五轮已把阶段顾问接入地图覆盖：点击后可看到住房/外来人口、吸引力瓶颈或街区核心位置。
- 第二十六轮已把阶段覆盖升级为分层标记：住房、外来人口、瓶颈和街区核心有独立类型、颜色和短标签。
- 第二十七轮已在阶段面板加入覆盖图层开关：住房容量、服务覆盖、物流拥堵和道路连通可按需查看。
- 第二十八轮已让物流图层显示订单线路：发货点、收货点和方向线能同时看到。
- 第二十九轮已让服务图层显示服务范围：服务点之外可以看到半透明覆盖区域。
- 第三十轮已让服务图层标出未覆盖住宅：玩家能看到哪些民居需要补市场/服务点。
- 第三十一轮已让道路图层按建筑功能细分缺路入口：住宅、服务、仓储和生产缺口更容易分辨。
- 第三十二轮已让物流图层标出多订单热点：发货/收货线路之外能看到拥堵集中建筑。
- 第三十三轮已给覆盖图层增加摘要条：住宅/空位、服务缺口、物流热点和道路缺口可直接读数。
- 第三十四轮已给覆盖图层增加结构化指标：后续瓶颈/阶段面板可以直接读取图层数值。
- 第三十五轮已把图层结构化指标接入阶段面板：当前打开图层的治理读数可直接看到。
- 第三十六轮已让阶段面板图层指标可点击定位：读数不再只是摘要，可以直接跳到对应地图目标。
- 第三十七轮已把旧群岛 `IslandCanvas` 从正式组件目录迁入 `src/legacy/archipelago`，并新增 legacy 边界测试，防止旧原型继续污染正式 UI 搜索路径。
- 第三十八轮已抽出共享移动路径服务：候选外来人口不再在 `SimulationEngine` 内部自带寻路实现，而是使用 `src/simulation/world/movementPath.ts` 的道路优先路径，后续居民/物流可逐步共用。
- 第三十九轮已把图层结构化指标接入瓶颈治理卡：服务缺口、道路入口缺口和物流热点会生成可排序、可点击、可定位的治理建议。
- 第四十轮已让街区繁荣接入真实运行因子：服务覆盖、道路贴近和物流活动会提高街区繁荣与人流表现，繁荣不再只看建筑聚集。
- 第四十一轮已让物流 RoadRoutePlanner 复用共享移动路径服务：货运不再穿越普通水面或建筑占用格，桥路可通行，无有效道路时会保持物流失败而不是自动直线兜底。
- 第四十二轮已把共享移动路径接入工人通勤：工人获得岗位后会生成道路优先路径，逐 tick 从住宅入口移动到雇主入口，抵达后才进入 working 状态。
- 第四十三轮已补上工人返家循环雏形：工人完成固定工作班次后生成返家路径，沿共享道路回到住宅入口并恢复 home 状态；这还不是完整日夜作息，只是生活循环的第一段闭环。
- 第四十四轮已把市场/服务成功转化为可见居民出行：服务交付时生成 `service-visit` 居民 agent，沿住宅到服务建筑路径前进，到达后返家并移除；同一家庭同一需求不会重复刷出多个人影。
- 第四十五轮已把居民服务/购物从即时结算推进为抵达后结算：居民到达市场、药铺、书院或戏台后才扣库存、扣家庭收入、产生税收和恢复需求；长稳压力场景明确 `migrationOutThreshold: 0` 为禁用迁出，并按 500 户满规模重新校准历史订单灰盒上限。
- 第四十六轮已把真实服务访问接入街区繁荣热度：居民正在前往市场、药铺、书院或戏台时，对应市街/服务街区会获得繁荣与人流加成，地图人流不再只由静态建筑和物流推导。
- 第四十七轮已把治理卡推进为可执行城市顾问：服务缺口、道路缺口、物流热点和常规瓶颈会显示原因、推荐工具/建筑和相关图层，玩家可一键定位或切换到铺路/营造工具。
- 第四十八轮已给承运人补上货运生命周期语义：货车/船只 agent 会记录订单、资源、数量、源/目的建筑和取货/送货阶段，动态渲染也能区分空车取货与载货送达。
- 第四十九轮已完成历史物流订单归档：已交付/已取消订单会进入 `logisticsArchive` 汇总，主快照只保留最近完成记录；2400 tick 长稳订单表上限从 20000 收紧到 2000，并验证归档确实发生。
- 第五十轮已把旧群岛材料/建造/存档引擎和旧材料 UI 迁入 `src/legacy/game/**`，正式 `src/game` 与旧 `MaterialRow` 已移除。
- 第五十一轮已新增城市活动热力图层：服务访问、工人通勤和货运路线会汇总为活动热力点、活动路径和基础活动指标。
- 第五十二轮已把活动热力推进为治理读数：道路压力、服务热度和货运拥堵会进入阶段面板，并在压力集中时生成“城市活动压力”治理卡。
- 第五十三轮已把活动压力投射到真实道路格：有路网时会读取 agent 剩余路径并生成 `货路/服路/通路/道压` 承压点，阶段面板“道压”可定位到具体道路段。
- 第五十四轮已把活动压力治理卡推进为分因推荐：货拥推荐补仓储缓冲，服务热推荐补服务点分流，道压推荐铺路分流。
- 第五十五轮已把治理卡建筑推荐接入城市阶段门禁：推荐对象会说明当前阶段和所需阶段，未解锁建筑会降级为查看图层，UI 点击推荐时也会二次拦截。
- 第五十六轮已把已解锁建筑推荐接入营造可执行性诊断：会检查连续空地和入口道路，无法放置时显示原因且不切换到建筑工具；当前系统尚未有正式营造材料/财政成本，因此不伪造资源门禁。
- 第五十七轮已建立首版正式营造成本：建筑放置会消耗财政和城市仓储材料，资源不足时不落建筑、不扣银两；治理卡营造条件也会诊断材料/银两不足。当前数值是运行时首版平衡，不等于最终商业经济表。
- 第五十八轮已把正式营造成本接入建造菜单：按钮显示银两/材料成本，资源不足时显示缺口并禁用营造入口。
- 第五十九轮已把建筑类治理建议接入地图落点提示：点击推荐会在图层中优先显示“建议落点/入口”，并在建造菜单标出推荐建筑；浏览器 QA 发现并修复了建议点被热点裁掉的问题。
- 第六十轮已把建筑类治理建议从点提示推进为 footprint 预览：推荐会输出真实建筑占地、入口格和旋转占位字段，地图显示 3×2 等距占地格与入口高亮，浏览器 QA 验证集市推荐出现 6 个 footprint 格、1 个入口格、2 个落点标记。
- 第六十一轮已把建筑工具接入动态试放预览：选择建筑后，鼠标移动到地图会显示 footprint、入口和冲突格；预览由 `GameRuntime.previewBuildingPlacement` 统一校验，不扣资源、不落建筑，浏览器 QA 验证了“入口必须紧邻道路”的冲突提示。
- 第六十二轮已把动态试放接入 `PlacementController`：选择、移动、旋转、确认、取消和成功后的重复放置改由状态机驱动；新增 Runtime placement 适配层，浏览器 QA 验证选择民居、移动预览、R 旋转保留预览、右键取消清空预览均正常。
- 第六十三轮已把正式营造成本接入试放预览：地块和道路条件满足但城市仓储/银两不足时，`GameRuntime.previewBuildingPlacement` 会直接返回不可营造和缺口，UI 预览因此在规划阶段变红，而不是点击后才失败。
- 第六十四轮已把道路工具从单击铺路推进到拖拽连续铺设：`GameRuntime.placeRoadPath` 能一次批量修改真实路网并汇总建筑占用/地形/越界/无变化跳过格，`SimulationCanvas` 在道路工具拖拽时调用该入口而不再平移相机。
- 第六十五轮已新增“拆路”工具：`GameRuntime.removeRoadPath` 能批量删除真实道路并汇总无路/越界跳过格，UI 侧提供明确拆路入口；当前只拆道路，不拆建筑，避免破坏人口、库存和物流一致性。
- 第六十六轮已给道路铺设接入财政成本：石板路每格消耗银两，拖拽路径会铺到财政可支付的部分，余额不足的格子跳过；拖过已有道路不会重复扣费或误判为缺钱。
- 第六十七轮已建立建筑拆除一致性入口：建筑详情可拆除建筑，运行时会释放地块、迁出失去住宅的家庭、释放相关岗位并取消引用该建筑的未完成物流订单。
- 第六十八轮已新增桥梁专门建造模式：桥梁工具可拖拽水面/岸边架桥，桥路按 18 银两/格扣费，普通陆地会被明确拒绝，水乡城市开始具备跨水交通规划能力。
- 第六十九轮已给桥梁接入专属道路视觉：桥路不再完全复用普通石板路样式，而是有独立桥面色、描边、桥墩和更宽桥面；这只是灰盒视觉差异，不等于商业级桥梁资产完成。
- 第七十轮已把道路图层从“入口旁有没有路”推进到“是否连到主路网”：建筑贴着孤立道路时会被标为未连通，阶段面板也会显示未连通和孤立路网读数。
- 第七十一轮已把“未连通/孤立路网”接入城市治理卡：当道路或桥梁只铺到局部时，瓶颈面板会优先提示“道路未连通”，而不是只当成普通缺路或物流不畅。
- 第七十二轮已让道路图层输出建议补线：孤立路网会找到离主路网最近的道路边界，并按是否跨水标出“建议接路”或“建议补桥”路径。
- 第七十三轮已把道路/桥梁补线建议推进为施工计划：治理卡会拆出需要新铺的中间格，区分石板路和桥梁，给出银两成本、缺口和当前是否可支付。
- 第七十四轮已把补线施工计划接入治理卡 UI 与地图覆盖：瓶颈卡可读出道路/桥梁格数、预计银两和财政缺口，点击推荐时保留 roadPlan 并高亮待施工格。
- 第七十五轮已把补线施工计划推进为一键施工：运行时可一次执行混合道路/桥梁 roadPlan，逐格处理财政、地形、建筑占用、已有道路和缺钱反馈，UI 点击 roadPlan 治理卡会直接施工。
- 第七十六轮已补上可控孤立路网调试/E2E 场景：URL 参数可稳定制造道路未连通卡，浏览器验证 roadPlan 卡出现、点击一键施工、财政扣费、成功 toast 和补线 overlay 清理。
- 第七十七轮已补上补线财政不足调试/E2E 场景：URL 参数可稳定制造不可支付 roadPlan，浏览器验证缺钱文案、点击失败不扣钱、保留施工格提示和手动铺路模式。
- 第七十八轮已把道路补线成功/失败场景沉淀为可重复 QA 命令：`npm run qa:road-plans` 会输出并校验两个 roadPlan 场景的前置指标、执行结果和后置指标。
- 第七十九轮已把服务缺口治理纳入 QA 场景库，并修复服务推荐“可建但无效”的问题：市场推荐会优先选择建成后能减少服务缺口的落点，`npm run qa:service-governance` 固化该链路。
- 第八十轮已把桥梁缺口治理纳入 QA 场景库：`bridge-gap` 调试场景能稳定制造水面断点，治理卡会生成 2 格桥梁 roadPlan，`npm run qa:bridge-gaps` 固化“补桥后孤立路网下降”的链路。
- 第八十一轮已把物流热点治理纳入 QA 场景库：`logistics-hotspot` 调试场景能稳定制造 3 条未完成订单压向同一市场，治理卡优先定位入货端，并由 `npm run qa:logistics-hotspots` 固化。
- 第八十二轮已建立浏览器 E2E 场景契约：`npm run qa:browser-e2e:contract` 会列出并校验 roadPlan、低财政、bridge-gap、logistics-hotspot、service-governance 五个浏览器场景的 URL、可见文案和 console error 门禁；这仍不是实际浏览器点击执行器。
- 第八十三轮已接入真实浏览器 E2E 执行器：`npm run qa:browser-e2e` 会构建生产包、启动 Vite preview、用 Playwright Chromium 打开 5 个治理场景、检查可见文案和 console error，并在 road-plan-success 场景真实点击治理卡验证 toast。
- 第八十四轮已补上低财政失败路径真实浏览器交互：`road-plan-low-treasury` 会点击“打开道路图层并接回主路网”，并验证 toast 显示“银两不足2，无法执行补线施工”。
- 第八十五轮已补上服务治理真实浏览器交互：`service-governance` 会点击“打开服务图层并营造市场”，并验证 toast 显示“服务覆盖缺口：打开服务图层并营造市场。”。
- 第八十六轮已补上桥梁缺口真实浏览器交互：`bridge-gap` 会点击“打开道路图层并接回主路网”，并验证 toast 显示“道路未连通：补线施工完成：桥梁 2 格，花费银两36。”。

- 第九十轮已把服务容量从隐含扣分推进为显式 `serviceQueues` 快照状态：服务建筑每 tick 吞吐、多余家庭排队、等待 tick 和排队热点可被模拟、治理图层和后续 UI 读取。
- 第九十一轮已把物流热点从“订单数量”推进到“目的建筑卸货吞吐”：同 tick 多车到达同一建筑时会受 `unloadCapacityPerTick` 限制，未卸货订单保留在目的地并形成 `logisticsQueues` 积压状态，物流图层显示 `卸货排队xN`。
